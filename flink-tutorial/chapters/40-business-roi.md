# 第40章 商业分析 II：成本、ROI、选型与创业机会

## 40.1 TCO 拆解

流平台的总拥有成本：

```text
TCO = 计算 + 存储 + 网络 + 软件许可/托管 + 人力 + 迁移 + 故障损失
```

### 计算

- Flink JM/TM 的 vCPU/内存；
- Kafka/上游系统的资源；
- 下游 OLAP/数据库；
- 压测/预发/灾备环境。

### 存储

- checkpoint/savepoint；
- 状态本地盘；
- 湖仓/数仓；
- 日志/指标。

### 网络

- 跨 AZ/跨区流量；
- Kafka 进出；
- 对象存储请求；
- 公网出口。

### 人力

- 平台开发/运维；
- 作业开发；
- on-call；
- 安全/合规。

### 故障损失

- 收入损失；
- 数据修正成本；
- 客户赔偿；
- 品牌影响；
- 合规罚款。

### 隐性成本

- 状态治理/清理；
- 升级/迁移；
- 培训/招聘；
- 监控/告警；
- 供应商锁定/退出；
- 机会成本（团队被运维占用）。

## 40.2 一个示意性算例

假设一个中型实时风控作业：

- 峰值 5 万 events/s；
- 状态 2 TB（RocksDB）；
- checkpoint 每 5 分钟增量；
- 20 个并行度，每个 TM 8 vCPU/32 GB；
- 需要 5 个 TM + 2 个 JM（含 HA）。

云上按需成本（**仅为示意，实际价格随区域/折扣/机型变化**）：

```text
计算：7 台 × 730 小时 × 每台单价（8 vCPU/32 GB）
存储：2 TB 状态 + 每天增量 × 保留 7 天
网络：Kafka 跨 AZ + checkpoint 上传
托管：如果使用托管 Flink，按 CU/小时溢价
人力：1.5 个工程师 × 全成本
```

假设单价（仅示意；与第 26、38 章的算例不是同一基线，不能跨章相加）：

```text
8 vCPU/32 GB 实例：$0.40/h
7 台 × 730h × $0.40 ≈ $2,044/月
对象存储 2 TB + checkpoint 10 TB ≈ $300/月
跨 AZ 流量 20 TB ≈ $200/月
人力 1.5 FTE × $8,000/月 ≈ $12,000/月
合计 ≈ $14,500/月，人力占 80%+
```

这是美元口径的示意算例；第 41 章的组织/人力数字用人民币口径，两者不是同一基线，不能直接换算或相加。做跨章比较时，先统一币种、地区、FTE 全成本口径和资源单价。

真正的账单往往由**人力、状态存储、跨 AZ 流量和 checkpoint** 主导，而不是 CPU。优化顺序应是：状态 TTL → 增量 checkpoint → 并行度 → 机型。

### 托管 vs 自建的成本对比

```text
托管：单价高 1.5~3 倍，但人力少
自建：单价低，但需要 1~3 个平台工程师
交叉点：当资源规模足够大，自建更便宜；当团队小/需求波动，托管更便宜
```

不要只比单价，要比“总成本 + 上线时间 + 故障风险”。

## 40.3 ROI 从哪来

流处理的 ROI 通常不是“省服务器”，而是：

- **收入**：实时推荐/定价/库存带来增量；
- **风险**：实时反欺诈减少损失；
- **体验**：实时订单/物流状态提升满意度；
- **效率**：CDC 替代定时抽数，减少人力；
- **决策**：分钟级指标替代 T+1。

量化示例（假设）：

- 反欺诈：每年减少损失 1,000 万元，平台成本 300 万元，ROI 约 2.3；
- 实时推荐：转化率提升 1%，增量毛利 800 万元，成本 200 万元，ROI 约 3；
- 数据集成：减少 3 个专职人力，年省 150 万元。

```text
ROI = (收益 - 成本) / 成本
回收期 = 初始投入 / 年化净收益
```

这些数字必须用企业自己的基线测算，不能直接套用。

### 如何建立基线

- 现状延迟/成本/损失；
- 实时化后的目标值；
- 收益的归因（A/B、历史回放、专家判断）；
- 成本的完整口径（含人力）；
- 风险折扣（故障/合规）。

没有基线的 ROI 只是故事。

## 40.4 建 vs 买

| 维度 | 自建 | 托管/商业 |
|---|---|---|
| 初期成本 | 低（开源） | 高（订阅/按量） |
| 运维 | 高 | 低 |
| 弹性 | 取决于团队 | 通常更好 |
| 定制 | 强 | 受产品限制 |
| 安全合规 | 自担 | 厂商分担 |
| 锁定 | 低 | 中/高 |
| 人才 | 需要 | 较少 |

判断：

- 流处理是核心能力、规模大、团队强 → 自建/混合；
- 只是业务支撑、团队小、要快 → 托管；
- 金融/政务有合规要求 → 评估私有化/专有云；
- 多业务共享 → 平台化，内部计费。

### 混合模式

很多企业的实际选择是混合：

```text
核心/大流量作业：自建或专有云
长尾/实验作业：托管/Serverless
敏感数据：私有化
非敏感/弹性：公有云
```

关键是统一元数据、权限、监控，避免“两套平台”。

## 40.5 供应商评估记分卡

| 维度 | 权重 | 问题 |
|---|---|---|
| 语义正确性 | 25% | EOS、状态、恢复是否验证过？ |
| 生态连接器 | 20% | 能否接现有 Kafka/DB/湖仓？ |
| 运维体验 | 15% | 升级、监控、扩缩容、故障恢复？ |
| 成本 | 15% | 3 年 TCO？流量/状态如何计费？ |
| 安全合规 | 10% | 认证、隔离、审计？ |
| 性能 | 10% | 真实数据压测？ |
| 锁定/退出 | 5% | 数据/作业能否迁移？ |

不要只看 POC 的吞吐数字。让供应商在你的数据、你的故障场景下演示。

### POC 检查清单

- 真实 schema/倾斜数据；
- 峰值 2 倍压测；
- kill TM/JM 恢复；
- checkpoint 大状态；
- 规则/维表热更新；
- 权限/审计；
- 成本账单模拟；
- 迁移/导出。

## 40.6 创业机会

- **垂直实时 SaaS**：反欺诈、车联网、工业监控、实时推荐；
- **流数据可观测性**：lag、状态、checkpoint、成本；
- **连接器/CDC 工具**：长尾系统集成；
- **SQL/低代码平台**：降低使用门槛；
- **成本优化**：自动伸缩、状态治理、checkpoint 存储；
- **AI 流管道**：特征、向量、LLM 数据清洗；
- **合规/审计**：金融/政务的流数据治理；
- **Agent 运行时**：事件驱动 Agent、工具调用、记忆。

判断标准：

- 客户是否愿意为“实时”单独付费？
- 是否被云厂商轻易捆绑？
- 是否有数据/行业壁垒？
- 毛利是否支撑交付？
- 是否有网络效应/锁定？

### 创业的常见陷阱

- 只做“更快的 Flink”，没有差异化；
- 依赖单一云/单一客户；
- 交付重、毛利低；
- 开源核心被云厂商托管；
- 低估合规/支持成本；
- 技术领先但销售/渠道弱。

## 40.7 风险

- 开源 commoditization：引擎本身难收费；
- 云厂商捆绑：价格/渠道劣势；
- 客户集中：大客户流失致命；
- 交付重：行业项目毛利低；
- 技术变化：流批湖/数据库边界移动；
- 经济周期：实时项目预算先被砍；
- 合规/数据驻留：跨境限制；
- 人才：流处理工程师稀缺。

## 40.8 五年判断

- 实时能力成为数据平台标配，而不是差异化；
- 云托管占比继续提升；
- 湖仓/流数据库侵蚀部分 Flink 场景；
- AI 带来新增量，但要求平台支持向量/特征/模型；
- 商业价值从“引擎”转向“平台+行业+治理”；
- 开源/托管/自建的边界继续变化，客户更看重可迁移性。

## 40.9 决策清单

- [ ] 业务延迟目标是否明确？
- [ ] 实时带来的收入/风险收益可量化？
- [ ] 3 年 TCO 是否算过？
- [ ] 自建团队是否具备流处理运维能力？
- [ ] 供应商是否支持你的连接器/合规？
- [ ] 退出/迁移成本是否可接受？
- [ ] 是否有故障演练和回滚方案？
- [ ] 是否准备好状态治理和成本监控？
- [ ] 是否有基线/对账/ROI 复盘机制？

## 40.10 单位经济模型：从“能卖”到“值得卖”

TCO 回答“客户要花多少”，单位经济回答“这门生意能不能持续”。尤其是订阅/托管模式，收入曲线好看不代表模型健康。

核心指标：

| 指标 | 公式 | 说明 |
|---|---|---|
| ACV | 年合同金额 | 新签/续约口径要分开 |
| ARR | 年化经常性收入 | 不含一次性服务 |
| 毛利率 | (收入 - 直接成本) / 收入 | 云资源、支持、交付计入直接成本 |
| CAC | 获客总成本 / 新客户数 | 含销售、市场、POC、差旅 |
| LTV | ACV × 毛利率 / 流失率 | 简化口径，忽略折现 |
| CAC 回收期 | CAC / (ACV × 毛利率) | 越短越好 |
| NRR | (期初客户本期收入) / 期初收入 | 衡量扩容与流失的净效果 |
| Logo churn | 流失客户数 / 期初客户数 | 与收入流失分开看 |

### 一个算例

```text
ACV = 12 万元/年
毛利率 = 75% → 年毛利 9 万元
CAC = 30 万元
CAC 回收期 = 30 / 9 ≈ 3.3 年
年流失率 = 10% → LTV ≈ 9 / 0.10 = 90 万元
LTV / CAC = 90 / 30 = 3.0
```

表面看 LTV/CAC = 3 达标，但回收期 3.3 年太长：现金流压力大，客户第二年流失就亏。改善路径只有三条——提高客单价、降低获客成本、提高毛利率/续约率。把 ACV 提到 20 万元、CAC 降到 20 万元，回收期降到约 1.3 年，模型才健康。

经验阈值（SaaS，仅供筛选，不是定律）：

- 毛利率 > 70%（纯软件）；托管基础设施可能只有 40%～60%；
- CAC 回收期 < 18～24 个月；
- LTV/CAC > 3；
- NRR > 110%；
- Logo churn < 10%/年（企业级）。

### 定价单位怎么选

| 计价单位 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| CU/小时 | 与资源成本对齐 | 客户难预测账单 | 托管 Flink |
| vCPU/内存/小时 | 透明、易比较 | 不体现状态/网络成本 | IaaS 型产品 |
| 事件数 | 与业务量挂钩 | 小事件多、聚合难 | 按量 API/Serverless |
| GB/月（状态/存储） | 覆盖状态成本 | 客户不理解“状态” | 湖仓/状态后端 |
| 流量/出网 | 覆盖网络成本 | 易产生意外账单 | 跨 AZ/公网场景 |
| 订阅/席位 | 可预测 | 与使用量脱节 | 平台/工具 |

最忌讳“只按 CPU 计价”：流作业的成本大头可能是状态、checkpoint 存储、跨 AZ 流量和人力。计价单位要和成本驱动因素对齐，否则越卖越亏。

### 打包与合同条款

- **分层**：开发版（限额）、团队版（SLA/多租户）、企业版（合规/私有化/专属支持）；
- **承诺消费**：客户承诺年消费换折扣，平台换可预测性；
- **突发与弹性**：大促/峰值按 burst 计费，避免常态资源浪费；
- **支持分级**：8×5、7×24、专属 TAM，价格与响应时间挂钩；
- **退出条款**：数据导出、作业迁移、savepoint 兼容，降低锁定阻力。

### AI 时代的成本项

LLM/向量检索把新的成本变量带进来：

```text
每次推理成本 = 输入 token × 单价 + 输出 token × 单价 + 向量检索 + 工具调用
```

如果按“每千次预测”收费，必须把失败重试、超时、模型降级、缓存命中都算进去。否则流量越大，亏损越大。第 35 章讲过 `ML_PREDICT`/`VECTOR_SEARCH` 的工程边界，商业上同样要设预算和熔断。

## 40.11 建 vs 买的财务决策

前面的 TCO 是静态比较，真正的决策还要看现金流、风险和可逆性。一个简化模型：

```text
NPV = Σ (年净收益_t / (1 + r)^t) - 初始投入
回收期 = 初始投入 / 年净现金流
```

其中“年净收益”= 自建节省的托管费 − 新增人力/硬件/运维 − 故障损失期望。不要只算第一年：自建通常在第 2～3 年才摊薄初始投入，而人员流失、版本升级和故障会持续消耗预算。

决策时至少做三档敏感性：

| 变量 | 保守 | 基准 | 乐观 |
|---|---|---|---|
| 自建人力 | 3 FTE | 2 FTE | 1.5 FTE |
| 托管溢价 | 3 倍 | 2 倍 | 1.5 倍 |
| 年故障损失 | 200 万元 | 50 万元 | 10 万元 |
| 迁移成本 | 一次性 100 万元 | 50 万元 | 20 万元 |

如果三档下结论都相同，决策很稳；如果只有乐观档支持自建，说明你在赌“团队稳定、故障少、规模持续增长”，应准备退出方案。

## 本章小结

流处理的商业分析要回到三个问题：**实时值多少钱、要花多少钱、失败会损失多少**。技术选型只是其中一环。

对大多数企业，托管/平台 + 少量自建核心作业是更现实的路径；对平台型公司，自建 + 内部计费可能更优。无论哪种，状态、恢复、成本治理都是长期竞争力。
