# 13 现状与未来方向

> 本章目标:站在 2026 年看 Agent 生态的全景——哪些已经定型、哪些正在快速变化、
> 下一步的技术方向在哪里、还有哪些开放问题。
> 对「想写一本能读多年的书」来说,这一章负责「诚实」:明确哪些是当下的判断,
> 哪些是更持久的结构。

---

## 1. 2026 年的 Agent 生态:全景图

### 1.1 已经定型的(不太会变的地基)

- **Agent 循环是共识**:感知-思考-行动-观察,所有框架都是它的封装;
- **工具调用是标准能力**:function calling 成为模型的「内置技能」;
- **MCP 是工具接入的事实标准**:2026 年月下载量数千万级,Linux 基金会治理;
- **LLM-as-Judge 是评测主力**:结构化评分 + 多次采样成为常规操作;
- **「Workflow + Agent」混合是主流工程实践**:确定的走代码,不确定的交给模型;
- **上下文工程是独立的工程学科**:预算分配、消息排序、Prompt Caching、
  动态工具子集与压缩,被主流厂商(Anthropic 等)作为专门方法论工程化推广
  (本教程第 05 章)。它随长上下文普及而地位上升——「会塞」比「塞得多」更重要。

### 1.2 正在快速变化的

- **框架格局**:从「胶水库(2023)」到「状态图(2024-25)」到「协议化(2026)」,
  每 6–12 个月换一次主角;
- **协议**:MCP 走向无状态核心;A2A 从提案走向落地;ACP(Agent Client Protocol)等新协议出现;
- **模型能力**:长上下文(200k–1M)、更强的工具遵循、原生多模态、实时语音(Realtime);
- **自主 Agent**:Claude Code 式的深度自主 Agent 从小众走向主流产品形态;
- **编码 Agent(最大的真实落地场景)**:Claude Code、Cursor 类产品是 2026 年
  Agent 商业化最成熟、部署量最大的品类——它们示范了「长会话 + 检查点 +
  权限感知」如何在生产里成立(见下方 §1.3 第 5 点);
- **实时语音 Agent(Realtime)**:语音到语音(ASR→LLM→TTS 端到端低延迟)成为
  客服、助理产品的新形态,对 Agent 的「对话形态」有结构影响(第 12 章流式
  与低延迟由此更重要)。

### 1.3 2026 年生态的五个关键词

1. **协议化**:MCP(AI↔工具)、A2A(AI↔AI)、ACP(AI↔应用界面)三线并进,
   互操作取代私有集成;
2. **记忆是最大的短板**:所有框架与产品的长程记忆都不成熟——
   这是 2026 年最确定的「机会窗口」;
3. **评测与安全从选修变必修**:企业采纳 Agent 的门槛是「能不能评测、安不安全」;
4. **低代码化**:Dify、Coze 等平台让非工程师也能搭 Agent,但深度工程仍需专业能力;
5. **企业 GRC 与私有化**:真正的企业采纳卡在**治理(Governance)、风险(Risk)、
   合规(Compliance)**——「能不能审计、出问题谁签字、数据能不能出域」比
   「效果好不好」更先被问。许多企业因此走**端侧/私有化部署**,用开源或
   私有化模型 + 自托管推理,这直接塑造了记忆与安全的产品形态。

> **给读者的一句提醒**:本节描述的是 2026 年年中的生态,具体产品与下载量数据
> 会快速变化;判断依据建议以官方文档与当时的生态报告为准。

## 2. 五个技术方向

### 2.1 记忆与持久状态

**问题**:当前 Agent 的记忆是「检索片段」,不是「真正的记忆」——
没有稳定的自我模型、没有自动整理、没有主动遗忘(第 04 章)。

**方向**:
- **自主记忆管理**:让 Agent 自己决定「何时存、存什么、何时忘」(MemGPT 路线);
- **结构化记忆**:从「文本片段」升级为「实体 + 关系 + 时间」的图记忆,
  支持推理(「用户 A 是用户 B 的上级」);
- **记忆压缩与分层**:自动化摘要金字塔,无限对话而不爆窗;
- **记忆即身份**:跨任务复用的「Agent 人格」与「经验库」。

### 2.2 多模态 Agent

- **输入多模态**:Agent 直接理解截图、表格、音频、视频
  (「看这张图上的价格表,帮我比价」);
- **输出多模态**:生成图片、语音、操作 UI;
- **计算机使用(Computer Use)**:Agent 直接操作 GUI——点按钮、填表单、
  拖拽——把「API 之外的世界」也纳入能力边界。

### 2.3 自主与自我进化

- **自我评估**:Agent 判断「我该不该继续、该不该换策略」的能力更成熟;
- **经验沉淀**:把成功轨迹提炼为「技能/流程」复用(程序记忆);
- **自我纠错**:不仅修正单步错误,还能修正「方法」(反思升级为策略学习);
- **长期运行**:面向小时/天/月级目标的持久 Agent(不再是单次任务)。

### 2.4 多智能体与「Agent 社会」

- **跨组织协作**:A2A 让不同公司的 Agent 相互协作(一家客服 Agent 找另一家
  物流 Agent 查包裹)——Agent 的「互联网」;
- **角色与身份**:Agent 有持久身份、信誉、权限(类似互联网的域名与证书);
- **协商与市场**:Agent 之间竞价、协商、结算(第 08 章市场模式的新形态);
- **安全与治理**:Agent 社会的规则(谁能调用谁、如何审计)成为新领域。

### 2.5 Agent 基础设施(Agent OS / Cloud)

- **Agent 运行时**:跨进程/跨机的 Agent 编排、调度、状态管理成为云服务;
- **Agent 开发平台**:从代码 SDK 到可视化编排 + 内置评测 + 内置护栏;
- **设备驱动层**:MCP 已被称为「LLM 应用的 USB」,这类基础设施在持续深化。

### 2.6 Agent 经济与商业模式(2026 正在成形)

技术方向之外,Agent 的**商业模式**也在成形。看懂钱怎么流动,
有助于判断哪些技术方向会被资本加速:

| 模式 | 谁买单 | 例子/形态 |
|---|---|---|
| **按任务付费** | 用户为「完成一个任务」付费 | 报告生成、代码修改、客服工单,按结果定价 |
| **按用量付费(API)** | 开发者 | token、工具调用次数、MCP 服务器订阅 |
| **Agent 即服务(AaaS)** | 企业 | 垂直 Agent(客服/法务/财务)按席位或结果订阅 |
| **结果分成** | 交易双方 | Agent 撮合交易按成交额抽成(电商/物流/金融) |
| **Agent 间结算** | 其它 Agent | A2A 场景:一个 Agent 调用另一个 Agent 的能力并付费 |

**对技术方向的启示**:
- 「按任务付费」需要**可靠的结果评测**(第 10 章)——定价的前提是「能证明
  任务完成了」;
- 「Agent 间结算」需要 **A2A 协议 + 身份/信誉体系**(第 08 章 §5、
  第 11 章 §3.4);
- 这些商业模式在 2026 年都还是早期,但「评测」与「身份」会成为
  底层基础设施——和本教程第 10、11 章的技术正好互补。

## 3. 模型侧会怎么变

Agent 的能力天花板由模型决定,2026 年的几个模型侧趋势直接影响 Agent:

| 趋势 | 对 Agent 的影响 |
|---|---|
| **长上下文普及** | 更多上下文直接塞进窗口,减少对检索的依赖(但仍不解决「无限记忆」) |
| **更强的工具遵循** | 工具选择更准、并行调用更稳、错误修正更快 |
| **原生结构化输出** | 规划/评测/决策的 JSON 输出更可靠 |
| **小模型 + 路由** | 混合模型架构:简单步骤便宜,复杂步骤贵(成本工程的新杠杆) |
| **多模态** | 见 §2.2 |
| **推理模型(Reasoning)** | 长思维链提升复杂推理,但延迟与成本更高,需按任务分级使用 |

## 4. 开放问题(Open Problems)

写「能读很多年」的书,必须诚实:以下问题在 2026 年**尚未解决**,
是未来几年最值得投入的方向。

1. **可靠的长程记忆**。生产级记忆 = 语义检索 + 自动整理 + 主动遗忘 + 隐私合规,
   没有一个框架做到了全部。
2. **可靠评测的自动化**。LLM-as-Judge 有偏差,轨迹评测成本高,
   「自动评估复杂任务成功与否」仍是半开放问题。
3. **安全与自主的平衡**。自主性带来价值,也带来风险。如何让 Agent
   「既强大又可约束」,没有通用解。
4. **Agent 的可解释性**。长轨迹里「为什么做了这个决定」难以解释,
   审计与信任的根基不牢。
5. **跨任务泛化**。多数 Agent 是「一个任务一个系统」,
   如何把经验从一个领域迁移到另一个领域,基本未解决。
6. **成本的可预测性**。自主 Agent 的 token 消耗方差大,
   「预算内完成目标」仍难保证。
7. **Agent 之间的信任**。A2A 的协议有了,但「怎么验证对方 Agent 可靠」没有。

## 5. 一些判断(带时间戳的诚实)

这些是 2026 年的判断,五年后回看可能不全对,但它们是**当前最合理的推断**:

- **短期(1–2 年)**:MCP 继续深化、A2A 开始落地、记忆成为差异化卖点、
  评测/安全工具进入企业采购清单;
- **中期(3–5 年)**:多 Agent 跨组织协作出现真实场景;持久化「AI 同事」
  (有身份、有记忆、有权限)成为产品形态;
- **长期(5 年+)**:Agent 从「工具」演进为「平台上的公民」——届时
  本教程第 11 章的安全问题会升级为「社会级治理问题」。

**但有些结构不会变**:
- 循环:感知-思考-行动-观察;
- 工程:能确定就 Workflow,不确定才 Agent;
- 度量:没有评测就没有改进;
- 原则:能力越强,约束越紧。

## 7. 对照 mini-agent:站在现在看未来

mini-agent 是一座「概念桥」:它把 2026 年的 Agent 原理讲清楚,
也为未来留好了接口——

- 把 `VectorMemory` 换成真实向量库 → 追上记忆方向的第一步;
- 把 `MockProvider` 换成多模态模型 → 支持多模态输入;
- 把 `Orchestrator` 接到 A2A → 跨组织协作;
- 把 `Tracer` 换成 OTel → 生产可观测。

**它的价值不在「功能全」,而在「结构对」**。结构对了,未来的一切升级都是填空。

## 8. 监管与治理:Agent 合规的地平线

Agent 越接近生产,「合规」越从法务的文档变成工程师的代码。三条主线值得
在 2026 年就盯住(本节只给方向与要点,具体生效日期**以官方最新为准**):

### EU AI Act:全球第一个「AI 通用立法」

2024 年欧盟通过《人工智能法案》(EU AI Act),分阶段生效。与 Agent 最相关的
两条义务线:

- **高风险 AI 系统**:需满足风险管理、数据治理、人工监督、文档与可追溯性等义务。
  **对 Agent 的启示**:自主决策系统更容易被认定为高风险——一个「能自己调工具、
  自己发消息」的 Agent,比单次问答的 LLM 应用更接近高风险定义;
- **GPAI(通用人工智能)模型**:2025 年 8 月起部分义务生效,面向「通用能力」的
  基础模型,重点是透明度与版权合规。

**工程启示**:EU AI Act 的「人工监督」义务,正好是第 12 章 §7 人机协作的制度化表达
——审批队列、可暂停、可接管,既是工程,也是合规。

### NIST AI RMF:美国的风险管理框架

NIST AI Risk Management Framework(RMF 1.0/2.0)用四个核心功能组织:

```
Govern(治理) → Map(映射) → Measure(度量) → Manage(管理)
```

- **Govern**:责任、透明、组织流程;
- **Map**:识别 Agent 的上下文与风险场景;
- **Measure**:量化评估——与第 10 章的安全评测、第 11 章的安全基线直接对应;
- **Manage**:响应与改进——对应第 12 章的监控与反馈闭环。

**要点**:RMF 的「Measure」把「安全评测」写进了官方建议;做 Agent 安全评测的团队,
用 RMF 的语言汇报,更容易被组织接受。

### 国内监管:生成式 AI 服务管理

《生成式人工智能服务管理暂行办法》(2023)及后续配套,对面向公众的服务提出:

- **算法备案**:提供具有舆论属性或社会动员能力的服务需备案;
- **安全评估**:上线前进行安全评估(内容安全、数据安全);
- **内容标识**:AI 生成内容需按规定添加标识。

**工程启示**:内容标识 = 生成侧加标记(第 12 章输出侧);安全评估 = 第 10 章评测集里
的安全用例 + 第 11 章的加固清单。监管要「可执行的证据」,评测报告就是证据。

### 落地点:合规是工程的一部分

合规不是法务单独的事,它有清晰的技术底座:

- **评测(第 10 章)**:安全用例、红线用例,是「安全评估」的可执行证据;
- **审计日志(第 12 章)**:trace + 审批记录,是「可追溯性」的原料
  (第 11 章 GDPR 的「可删除」与「审计」是两条不同的线,都要留);
- **可解释性(第 02 章反思)**:让「为什么这么做」讲得清,是「人工监督」的前提。

> **一句话**:先把评测、审计、可解释性做扎实,合规审查来临时,你交出的不是文档,
> 而是可运行的证据链。具体时间线以官方最新为准。

## 9. 本节要点

1. 2026 生态:循环/工具/MCP/Judge 已定型;框架与协议在快速更迭;
2. 五个关键词:协议化、记忆短板、评测安全必修、低代码化、企业 GRC/私有化;
3. 五个技术方向 + 商业模式:记忆与持久状态、多模态、自主进化、多智能体社会、
   Agent 基础设施——外加 §2.6 的 Agent 经济(计数为五个技术方向,商业模式单列);
4. **商业模式在成形**:按任务付费、AaaS、结果分成、Agent 间结算——
   都需要「评测」与「身份」做底层(与第 10、11 章互补);
5. 模型侧:长上下文、强工具遵循、原生结构化、小模型路由、推理模型;
6. 七个开放问题:长程记忆、自动评测、安全平衡、可解释性、跨任务泛化、
   成本可预测、Agent 信任;
7. **监管与治理成为必修课**:EU AI Act 分阶段生效、NIST AI RMF、国内生成式 AI 监管——
   评测(第 10 章)、审计日志(第 12 章)、人工监督(第 12 章 §7)是合规的技术基础(§8);
8. **结构性的知识不会过时**:循环、工程权衡、评测驱动、能力与约束的平衡。
