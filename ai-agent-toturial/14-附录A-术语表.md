## 12. 工程原则(第 22 章附录 I)

| 术语 | 含义 | 章节 |
|---|---|---|
| **工程原则(Principles)** | 可命名的「该按什么标准做决定」的判断依据;与反模式互为镜像 | 22 |
| **P-01 有目标+能行动+能迭代** | Agent 的最小定义,判断系统性质的第一问 | 01、22 |
| **P-02 能确定就不用模型** | 确定的部分用代码/规则,不确定的部分才交给模型 | 01、22 |
| **P-05 先单后多** | 多 Agent 必须由评测证明必要,一次只拆一个 | 08、22 |
| **P-12 停止条件三问** | 正常结束 + 硬上限 + 预算上限,少一个就是烧钱 | 02、22 |
| **P-13 循环是状态机** | 显式状态(消息+计数+预算)带来可恢复/可测试/可观测 | 02、22 |
| **P-19 自建中间格式** | 不绑定任何厂商的 Message/ToolCall 契约 | 03、07、22 |
| **P-23 工具参数必校验** | 模型输出是「需要校验的输入」,不是「模型的承诺」 | 03、11、22 |

| **P-57 没有评测就不是改进** | 评测是 Agent 工程的第一优先级 | 10、22 |
| **P-58 结果+轨迹双重断言** | 过程对,结果才可持续;`AgentResult.messages` 是轨迹数据源 | 10、22 |
| **P-60 能力边界是最后防线** | 别指望模型懂安全,要让系统在模型被骗时依然安全 | 11、22 |
| **P-66 成本公式化** | `C ≈ n×(P_in·r_in + P_out·r_out) + 工具成本`,优化=改变量 | 12、22 |
