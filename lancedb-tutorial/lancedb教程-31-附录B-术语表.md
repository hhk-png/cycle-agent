# 附录 B　术语表

这份表解决一个具体问题：**同一个概念，在不同的中文资料里被翻成了不同的词，
而在同一份教程里必须只有一个。** 下面每一条给出英文原词、本教程统一使用的
中文译法、一句话解释，以及它主要出现在哪一章。

有三条命名约定先在前面说清楚，因为它们决定了后面很多条的写法：

**能用英文的就不硬翻。** `prefilter` / `postfilter` / `nprobes` /
`manifest` / `mini_block` / `FastScan` 这些词，中文圈里的译法
（"前置过滤""后置过滤""探测数"）反而会造成歧义——尤其是 `prefilter`
一旦翻成"前置过滤"，读者就没法把它和 `where(..., prefilter=...)`
这个 API 参数对应起来。这类词一律保留英文。

**译法以章节里的实际用法为准。** 这张表不是"我认为该怎么翻"，
而是"这份教程正文里确实这么写"。如果某一条和正文对不上，
以正文为准，并且应该修的是这张表。

**一个英文词只对应一个中文词。** 比如 `compaction` 全篇是"压实"，
不是"合并"也不是"压缩"（那是 compression）；`fragment` 全篇是"片段"，
不是"分片"。

条目按英文首词的首字母分组，数字和小写开头的单独归在开头那一组：

数字与小写开头 · A · B · C · D · E · F · G–H · I–K · L · M · N · O–P ·
R · S · T · V–Z

## 数字与小写开头

**4-bit SQ**（4-bit 标量量化）——
比 8-bit SQ 再省一半空间的标量量化档位。第 16.4 节。

**m**（HNSW 的度数上限）——
每个节点最多连多少条边。它同时决定内存占用、
建图时间，以及层高分布（`ml = 1/ln(m)`），是 HNSW 建图前必须定下来的
第一个参数。第 15 章，见 HNSW。

## A

**accelerator**（加速器 / GPU）——
`create_index` 上可选的计算后端：`"cuda"`（Linux）或 `"mps"`（Apple
Silicon），打开后由 PyTorch 训 k-means、Rust 核心负责索引序列化。
GPU 建索引不是新功能（2023 年就有），官方给的 19–26 倍是**厂商口径**；
只有"自动 GPU 索引"是企业版独占。第 12.4、29.3.1 节。

**ADC**（asymmetric distance computation，非对称距离计算）——
PQ 检索时用"查表"代替"逐维算距离"的做法：查询向量不量化，
数据库向量量化，所以两侧不对称。这是 PQ 能把距离计算从
O(维数) 降到 O(子空间数) 的关键。第 14.3 节。

**ANN**（approximate nearest neighbour，近似最近邻）——
不保证返回真正的最近邻、只保证大概率的检索方式。
整份教程里"向量检索"基本就等于 ANN。第 12.1 节。

**Arrow**（Apache Arrow）——
列式内存格式的事实标准，定义了类型系统、缓冲区布局和零拷贝的
跨语言交换。LanceDB 的读写边界就是 Arrow 的 `Table` / `RecordBatch`。
第 5 章。

**Arrow Flight**（Flight / Arrow Flight RPC）——
Arrow 生态里的 gRPC 传输协议，把 C Data Interface 的零拷贝语义
从"同进程"扩到"跨网络"。它解决的是**"计算发生在哪里"**
（服务端读、只把结果传回来），不是"传输更快"——
跨网络时省掉的是序列化，不是字节。开源版 Python API
**没有提供 Flight 端点**（实测 `lancedb` 顶层与表上都没有相关名字）。
附录 J.6。

**ASCII folding**（ascii_folding，ASCII 折叠）——
把重音字符折叠成 ASCII 等价形式（`café` → `cafe`）的分词器阶段。
它属于"归一化"那一类变换。第 17.4 节。

## B

**B-tree**（B 树 / B+ 树）——
多路平衡搜索树，节点里存多个有序键，适合范围查询。
LanceDB 的 `BTREE` 标量索引在物理上是"分页的键 + 页表"，
所以它更像 B+ 树的上层结构而不是经典内存树。第 18.1 节，见 scalar index。

**bitmap index**（位图索引）——
为列的每个不同取值维护一张位图，第 i 位表示第 i 行是否等于该值。
低基数列上的等值与 `IN` 查询最快，高基数列上会爆炸。第 18.2 节。

**blob**（blob / 二进制大对象）——
把图片、音频、视频这类"一个值就几十 MB"的内容当一等公民存。
Lance 把 blob 外置成独立 buffer，行里只留偏移和长度。第 21.4 节。

**BM25**（Best Matching 25）——
全文检索的经典打分函数，由 TF-IDF 演进而来，加了词频饱和与文档长度归一。
**分数越大越相关**，和向量检索的 `_distance` 方向相反。第 17.3 节。

**branch**（分支）——
可写的版本引用，`main` 是默认分支。它和 tag 的区别是：
tag 是只读的书签，branch 上可以继续提交。第 7 章。

**brute force**（暴力检索）——
不算索引，直接对所有向量逐个算距离。**小数据上它几乎总是更快**，
第 12 章实测 2 万行 64 维只要零点几毫秒。第 12.1 节。

**byte_stream_split**（BSS，字节流拆分）——
把浮点数的各个字节按"先所有数的第 0 字节、再所有数的第 1 字节"
的顺序重排，让高位字节集中在前、利于压缩。第 4 章实测它只省 7.1%，
在量化过的浮点上反而更大 12%。第 4 章。

**BQ**（binary quantization，二值量化）——
每一维只留一个符号位，压缩率 32 倍，距离用汉明距离算。
召回率损失明显，适合"可以多取候选、最后再重排"的流水线。
第 16.5 节。

**bloom filter**（布隆过滤器）——
一种概率型集合结构，"元素不在集合里"永远不会判错、
"在集合里"可能是误判。在 Lance 里用作标量索引的一种，加速
高基数列的**等值**查询。本实现没有实现它，只在概念上讨论过。
第 10、18 章。

## C

**C Data Interface**（Arrow C Data Interface，Arrow C 数据接口）——
Arrow 的跨语言 ABI，让不同语言/不同库的实现**共享同一块内存而不经过
序列化**。它有两个入口且语义不同：`__arrow_c_array__` 导出一块连续的
列式内存（`ArrowArray`），`__arrow_c_stream__` 导出一个可以反复拉的游标
（`ArrowArrayStream`）。LanceDB 的查询结果走的是 **stream** 那条
（实测 `__arrow_c_stream__` 有、`__arrow_c_array__` 没有）。
附录 J.2。

**computed column**（计算列）——
由其他列（或表达式）算出来的列，通过 `add_columns` 声明、
用 `refresh_column` 补算或重算。它是"派生数据"这一层的一部分，
依赖稳定行 id 才能正确刷新。附录 F.8。

**CJK bigram**（CJK 双字组）——
中文没有空格分词，教学实现把 CJK 连续段切成**重叠的二元字符组**
（`中国人民银行` → `中国 / 国人 / 人民 / 民银 / 银行`），标点和全角形式
被排除在段外。真实 LanceDB 走 jieba / lindera / icu，两边检索质量不可比。
第 17.6 节。

**codebook**（码本）——
量化里"一组代表向量或代表取值"的集合。PQ 的码本是每个子空间的
k-means 质心，SQ 的码本是每一维的分桶边界。第 13、14、16 章。

**ColBERT**（Contextualized Late Interaction over BERT）——
把"一篇文档一个向量"换成"每个 token 一个向量"的检索方案，
用 MaxSim 在查询 token 和文档 token 之间做晚交互。第 21.1 节。

**column metadata**（列元数据）——
Lance 文件里描述"这一列分成几页、每页用什么编码、值在哪些缓冲区、
min/max/null 数是多少"的结构。**元数据成本随页数线性增长**，
这是"页不能太小"的直接原因。第 3.4 节。

**compaction**（压实）——
把一批小片段合并成更大的片段，减少文件数量和删除文件开销。
**它不保证让查询变快**——第 23 章实测过一次压实后同一个查询
**多读约 27 倍字节**的案例，原因是一百组 min/max 统计被合并成了一组。
（口径是字节数，不是延迟：挂钟时间不是确定量，那一节明确不当结论用。）
第 23 章。

**conditional put**（条件写）——
"只有目标对象还不存在时才写入"的存储原语，也叫
`put_if_not_exists` / `If-None-Match`。它是无锁原子提交的地基：
提交 manifest 就是一次条件写，失败了说明别人先提交了。
第 6、8 章。

**conflict matrix**（冲突矩阵）——
"当前事务类型 × 并发事务类型 → 能不能共存"的表格。
它把"乐观并发下什么时候必须重试"从经验变成了可查的表。第 8 章。

**cosine distance**（cosine / 余弦）——
用向量夹角衡量关系，对向量长度不敏感。正文里它有时以
"余弦相似度"的形式出现（第 20.2 节，讲分数方向那一处），
所以要注意**同一个 `cosine` 在"相似度"和"距离"两种叙述下方向是反的**。
API 参数一律写作 `'cosine'`。它在归一化向量上等价于 L2 的单调变换。
第 12、20 章。

**cross-encoder**（交叉编码器）——
把"查询 + 文档"拼成一个输入、让模型直接输出相关性分数的重排模型。
**准但慢**（要对每个候选跑一次前向），所以只能放在最终重排那一步。
第 20.6 节。

**DataFusion**（Apache DataFusion）——
Rust 写的查询引擎，提供物理计划、算子（`ProjectionExec` /
`FilterExec` / `SortExec` …）和表达式求值。**LanceDB 的查询执行不是
自己写的执行器，而是把 Lance 的读取算子挂到 DataFusion 的物理计划上跑**
——`analyze_plan()` 里那些 `*Exec` 就是它。附录 I.2。

## D

**data skipping**（data skipping，数据跳过）——
用"每块的 min/max 统计"直接排除不可能命中的块，从而少读数据。
它和索引的区别是：索引要先建，跳过靠的是本来就有的统计。
第 18 章。

**deletion file**（删除文件）——
记录"这个片段里哪些行被删了"的独立文件。数据文件本身不可变，
删除通过"写一个删除文件 + 改 manifest"完成。第 9 章。

**delta encoding**（delta 编码 / 差分编码）——
存相邻值之差而不是值本身，对单调递增的列很有效。
解码时必须**加上首值**，漏掉它只在首值非零时暴露——
附录 C 记了这个真实的 bug。第 4 章。

**delta index**（增量索引 / delta 索引）——
新写入的数据先建一个小的补丁索引，查询时新旧两份一起查，
避免每次都重建全量索引。第 18、23 章。

**dictionary encoding**（字典编码）——
把重复出现的值抽成字典，列里只存字典下标。
低基数（重复率高）的列上收益最大。第 4 章。

**distance**（距离 / 度量值）——
向量检索返回的 `_distance` 列。**它的方向和 `_score` 相反**：
距离越小越好。第 12、19、20 章。

**document frequency**（df，文档频率）——
包含某个词的文档数。BM25 里 `df` 越大、这个词的区分度越低、
权重越小。第 17.3 节。

**dot distance**（dot product，内积）——
不做归一化的相似度，等价于 cosine 乘以两个向量的模长。
归一化向量上它和 cosine 是同一件事。第 16、20 章。

## E

**ef / ef_construction**（HNSW 的束宽参数）——
`ef_construction` 是建图时每层的候选束宽，`ef` 是查询时的束宽。
两者越大召回越高、越慢。**源码默认 `ef_construction=300`，
文档说 150**，以源码为准。第 15 章。

**embedding function**（嵌入函数）——
把文本/图片转成向量的函数，注册到表上之后写入时自动补向量列。
第 22 章。

## F

**FastScan**（FastScan）——
PQ 检索里的一个加速技巧：把码本分组、用 SIMD 一次算一批子空间距离，
牺牲一点精度换吞吐。**本教程正文没有展开它，`mini_lancedb` 里也没有实现它**
（2026-10 检索正文，未找到该词）。列在这里只是因为它在 PQ 的论文和
其它向量库里出现的频率很高，读者会遇到。第 14 章的 PQ 部分讲了
它要解决的问题（ADC 的查表开销）。

**fast_search**（fast_search）——
一个**方法**（不是 `search()` 的关键字参数），作用是把
"对未索引数据的那一次暴力扫描"跳掉。代价是未索引的行
**会被静默跳过**。第 12.6 节。

**field id**（field_id，字段 id）——
字段的稳定数字标识，和数据文件一起落盘。有了它，
"删掉中间一列"就是纯元数据操作，老数据文件依然可读。第 5 章。

**file format version**（文件格式版本）——
容器布局与编码集，目前是 2.0 到 2.3（稳定 2.2，在研 2.3）。
它和 Rust crate 版本、Python 包版本、索引格式版本**是三套独立编号**；
升级格式版本不是改开关，而是一次数据集重写。第 0.6、28.2 节。

**flat index**（FLAT 索引 / 暴力索引）——
不建任何结构、查询时全量扫描的"索引"。在 LanceDB 里
`IVF_FLAT` 指的是"IVF 分区 + 分区内不量化"，而"不建索引"的那条路径
在正文里统一叫**暴力检索**。第 12、13 章。

**fragment**（片段）——
一次写入产生的一组数据文件，是版本管理、压实、统计剪枝的基本单位。
一个表由若干片段组成，每个片段有自己的行范围和统计。第 7 章。

**fragment id**（片段 id）——
片段的数字标识，参与构成稳定行地址。真实 Lance 用随机 u64，
这样多个写入者不会撞 id。第 7、9 章。

**FSST**（Fast Static Symbol Table，快速静态符号表）——
一种为短字符串设计的压缩算法：先建一张"常见子串 → 单字节符号"的静态表，
再把字符串换成符号序列。第 4 章。

**FTS / full-text search**（全文检索）——
基于词匹配的检索，和向量检索互补：它擅长精确词、专有名词、代码标识符，
不擅长同义改写。第 17 章。

**FlatBuffers**——
Lance 用来序列化 manifest 等元数据的二进制格式（Google 出的，
和 protobuf 同一族但**不需要先解析出一个中间对象**，
可以直接随机访问字段）。"schema 演进代价低"这件事一部分建立在
它的自描述性上。第 3、7 章。

**FM-Index**（FM 索引 / Ferragina-Manzini 索引）——
基于 BWT（Burrows-Wheeler 变换）的**精确子串**索引，
能对字节串做 `LIKE '%abc%'` 的精确匹配而不是候选集。
它和 NGRAM 的分工是"精确"对"近似"。第 18.9 节。

## G–H

**ground truth**（基准真值 / 真值集）——
用暴力检索算出来的"真正的最近邻"，用来计算索引的召回率。
第 12、13 章。

**Hamming distance**（汉明距离）——
两个等长二进制串里不同位的个数。BQ 用它来做超快的距离比较。
注意 `IvfFlat(distance_type='hamming')` 在 0.40.0 上会让 Rust 层 panic。
第 16 章。

**HNSW**（Hierarchical Navigable Small World，分层可导航小世界）——
分层的近邻图，上层稀疏用于快速下降，下层稠密用于精确定位。
建图慢、内存大，但查询延迟和召回都很好。第 15 章。

**hybrid search**（混合检索）——
向量检索和全文检索同时跑、再把两路结果融合。
融合前必须先解决"分数方向相反"的问题。第 20 章。

## I–K

**idf**（inverse document frequency，逆文档频率）——
`log` 形式的"词有多稀有"，BM25 里给稀有词更高权重。第 17.3 节。

**index_stats**（索引统计）——
`table.index_stats(name)` 的返回值，包含
`num_indexed_rows` / `num_unindexed_rows` / `size_bytes` 等。
**索引名不存在时返回 `None`，不抛异常**。第 12.6 节。

**inverted index**（倒排索引）——
"词 → 文档列表"的映射，全文检索的核心结构。
每个词对应一个 posting list。第 17.2 节。

**IVF**（inverted file，倒排文件）——
先用 k-means 把向量空间分成若干分区，查询时只探测最近的
`nprobes` 个分区。它是向量索引里的"粗筛"层。第 13 章，见 PQ、residual vector。

**k-means**（k-means / k 均值聚类）——
把 N 个点分成 k 簇的迭代算法：分配点到最近质心、重算质心、重复。
IVF 和 PQ 两者的训练都用它。第 13.3 节。

**Iceberg**（Apache Iceberg）——
最主流的开放湖仓表格式，和 Lance 是同一层的竞品：
都提供快照、清单、schema 演进。两者的根本差异在**数据文件**上——
Iceberg 用 Parquet（面向扫描优化），Lance 用自己的格式
（面向随机访问、向量检索和多模态）。第 1、26、27 章。

## L

**label list index**（LABEL_LIST 索引）——
当列的值本身是一个列表（标签、多值字段）时用的索引，
回答"哪些行的列表里包含 X"。第 18.3 节。

**Lance file format**（Lance 文件格式）——
自研的列式文件容器：数据页 + 列元数据 + offset 表 + 全局缓冲区表
+ 40 字节 footer（尾部魔数 `LANC`）。第 3 章。

**Lance V3**（Lance V3）——
一个流行的误称：**不存在 "Lance 文件格式 V3"**。会遇到的 "Lance V3"
指的是向量索引的落盘布局 V3（`index_version`），或者全文索引的
posting 布局 V3（FTS 的 `block_size=256`），两者都**不是文件格式**。
第 0.6、28.3 节，见 file format version。

**late interaction**（晚交互）——
查询和文档各自编码成多向量、在检索时才做精细交互的方案。
ColBERT 是代表。第 21.1 节。

**late materialization**（延迟物化）——
先只读过滤用的列算出掩码，再把活下来那些行的投影列读回来。
列存最大的杀招，收益量级等于过滤的选择性。第 10、19 章。

**latest hint**（latest hint / 最新提示文件）——
一个只记"当前最新版本号"的小文件，让读取者一次读就能定位最新版本，
不必 LIST 整个版本目录。第 7 章。

**LSM**（Log-Structured Merge tree，日志结构合并树）——
把写变成"顺序追加 + 后台合并"的写入策略。LanceDB 用它支撑
高频小批写入。第 25 章。

**LZ4**（LZ4）——
以解压速度著称的通用压缩算法，"低延迟"那一档。
第 4 章里有它和 Zstd 的取舍。

## M

**manifest**（manifest / 版本清单）——
记录"这个版本包含哪些片段、哪些删除文件、哪些索引、schema 是什么"
的元数据快照。**每个版本一个 manifest，写完就不可变。** 第 7 章。

**MaxSim**（MaxSim / 最大相似度）——
ColBERT 式晚交互的打分方式：对每个查询 token，取它在文档所有
token 里最相似的那个，再把这些最大值加起来。第 21.1 节。

**merge insert**（merge_insert / 合并插入）——
一次事务里同时完成插入、更新、删除的 upsert 操作，
按 `on` 指定的键做连接。**它会重排行**，而且超过一万行就不实用了。
第 9、25 章。

**metric**（度量）——
距离函数的选择：`l2` / `cosine` / `dot`（某些路径还有 `hamming`）。
0.40.0 里 `distance_type()` 是正名，`metric()` 是它被标记为
"将来可能弃用"的别名；建索引侧只有 `distance_type` 一个名字。
第 12、13 章。

**mini_block**（mini-block / 小块）——
把一页切成更小的块，让"跳过一部分数据"能以更细的粒度进行。
第 4、6 章。

**MRR**（Mean Reciprocal Rank，平均倒数排名）——
一种融合/评价方式：只看到"第一个相关结果排在第几位"，
取名次的倒数。对分数尺度免疫，和 RRF 是同一家族。第 20 章，
见 RRF、reranker。

**MVCC**（Multi-Version Concurrency Control，多版本并发控制）——
读操作看一个固定快照、写操作生成新版本，读写互不阻塞。
LanceDB 的版本机制是 MVCC 的一种实现。第 8、27 章。

**materialized view**（物化视图）——
把一条查询的结果当作一张**真表**存下来的派生数据。它依赖
**稳定行 id** 才能做增量刷新（没有它就只能全量重算）。
它和"视图"不是一回事：视图不存数据，而且在开源版里不可用。
附录 F。

**MemWAL**（内存 WAL / LSM 写路径）——
0.40 里一条可配置的写路径：小批写入先进内存（WAL），
攒够了一次性落盘。它能提高小批写的吞吐，代价是
"数据什么时候真的可见"变成了一件可配置的事。
第 8 章与附录 G.4。

## N

**namespace**（命名空间）——
表的分组层级，用来在同一套存储上做多租户隔离。
本地连接没有这个能力，调用会抛 `NotImplementedError`。第 6、25 章。

**NGRAM index**（NGRAM 索引）——
把字符串切成连续 n 个字符的片段建索引，用来加速 `LIKE '%abc%'`
这类**中间匹配**。它只给候选集，还要回表验证。第 18.4 节。

**nprobes**（nprobes / 探测分区数）——
IVF 查询时探测几个分区。调大它提升召回，但**在量化误差主导时
它会卡在一条平台上不动**——第 24 章实测从 1 加到 64，
召回只从 0.42 升到 0.47 就不再动了。那时该拧的是 `refine_factor`。
第 13.5、24.3 节。

**null bitmap**（有效性位图 / null 位图）——
每个值 1 bit，标记该位置是不是 null。Arrow 里叫 validity bitmap。
第 3、5 章。

## O–P

**object store**（对象存储）——
S3、GCS、Azure Blob 这类"只能整体读、整体写、按 key 访问"的存储。
LanceDB 的很多设计（不可变文件、条件写、清单合并）都是为它做的。
第 6 章。

**on_bad_vectors**（坏向量处理策略）——
写入时遇到长度不一致或含 NaN 的向量怎么办：
`'error'` / `'drop'` / `'fill'` / `'null'` 四选一。第 25 章。

**optimize**（optimize / 一键维护）——
把压实、清理旧版本、索引维护收成一个动作的方法。
**它的返回值是 `None`**，尽管存在一个叫 `OptimizeStats` 的类。第 23.6 节。

**page**（页 / 数据页）——
列里一段连续的值，是编码、压缩、读取的最小单位。
**编码是逐页决定的**，同一列的不同页可以用不同编码。第 3、4 章。

**page table**（页表）——
记录每页的（偏移, 长度, 编码）的映射表。有了它，
"读第几页"就只需元数据，不必先解析前面的页。第 3 章。

**partitioned search**（分区级检索）——
在 IVF 结构上把"探测哪些分区"当成一级并行任务，
分区之间的搜索彼此独立、可以分发。第 12 章。

**postfilter**（postfilter / 后置过滤）——
先做 ANN 再过滤。**它不是"另一种实现"而是"另一个查询语义"**：
`prefilter=False` 时会返回**少于 k 行**。第 18.8、19.5 节。

**posting list**（位置列表 / 倒排列表）——
倒排索引里"某个词出现在哪些文档的哪些位置"的列表。
存位置是为了支持短语查询。第 17.2 节。

**PQ**（product quantization，乘积量化）——
把高维向量切成若干低维子空间、每个子空间各自量化，
距离计算退化成查表。压缩率高、精度可调，是 IVF_PQ 里的那个 PQ。
第 14 章，见 IVF、residual vector。

**prefilter**（prefilter / 前置过滤）——
先过滤再检索：用标量索引算出候选掩码，只在掩码内做 ANN。
过滤后候选集远小于 k 时，它和 postfilter 的结果会**根本不同**。
第 18.8、19.5 节。

**predicate pushdown**（谓词下推）——
把过滤条件下推到扫描层，让"不该读的数据在更早的地方就被跳过"。
第 10 章。

**prewarm**（预热）——
主动把索引或数据页读进缓存，避免第一个查询吃冷启动。
第 24 章。

**product quantization**（乘积量化）——
见 PQ。

**projection pushdown**（投影下推）——
只读查询真正需要的列。**几乎总是有收益、没有副作用**，
但要注意"过滤条件引用的列也必须读"。第 10、19.3 节。

**Parquet**（Apache Parquet）——
列式**文件格式**的行业标准，也是 Lance 最常被拿去比的对象。
它面向"整列顺序扫描"优化，因此配合向量检索常见的
"按行号随机取"场景会放大读放大。Lance 换了一套格式来解决这件事。
第 1、3 章。

**protobuf**（Protocol Buffers）——
Google 出的接口描述语言与二进制序列化格式，Lance 的
manifest / 元数据用它（配合 FlatBuffers）。相比 FlatBuffers
它需要一个解析步骤，换来的是更强的 schema 约束。第 7 章。

## R

**RAG**（retrieval-augmented generation，检索增强生成）——
先检索出相关片段、再把它塞进大模型上下文的那套做法。
LanceDB 在这条链路里扮演的是**检索层**。教程里凡是
"生产实践"的场景，默认语境都是 RAG。第 1、25 章。

**row lineage**（行血脉）——
跟踪"这一行是从哪一行衍生出来的"。它是稳定行 id 之外的
一层：稳定 id 保证"同一行永远是同一个 id"，
血脉还记录"它是谁的后代"。物化视图和派生数据的增量刷新
依赖它。第 7.8 节，附录 F。

**RaBitQ**（RaBitQ）——
在二值量化的基础上补一个旋转和一组标量补偿项，
让"汉明距离"更接近真实距离的量化方案。
它是 BQ 精度不够时的下一步。第 16.6 节。

**recall@k**（recall@k / 前 k 召回率）——
ANN 返回的前 k 个结果里，有多少个真的在暴力检索的前 k 里。
它是衡量索引好坏的唯一直接指标。第 12、13 章。

**reconstruction error**（重建误差）——
量化后"把压缩码还原出来的向量"和原向量的距离。
它是量化索引召回率上限的物理来源。第 14、16 章。

**refine_factor**（refine_factor / 精化系数）——
多取 `refine_factor × k` 个候选，用**完整向量**重算距离再截断。
量化索引召回卡住时真正管用的旋钮。第 13、24 章。

**reranker**（重排器 / 重排模型）——
对初步检索结果做二次排序的组件，如 RRF、cross-encoder、ColBERT。
第 20 章，见 RRF、MRR。

**residual vector**（残差向量）——
向量减去它所属簇的质心之后剩下的部分。对残差做量化，
等于让每个簇有自己的坐标系，精度显著更好。
**只在 L2 / cosine 上成立**。第 13.6、14.6 节，见 IVF、PQ。

**RLE**（run-length encoding，游程编码）——
把连续的重复值记成"值 + 重复次数"。对排序后高度重复的列很有效。
第 4 章。

**row address**（行地址）——
真实 Lance 里定位一行的地址 `(fragment_id << 32) | offset`。
它和"逻辑行号"（第几行）是两回事。第 9 章。

**这个"地址"不能当成稳定标识用**，这一点容易读错：它的高位是
`fragment_id`，而**压实会把行搬到新片段里**，于是同一个逻辑行的
行地址在压实前后完全不同。真正跨版本稳定的是
**stable row id**（下面那条，需要显式打开），官方文档的原文是
"row ids are not stable and are relative to the current version"——
说的就是行地址。**两者差在一个开关上，别把它们当同义词。**

**row group**（row group / 行组）——
Parquet 的组织单位（典型 128 MB）。Lance 不用它，
正文里提到它主要是为了说明"为什么 Parquet 的点查代价高"。第 1、3 章。

**row id**（行 ID）——
见 stable row id / row address。

**RRF**（Reciprocal Rank Fusion，倒数排名融合）——
只用名次、不用原始分数的融合方式：每个结果得 `1/(K + rank)` 分，
再相加。**对分数尺度免疫**，所以是混合检索的默认重排器。第 20.3 节，
见 MRR、reranker。

## S

**scalar index**（标量索引）——
打在普通列（数字、字符串、列表）上的索引，服务于过滤而不是相似度。
LanceDB 提供 BTREE / BITMAP / LABEL_LIST，另有 NGRAM 与 ZONEMAP。
第 18 章，见 B-tree。

**schema evolution**（schema 演进）——
在表已经在用的情况下加列、删列、改名、改可空性。
因为有稳定 field id，这些操作大多是纯元数据操作。第 5 章。

**score direction**（分数方向）——
"越大越好还是越小越好"。FTS 的 `_score` 越大越好，
向量检索的 `_distance` 越小越好，重排后的 `_relevance_score`
又视重排器而定。**这是整份教程里最容易搞错的一件事。** 第 17.8、20.2 节。

**selectivity**（选择性）——
过滤条件命中多少比例的行。它决定了 prefilter 该不该用、
延迟物化能省多少。第 11、19 章。

**snapshot isolation**（快照隔离）——
每个读操作看到的是一个固定版本，不受并发写影响。
LanceDB 的读一致性就是它。第 7、8 章。

**SQ**（scalar quantization，标量量化）——
每一维单独量化：把 float32 映射到 8 bit（或 4 bit）整数。
压缩率约 4 倍，精度损失比 PQ 小。第 16.1 节。

**stable row id**（stable row id / 稳定行 ID）——
压实、更新、删除、merge 之后仍然指向同一行的标识。
需要在 `storage_options` 里显式打开
（`new_table_enable_stable_row_ids`）。第 7、9、23 章。

**stemmer**（词干化）——
把词还原到词干（`running` → `run`）。Porter 词干化是规则型算法的祖师爷。
**词干化会让"查询词"和"索引词"同时变形，两边都必须用同一个配置。** 第 17.5 节。

**stop words**（停用词）——
`the`、`a`、`of` 这类信息量极低的词，通常在建索引和查询时都去掉。
第 17.4 节。

**structural encoding**（结构化解开 / 结构化编码）——
把嵌套列摊平成若干平列（`tags` → `tags.offsets` + `tags.item`），
让每一列独立编码、独立读取。第 3.5 节。

**Scannable**（可扫描对象）——
摄入路径上的一个协议：数据源声明"我可以被扫描几次"。
**可重扫**的数据源能被读两遍（第一遍推断 schema，第二遍真写），
一次性的数据源不能——这个区别决定了宽行摄入时那个
与总行数无关的内存上限是怎么来的。附录 H.3。

## T

**tag**（标签）——
版本上的只读书签。它的实际用处是**保护版本不被清理**：
清理只删没有 tag 保护的旧版本。第 7、23 章。

**three-valued logic**（三值逻辑）——
SQL 的 `TRUE` / `FALSE` / `NULL(UNKNOWN)` 三态。
过滤条件求值为 `NULL` 的行**不会**进入结果。
注意真实 LanceDB 底层用 Arrow 的全序比较，
`NaN = NaN` 是 `true` 而不是 `NULL`——和 `mini_lancedb` 的语义相反。
第 11 章。

**time travel**（时间旅行）——
按版本号或时间点读历史数据。第 7 章。

**tokenizer**（分词器）——
把一段文本切成 token 的管线：基础分词器 + 一串过滤器
（小写化、停用词、词干化、ASCII 折叠）。第 17.4 节。

**top-k**（top-k / 前 k 个）——
取距离最小的 k 行。它和"过滤"的顺序是 prefilter / postfilter
那个决策的全部内容。第 12、19 章。

**transaction**（事务）——
一次原子的元数据变更，落成一个事务文件。多个事务竞争时，
只有"能安全重放"的那一类可以共存，判据是冲突矩阵。第 8 章。

## V–Z

**vacuum**（vacuum / 清理）——
PostgreSQL 风格的"回收旧版本占用的空间"。LanceDB 里对应
`optimize(cleanup_older_than=...)`。第 23 章。

**vector index**（向量索引）——
为 ANN 构建的索引结构。LanceDB 提供 IVF 系列、HNSW 系列，
以及量化变体（PQ / SQ / RQ / BQ）。第 12 章。

**version manifest**（版本 manifest）——
见 manifest。

**zone map**（zone map / 区域映射）——
"每个块的最小值和最大值"这类粗粒度统计。
**严格说它不是索引**——它不指向行，只回答"这个块里有没有可能有"。
第 18.5 节。

**Zstd**（Zstandard）——
压缩率和速度折中得较好的通用算法，在 Lance 里代表"高压缩比"那一档，
和 LZ4 构成取舍的两端。第 4 章。

**zero-copy**（零拷贝）——
两边共享同一块内存、不做数据复制。在 Arrow 生态里它由
C Data Interface 保证。**两个要分开的断言**："Arrow 内部零拷贝"
和"LanceDB 到你的 DataFrame 零拷贝"——前者本机确认，
后者因缺依赖本书没有实测结论。验证要**量内存而不是量耗时**。
附录 J.3、J.7。

## 找不到的那些词

有几个常见词在这份教程里**没有出现**，说明一下原因，免得读者以为是漏了：

`similarity`（相似度）——正文一律用"距离"或"分数"，
提"相似度"的地方都会立刻说明它和距离的方向关系。
把两者混用是分数方向错误的源头。

`shard`（分片）——**这条原来是错的，改了。** 原文写的是
"LanceDB 里没有分片概念，最接近的是片段（fragment）"。前半句在
**主路径**上成立：manifest + 片段那套模型里确实没有分片，
`fragment`（片段）和 `shard`（分片）是完全不同的两层，别混。
但**0.40 的 MemWAL 写路径是有分片的**——`LsmWriteSpec.bucket("id", 8)`
就是按某个键做 8 路哈希分片，`unsharded()` 是"不分片"，
而"一次 `merge_insert` 只能打一个分片"是那条路径上的一条硬限制
（附录 G §G.4）。所以准确的写法是：
**分片属于 MemWAL / LSM 写路径，不属于片段模型**——
两者同名而所指不同，正好是这一节要防的那类混淆。

`vector database`（向量数据库）——正文用"LanceDB 这类系统"
或直接叫"向量检索系统"，因为教程的立场是
"它是一个嵌进应用的列存 + 索引库"，而不是一个独立的数据库服务。
