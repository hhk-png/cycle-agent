# 结语：把控制面做成肌肉记忆

## 回到最初的问题

这本教程从一个事故开始：模型指标很好，却无法复现、无法解释、无法安全上线。MLflow 不是这个问题的全部答案，但它把“发生了什么”从人的记忆变成了结构化数据。

MiniMLflow 用约一万八千行代码证明：

- 一个实验追踪系统的核心不是 UI，而是**不可变参数、追加指标、制品指针和一致的状态机**；
- 一个 Registry 的核心不是“上传模型”，而是**不可变版本 + 可变发布指针 + 来源血缘**；
- 一个模型格式的核心不是“能预测”，而是**可加载契约 + 签名 + 依赖 + 安全边界**；
- 一个 GenAI 观测系统的核心不是“日志”，而是**请求级因果 + 采样/脱敏 + 评测闭环**；
- 一个 Prompt Registry 的核心不是“存字符串”，而是**不可变版本 + 可变别名 + 受控渲染**；
- 一个评测数据集的核心不是“一个 JSON 文件”，而是**独立身份 + 内容 digest + schema/profile + 可审计的合并**；
- 一个 Gateway 的核心不是“转发请求”，而是**路由 + 回退 + 配额 + 成本 + 密钥隔离**；
- 一个 Webhook 系统的核心不是“发 POST”，而是**事务性 outbox + 至少一次 + 签名/去重 + SSRF 边界**；
- 一个评分服务的核心不是“能返回 JSON”，而是**输入契约 + 版本固化 + 超时/批处理/灰度 + 可观测性**；
- 一个可运营的模型产品的核心不是“模型分数”，而是**数据契约 + 评测门禁 + 注册审批 + 反馈闭环**；
- 一个 Agent 运营层的核心不是“多跑几个 judge”，而是**会话聚合 + 可重放模拟 + 采样幂等 + 分诊证据 + 统计门禁**；
- 一个可运营的 GenAI 产品的核心不是“接上大模型”，而是**检索可量、答案有据、门禁可回滚、成本可归因**。

## 三条长期有效的原则

### 1. 元数据是产品，不是副产品

命名、标签、指标定义、数据版本、评测集，都是需要版本化和评审的资产。工具只是载体；没有约定，工具会帮你更快地制造混乱。

### 2. 一致性来自边界设计

参数不可变、批量原子、状态单向、路径 containment、搜索参数化、反序列化白名单——这些不是“实现细节”，而是系统可信的基础。把规则放在正确的层（数据库/服务/协议），并用测试证明。

### 3. 区分“能跑”与“可运营”

MiniMLflow 能跑通训练→追踪→注册→服务→追踪的闭环，但它不是生产平台。生产需要：

- 数据库/对象存储/迁移/备份；
- 鉴权/租户/审计/配额；
- 高并发/异步/采样；
- 监控/故障演练/支持；
- 组织流程与 owner。

承认差距，才能做出正确的 build/buy 决策。

## 如果你只带走六件事

1. 用 Experiment 表示问题，用 Run 表示执行；不要把二者混在一起。
2. 参数不可变，指标是历史，标签可修正，artifact 是字节。
3. 模型版本是不可变指针，alias 是发布指针；生产不要直接用 `latest`。
4. 评测必须绑定数据版本、阈值、切片和不确定性；LLM 评测是组合拳，不是单一分数。
5. 平台的价值取决于“故障时能否恢复、换供应商时能否迁移”，而不是功能列表。
6. Agent 的评测单位是会话；模拟器只覆盖你写下的假设，真实反馈不能省。

## 下一步可以做什么

- 把 MiniMLflow 扩展一个真实 flavor（例如纯 JSON 决策树），练习打包/签名/加载。
- 把 SQLite 换成 Postgres，补迁移与并发测试。
- 给 Trace 加采样、异步写入和 OTLP 导出。
- 把搜索 DSL 扩展到 keyset 分页和更多操作符。
- 给 Registry 补 LoggedModel 的 `registrations` 反向关系，按第 34/40 章的清单做一次 3.x 迁移。
- 在隔离环境跑通第 41 章的 Compose 编排与备份恢复演练。
- 把第 42 章的评分协议扩展成动态批处理 + Prometheus 指标 + 优雅下线，并做一次压测。
- 按第 43 章的清单，为你自己的业务写一份数据契约、评测门禁和 90 天上线计划。
- 按第 44 章的练习，把评测集改成受管数据集，并实现 inputs 哈希去重与记录级删除。
- 按第 45 章的练习，为你的线上模型建一个 monitor，绑定基线 digest，并设计一条“漂移 → 排查 → 回滚/重训”的 runbook。
- 按第 46 章的练习，把会话评测、在线采样、issue 分诊与 `assert_improved` 接进你的发布流水线，并做一次模拟器偏差审计。
- 按第 47 章与附录 M，为你的知识助手建 BM25/向量检索基线、黄金集、引用与 grounding 门禁、在线抽样和漂移监控，并做一次 Prompt/索引/模型的分层回滚演练。
- 给 Gateway 加分布式限流（Redis）与真实 provider 适配，补熔断与预算。
- 把 Webhook 改成事务性 outbox + 多副本 claiming + secret 加密，并做一次 DLQ 回放演练。
- 用真实 MLflow 3.x 跑一遍第 39 章的 trace → prompt → evaluate → `@mlflow.test` 链路。
- 为你的团队写一份 90 天试点计划，用真实指标验证 ROI。
- 读真实 MLflow 的源码/文档，对照本教程的分层，找出你关心的实现。

## 最后一句

工具会变，模型会变，云会变。**可复现、可解释、可回滚**这三件事不会变。把它们变成团队的肌肉记忆，比记住任何一个 API 都重要。
