# 前言与导读

这本书不打算再写一份"ClickHouse 语法大全"——那样的资料官方文档已经足够多。它要回答的是另一类问题:**它为什么这么做?这条行为背后的机制是什么?什么条件下它不成立?**

为了把"机制"讲到**能被验证**的程度,本书配了一份**纯 Python 写的简化实现** `mini-clickhouse`:凡是涉及"内部是怎么做的"的地方,你都能在它里面找到对应代码,并且跑起来。它不快,也不打算快——它的作用是把抽象的描述变成一段能读、能改、能跑出结果的代码。

这篇导读只交代三件事:这本书写给谁、该按什么顺序读(四条路径,按需挑一条)、以及阅读时要遵守的两条约定。**建议先把 §00.4 那两条约定看一眼再往下读**——后面所有"未确认"标记的含义,以及 part / 分区 / granule / mark 四个词的严格用法,都建立在那两条约定上。

## 00.1 这本书写给谁

ClickHouse 的入门门槛低得吓人——装一个二进制、建一张 `MergeTree` 表、灌几百万行,`SELECT ... GROUP BY` 就能在一秒内返回。也正因为门槛低,大多数团队在"能跑通"之后就直接上了生产,然后在半年后开始收到两类工单:一类是"查询突然慢了十倍",一类是"磁盘又满了"。

这两类问题几乎都不是 SQL 写错,而是**用关系数据库的直觉去猜 ClickHouse 的行为**。比如:

- 以为 `Decimal(9,2) * Decimal(9,2)` 会升成 `Decimal(18,4)`,结果拿到的是 `Decimal(9,4)`:**标度(小数位数)相加了,宽度却纹丝不动**,这是这本书里最容易让老手也栽跟头的一条类型规则(完整规则与它旁边的溢出陷阱见 `第 03 章 §03.4`);
- 以为加一列 `Nullable` 只是语义变化,结果查询慢了 3 倍;
- 以为 `ORDER BY` 是"最后排序",不知道它同时是排序键、稀疏索引和压缩聚簇;
- 以为 `ALTER TABLE ... UPDATE` 是原地改一行,不知道它是一次异步的 part 重写。

这些直觉之所以会失效,是因为 ClickHouse 的每条行为背后都压着一个存储或执行模型上的理由。后面的章节,基本就是在把这些理由一条条补上。

这本书要解决的,就是这类"直觉与实现不一致"的地方。它写给**有 SQL 基础、想深入 ClickHouse 的工程师**:你写过 `GROUP BY`、知道什么是索引、能看懂执行计划,但你不想再靠试错去理解 ClickHouse。

本书的写作基线是 **ClickHouse 25.3**(2025 年发布的一条 LTS 线)。所有关于默认值、函数名、类型行为的陈述,都以这个版本为准。有一点要先说清:**本书写于 2026 年 10 月,而 25.3 的支持窗口在 2026 年 3 月就已经结束**——它是一条用来核对行为的基准版本,不是"现在该上的生产基线"。至于"哪几条是 LTS、LTS 维护多久",`第 01 章 §01.9` 给了本书的结论、依据和挑选版本的方法,但版本号本身可以背,发布节奏不建议背——真要拿它做升级或采购决策,仍以官方发布说明为准。

## 00.2 四条阅读路径

这本书是按"概念依赖"排序的,不是按"使用频率"排序的。按需求挑一条路径,比从第一页啃到最后更划算。

**路径一:从零上手。** `第 01 → 02 → 04 → 06 → 07 → 12 章`。这条路径刻意跳过存储格式和查询引擎:先用 `MergeTree` 把数据装进去、把 `ORDER BY` 和聚合写对,就能交付一张可用的分析表。`第 05 章` 等遇到"为什么这个查询不裁剪数据"时再回头读。

**路径二:从 MySQL / PostgreSQL 迁过来。** 主线是 `第 37 章`(附录 E:MySQL / PostgreSQL 迁移 playbook)——它把"先改哪些心态、类型怎么换成等价的、哪些子句语义不同、哪些同名函数不等价"按迁移的顺序串成一条可执行的流程,并把每一步指向展开它的章节。跟着它走会顺路读到 `第 02 章 §02.8`(五个心态转变)、`第 03 章`(类型系统完全不是一回事)、`第 15 章`(JOIN 的代价模型是反的)、`第 18 章`(更新是异步重写)、`第 28 章`(反模式清单)。你原有的 SQL 技能八成能直接迁移,剩下两成恰恰是让迁移失败的那部分。

**路径三:要设计一套数仓 / 表结构。** `第 05 → 06 → 12 → 13 → 14 章`。先看清排序键在磁盘上意味着什么(`第 05 章`),再看怎么选排序键与分区键(`第 06 章`),然后看聚合状态怎么被持久化(`第 12 章`)、物化视图怎么把预计算挂到写入路径上(`第 13 章`),最后由 `第 14 章` 把这几件事收拢成一套可执行的建模方法论。这条路径的产出不是"会用 ClickHouse",而是"敢为别人定表结构"。

**路径四:只想搞懂引擎内部。** `第 05 → 10 → 11 → 20 → 31 章`。这条路径从存储格式往上走:先看数据在磁盘上长什么样(part、granule、mark),再看它怎么被读进 pipeline,最后看稀疏索引怎么把 I/O 砍掉。`第 31 章` 用一份可运行的 Python 实现把这些机制重写了一遍——读代码比读文档更直接。

## 00.3 结构地图

全书 39 章,分成十个组。

**基础(第 00–03 章)。** 前言、认识 ClickHouse、快速上手、数据类型体系。这一组的目的是把词汇表建立起来——后面所有章节都在用这里定义的词。

**存储(第 04–06 章,以及第 20 章)。** 表引擎总览与选择、MergeTree 存储结构、表结构与 DDL、压缩与编码。其中 `第 05 章` 是全书的地基:part 是什么、`ORDER BY` 为什么同时是索引、granule 和 mark 怎么把一次全表扫变成几十次随机读。没读懂这一章,后面很多"为什么"都无从谈起。

**查询(第 07–12 章,以及第 15–17 章)。** SQL 语法全貌、数据写入与导入、DDL/ALTER 与运维语句、查询执行引擎、索引与数据跳过、聚合与 `GROUP BY`、JOIN 全解、排序与窗口函数、函数库全景。最厚的一组,也是日常使用最频繁的一组。

**预计算与建模(第 13–14 章)。** 物化视图与增量聚合、数据建模与表设计。为什么把这两章从"查询"里单拎出来:前面九章回答的是"ClickHouse 怎么做事",这两章回答的是"**你该让它做什么**"。物化视图是把聚合状态持久化到写入路径上的唯一手段,数据建模则是把排序键、分区键、类型、预计算四个决定一次做完的方法论。它们不引入新机制,只把已有机制拧成设计决定——所以放在这里最合适。

**数据生命周期(第 18–19 章)。** 分区、合并、Mutation 与 TTL,以及数据格式与序列化——数据进来之后会发生什么,都在这里。

**分布式(第 21–23 章)。** 字典、复制与 Keeper、分片与分布式查询。单机能力到这里封顶,再往上就要面对多副本一致性和跨分片聚合。

**运维与性能(第 24–29 章)。** 查询优化与执行计划、并发控制与配额、权限与安全、可观测性与 system 表、性能调优与反模式、生产部署与运维。

**集成与实现(第 30–32 章)。** 集成与生态、从零实现简化版 ClickHouse、现状与未来方向。`第 31 章` 配套的 `mini-clickhouse` 是本书的"实物教具"。

附录一共六份,落在第 33–38 章(附录 A–F)。它们不引入新概念,只把前面 33 章压成可随时查阅、可照着执行的形式;按用途分成最后两个组。

**参考(第 33–36 章)。** 四份工具书:附录 A 是 SQL 与函数速查,附录 B 是 mini-clickhouse 工程手册,附录 C 是术语表,附录 D 是按症状组织的 FAQ 与排错。查默认值、查术语、查报错,都在这一组。

**迁移与实战(第 37–38 章)。** 附录 E 是 **MySQL / PostgreSQL 迁移 playbook**——把"从别的数据库搬过来"按顺序做成一条可执行的流程;附录 F 是从零搭一个可观测性平台的端到端实战,**全书唯一的结语**也在那里。要动手落地,从这一组开始。

## 00.4 阅读约定

**事实标注规则。** 本书以 ClickHouse 25.3 为准。凡是写进正文的具体主张——默认值、参数名、函数名、报错行为——作者都核对过 25.3 的文档或源码。凡是核对不了的,会在正文里直接写"**未确认**",并说明为什么不确定(通常是因为:该行为在版本之间变过、该参数是内部实现细节、或者手边没有对应版本的实例可以验证)。**"未确认"不是"不重要",而是"不要拿它当事实用"**——如果你在生产里依赖某条标了"未确认"的行为,请自己在目标版本上验一遍。

这条规则是有代价的:有些地方看起来"本该顺便提一句"的细节被省略了。宁可少写一条,也不写错一条。

**自查入口。** 当你怀疑某个默认值"这本书是不是写错了",官方有一张 `system.settings_changes` 表可以直接查:它有三列 `type` / `version` / `changes`,其中 `changes` 是 `Array(Tuple(name, previous_value, new_value, reason, compatibility_mode))`,逐条记录"哪个设置在哪个版本、从什么值改成了什么值、改动理由是什么"。查一条设置改过几次默认值:

```sql
SELECT version, change.4 AS reason,
       change.1 AS name, change.2 AS previous, change.3 AS new_value
FROM system.settings_changes
ARRAY JOIN changes AS change
WHERE name = 'use_query_condition_cache'
ORDER BY version;
```

但它有两条**局限**,这也正好解释了为什么本书有些默认值只能标"未确认":它**只覆盖 `compatibility` 机制引入之后的改动**(更早的历史它不记),而且**不覆盖服务端配置**(`config.xml` / `config.d/` 里那些,不在这张表里)。所以一条默认值在这张表里查不到,并不等于它从没变过——也可能只是落在了它的盲区。查不到时,回到目标版本的官方文档,或直接在实例上 `SELECT` 出来。

**代码示例怎么跑。** 书中的 SQL 都能在真实的 ClickHouse 25.3 上执行。同时,本书配套了一份纯 Python 的简化实现 `mini-clickhouse`,它在关键机制上刻意照抄了真实 ClickHouse 的设计(part 目录布局、稀疏索引、向量化算子、`DataType` / `IColumn` 两段式类型系统)。凡是能在这个实现上跑出结果的例子,都会标注;跑不了的会说明原因。`第 31 章` 讲它的设计,`第 34 章` 是它的工程手册。**这份实现是教具,不是替代品**——它没有实现真实 ClickHouse 的性能特性,也没有实现全部函数。

**术语统一。** 有一组词在中文社区被混用得很厉害,本书内部保持严格区分:

- **part(数据片段)**:一次写入在磁盘上落成的一个不可变目录。合并的输入输出都是 part。中文正文里写"part",不写"块"。
- **分区(partition)**:由建表时的 `PARTITION BY` 表达式决定的逻辑划分。一个分区包含一个或多个 part。注意 part ≠ 分区:一个分区可以有几十个 part。
- **granule(粒度)**:索引的最小读取单位,由 `index_granularity` 决定(默认 8192 行)。读取器不会读"一行",而是读"一个 granule"。
- **mark(标记)**:`.mrk2` 文件里的一条偏移记录,指出某个 granule 在某个列文件中的起始位置(25.3 的宽 part 每列一个 `<列>.mrk2`;`.mrk` 不是"不存在",它是自适应粒度之前那一代的老名字,今天仍在个别引擎里出现,比如 `StripeLog` 的 `index.mrk`)。稀疏索引查到 granule 编号后,靠 mark 定位到字节。

这四个词的关系可以用一句话串起来:**分区由 part 组成,part 由 granule 组成,granule 的物理位置由 mark 记录**。细节在 `第 05 章`。

## 00.5 这本书不覆盖什么

说清楚边界,比列目录更有用。

**不教 ClickHouse Cloud 的计费与商业功能。** 本书讲的是开源版本(OSS)的行为。Cloud 上的共享存储、弹性伸缩、计量计费是另一套话题;只有在讲到功能差异时才顺带提一句。

**不逐行解读 C++ 源码。** 涉及内部机制时会指出对应的源文件(比如类型工厂在 `src/DataTypes/DataTypeFactory.cpp`),但不会逐行翻译实现。想看逐行的,去看 `第 31 章` 的 Python 实现——它把同样的机制写得短到能一口气读完。

**不做 DBA 认证辅导。** 没有模拟题,没有考点清单。`第 29 章` 讲的部署与运维是"能让你把一个集群安全跑起来"的程度,不是"能通过某张证书考试"的程度。

**不承诺覆盖全部函数。** ClickHouse 的函数数以千计,且每个版本都在增加。`第 17 章` 讲函数的分类、组合子和命名规律,`第 33 章` 给速查表。学会"怎么查一个函数存在不存在、它的返回类型是什么",比背下来更实用。

## 00.6 如果只读三章

如果这本书你只会读完三章,选 `第 05 章`、`第 12 章`、`第 28 章`。它们分别回答"它为什么快"(排序键兼作稀疏索引与压缩聚簇、granule 把随机读的量级降到可控)、"我该怎么问"(聚合的分块计算、`GROUP BY` 哈希表、近似函数的取舍)和"我哪里做错了"(反模式清单与定位方法)。合起来覆盖了"为什么快、怎么问、错在哪"三件事,剩下三十六章都是在补细节。

## 00.7 小结

这本书假定你有 SQL 基础,目标是让你理解 ClickHouse 的**行为模型**,而不只是记住语法。全书以 25.3 为准,核对不了的会被明确标成"未确认";示例既能跑在真实的 ClickHouse 上,也能跑在配套的 `mini-clickhouse` 上——后者是理解内部机制的教具,见 `第 31 章`。

写作上给自己拴了两条绳子:能用散文讲清楚的不堆名词,能核实的才下结论。后面每一章都按这个标准写。

从 `第 01 章` 开始,我们先把"ClickHouse 是什么"这件事说清楚——尤其是那些写在宣传语里、但很少有人真正解释过的词:列式、MPP、向量化、无事务。
