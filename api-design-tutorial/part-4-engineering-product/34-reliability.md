# 第 34 章 可靠性与容错：超时、重试、熔断与背压

## 34.1 分布式系统默认会失败

在单机程序中，函数调用要么返回，要么抛异常。在分布式系统中，失败有更多形态：

- 请求丢失；
- 响应丢失；
- 超时但实际成功；
- 重复投递；
- 部分成功；
- 慢节点；
- 网络分区；
- 依赖降级；
- 时钟漂移；
- 资源耗尽；
- 证书过期；
- DNS 故障。

可靠性设计不是“避免失败”，而是“失败时仍然可预测、可恢复”。

### 失败的类型

| 类型 | 特征 | 应对 |
|---|---|---|
| 瞬时 | 短暂抖动 | 重试 |
| 间歇 | 时好时坏 | 重试 + 熔断 |
| 持续 | 依赖宕机 | 熔断 + 降级 |
| 部分 | 某些请求失败 | 隔离 + 降级 |
| 静默 | 返回错误数据 | 校验 + 对账 |

### 最危险的失败

不是“请求失败”，而是：

- 超时但实际成功；
- 返回旧数据；
- 部分成功；
- 静默错误；
- 重复副作用。

这些失败不会被简单重试解决，需要幂等、对账和审计。

## 34.2 超时

没有超时的调用会无限占用资源：

- 线程；
- 连接；
- 内存；
- 请求配额；
- 用户耐心。

### 超时分层

```text
客户端超时 10s
网关超时 8s
服务超时 5s
数据库超时 2s
下游调用 1s
```

外层超时应大于内层，否则外层会先放弃，内层仍在工作。

### 超时预算

一次请求多个依赖时，总预算要分配：

```text
总 1s
├── 认证 50ms
├── 数据库 300ms
├── 服务 A 300ms
└── 服务 B 250ms
剩余 100ms 缓冲
```

### 超时后的状态

超时不代表失败。可能：

- 请求未到达；
- 已执行但响应丢失；
- 仍在执行。

因此写操作需要幂等键和状态查询。

### 超时的设置

- 基于 P99 或 SLO；
- 考虑依赖的延迟；
- 留出重试时间；
- 不要设得太短（误杀）；
- 不要设得太长（资源占用）；
- 动态调整。

## 34.3 重试

重试能提高成功率，也能放大故障。

### 何时重试

- 网络错误；
- 超时（幂等前提下）；
- 429；
- 502/503/504；
- 连接重置。

### 何时不重试

- 400/401/403/404；
- 业务规则拒绝；
- 非幂等写操作没有幂等键；
- 重试预算耗尽。

### 退避

```text
delay = min(base * 2^attempt, max) * random(0.5, 1.5)
```

抖动防止惊群。

### 重试预算

```text
总请求中最多 10% 用于重试
```

避免故障时重试流量压垮系统。

### 重试层

不要在客户端、网关、服务网格、服务内部同时重试。选择一层，或用预算协调。

### 重试风暴

```text
依赖变慢 → 所有客户端超时 → 全部重试 → 依赖更慢 → ...
```

防护：

- 指数退避 + 抖动；
- 重试预算；
- 熔断；
- 服务端 `Retry-After`；
- 队列缓冲。

## 34.4 熔断

当依赖持续失败时，快速失败，避免资源耗尽：

```text
CLOSED → 失败率超阈值 → OPEN → 冷却时间 → HALF_OPEN
  ↑                                        ↓
  └──────────── 成功 ←────────────────────┘
```

### 参数

- 失败率阈值（如 50%）；
- 最小请求数；
- 冷却时间；
- 半开探测请求数；
- 按依赖/端点隔离。

### 注意

- 熔断不是重试的替代；
- 半开时只放少量请求；
- 熔断状态要可观测；
- 避免全局熔断导致级联失败；
- 熔断后要有降级。

### 熔断的粒度

- 按依赖；
- 按端点；
- 按租户；
- 按实例。

粒度过粗会误伤，过细会增加复杂度。

## 34.5 舱壁（Bulkhead）

隔离资源池：

- 每个依赖独立连接池；
- 每个租户独立配额；
- 关键/非关键流量分离；
- 线程池隔离；
- 队列隔离；
- 数据库连接隔离。

一个依赖故障不应耗尽所有资源。

### 舱壁的实现

- 连接池上限；
- 信号量；
- 线程池；
- 队列上限；
- 租户配额。

## 34.6 背压

当消费者处理不过来时，必须让生产者减速：

- 队列上限；
- 拒绝新请求；
- 降低拉取速率；
- 流控窗口；
- 丢弃低优先级；
- 返回 429/503。

没有背压的系统会在队列中堆积，最终 OOM。

### 背压的信号

- 队列长度；
- 处理延迟；
- 消费者 lag；
- 内存使用；
- GC。

### 背压的策略

- 阻塞生产者；
- 拒绝；
- 降级；
- 丢弃；
- 扩容。

## 34.7 负载削减

过载时主动拒绝低优先级请求：

```text
优先级 0：支付、登录 → 保留
优先级 1：查询 → 缓存/降级
优先级 2：报表、导出 → 拒绝
```

需要：

- 请求分类；
- 配额；
- 降级策略；
- 用户沟通；
- 监控。

### 请求分类

- 端点；
- 租户；
- 用户；
- 客户端版本；
- 付费等级；
- 操作类型。

## 34.8 优雅降级

- 推荐服务失败 → 返回空推荐；
- 评论服务失败 → 隐藏评论区；
- 库存服务失败 → 显示“暂时无法确认”；
- 支付失败 → 保留订单，允许重试；
- 搜索失败 → 返回缓存结果；
- 地图失败 → 显示地址文本。

降级要明确：

- 哪些功能可降级；
- 降级后的用户体验；
- 数据一致性；
- 恢复策略；
- 告警；
- 降级开关。

## 34.9 多区域与灾难恢复

- 多活；
- 主备；
- 区域故障转移；
- 数据复制；
- RPO/RTO；
- DNS/流量切换；
- 配置同步；
- 演练。

### RPO/RTO

- RPO：可接受的数据丢失量；
- RTO：可接受的恢复时间。

```text
RPO = 0    → 同步复制
RPO < 1min → 异步复制
RTO < 5min → 自动化切换
```

### 多区域模式

| 模式 | RPO | RTO | 成本 | 复杂度 |
|---|---|---|---|---|
| 单区域 | 高 | 高 | 低 | 低 |
| 主备 | 中 | 中 | 中 | 中 |
| 双活 | 低 | 低 | 高 | 高 |
| 多活 | 最低 | 最低 | 最高 | 最高 |

### 灾难恢复演练

- 定期切换；
- 验证数据；
- 验证 DNS；
- 验证配置；
- 验证监控；
- 记录问题；
- 改进。

没有演练的灾难恢复计划等于没有。

## 34.10 混沌工程

主动注入故障：

- 杀死实例；
- 延迟；
- 丢包；
- 依赖错误；
- 磁盘满；
- 时钟偏移；
- DNS 故障。

验证：

- 监控；
- 告警；
- 降级；
- 恢复；
- 数据一致性。

从非生产环境开始，逐步扩大。

### 混沌实验的步骤

```text
1. 定义稳态
2. 注入故障
3. 观察
4. 恢复
5. 复盘
```

## 34.11 错误预算

```text
SLO 99.95% → 每月 21.6 分钟错误预算
```

- 预算充足：加快发布；
- 预算耗尽：冻结发布，投入稳定性；
- 预算用于权衡，不是惩罚。

### 错误预算的策略

- 预算 > 50%：正常发布；
- 预算 20%～50%：谨慎发布；
- 预算 < 20%：只发修复；
- 预算耗尽：冻结功能发布。

## 34.12 代码示例：重试与熔断

```python
import random
import time

def retry(fn, attempts=3, base=0.2, max_delay=2.0):
    for i in range(attempts):
        try:
            return fn()
        except RetryableError:
            if i == attempts - 1:
                raise
            delay = min(base * (2 ** i), max_delay)
            time.sleep(delay * random.uniform(0.5, 1.5))
```

熔断伪代码（省略滑动窗口与多实例状态同步，仅说明状态迁移）：

```python
import time

class CircuitBreaker:
    def __init__(self, failure_threshold=0.5, min_requests=20, cooldown=30):
        self.failure_threshold = failure_threshold  # 0..1
        self.min_requests = min_requests
        self.cooldown = cooldown
        self.state = "CLOSED"
        self.failures = 0
        self.requests = 0
        self.opened_at = None

    def call(self, fn):
        if self.state == "OPEN":
            if time.time() - self.opened_at < self.cooldown:
                raise CircuitOpen()
            self.state = "HALF_OPEN"

        try:
            result = fn()
            self._on_success()
            return result
        except Exception:
            self._on_failure()
            raise

    def _on_success(self):
        if self.state == "HALF_OPEN":
            self.state = "CLOSED"
            self.failures = 0
            self.requests = 0
        else:
            self.requests += 1

    def _on_failure(self):
        if self.state == "HALF_OPEN":
            self.state = "OPEN"
            self.opened_at = time.time()
            return

        self.failures += 1
        self.requests += 1
        if (
            self.requests >= self.min_requests
            and self.failures / self.requests >= self.failure_threshold
        ):
            self.state = "OPEN"
            self.opened_at = time.time()
```

生产实现还需要：滑动窗口、半开状态只放行少量探针、按错误类型区分、多实例共享状态、指标与告警。

## 34.13 反模式

- 无超时；
- 无限重试；
- 多层重试叠加；
- 重试非幂等操作；
- 熔断阈值拍脑袋；
- 没有背压；
- 降级没有监控；
- 多区域但没演练；
- 错误预算不落地；
- 把“高可用”当作口号；
- 只做冗余不做故障转移；
- 没有对账。

## 34.14 本章小结

- 分布式系统默认会失败，可靠性设计要覆盖失败形态。
- 超时要分层、有预算。
- 重试要有限制、退避、抖动、幂等前提。
- 熔断、舱壁、背压、负载削减防止级联故障。
- 优雅降级要明确可降级范围。
- 多区域与灾难恢复需要 RPO/RTO 和演练。
- 错误预算连接可靠性与发布决策。
- 跨区域故障转移、fencing、脑裂与一致性承诺，见[附录 Z](../appendices/z-distributed-consistency-multi-region.md)。
- 用形式化与故障注入验证不变量，见[附录 AA](../appendices/aa-formal-contracts-model-checking.md)。
- 重试风暴、幂等失效、缓存串租户、Webhook 重放等真实失败链，见[附录 U](../appendices/u-incident-postmortems.md)。
