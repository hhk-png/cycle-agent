# 附录 A：API 设计检查清单

> 使用方式：设计评审前逐项检查；“不适用”要写明理由，而不是跳过。

## A.1 目标与消费者

- [ ] 每个 API 有明确的产品/技术负责人。
- [ ] 主要消费者已识别（前端、移动端、伙伴、内部服务、Agent）。
- [ ] 每个消费者的关键任务已写成故事/用例。
- [ ] 已知消费者的协议、网络、语言、发布节奏限制。
- [ ] 有成功指标（激活、延迟、错误率、用量、收入）。
- [ ] 有明确的“不做什么”。

## A.2 领域与资源

- [ ] 资源来自领域概念，不是数据库表。
- [ ] 实体、值对象、聚合边界清晰。
- [ ] 关键不变量已列出。
- [ ] 每个核心资源有状态机。
- [ ] 跨聚合一致性策略明确（事务、Saga、Outbox）。
- [ ] 有界上下文边界清晰。
- [ ] 读写模型是否需要分离已评估。
- [ ] 领域术语表存在。

## A.3 契约

- [ ] 契约使用 OpenAPI / Proto / SDL / AsyncAPI 等机器可读格式。
- [ ] 契约覆盖成功、校验失败、认证失败、权限失败、冲突、限流、依赖失败。
- [ ] 每个 operation 有稳定 `operationId`。
- [ ] 请求/响应有示例。
- [ ] 字段有类型、格式、必填性、约束、描述。
- [ ] 枚举有未知值处理策略。
- [ ] 金额、时间、空值语义明确。
- [ ] 契约有版本，并纳入代码仓库。
- [ ] 契约与实现有 CI 漂移检查。
- [ ] 有破坏性变更检测。

## A.4 URL 与命名

- [ ] 资源使用复数名词。
- [ ] 大小写/分隔符全 API 一致。
- [ ] 层级不超过 2～3 层。
- [ ] 复杂动作用子资源或冒号语法。
- [ ] ID 不透明、稳定、不可枚举。
- [ ] 不在 URL 中放敏感信息。
- [ ] 查询参数语法统一。
- [ ] 未知参数处理策略明确。
- [ ] 规范 URL 与别名策略明确。

## A.5 请求与响应

- [ ] 媒体类型正确。
- [ ] 单资源与列表结构一致。
- [ ] 列表使用统一分页信封。
- [ ] 错误使用标准格式。
- [ ] 金额/时间/枚举/空值有明确类型。
- [ ] 多态使用判别字段。
- [ ] 支持必要的字段选择/展开，并有上限。
- [ ] 返回 `Request-Id`。
- [ ] 大响应有分页/流式/压缩策略。
- [ ] 不泄露内部实现或敏感数据。

## A.6 列表与查询

- [ ] 分页方式与数据量匹配（offset/cursor/keyset）。
- [ ] 游标不透明、防篡改、可过期、绑定过滤条件。
- [ ] 排序有唯一键，保证稳定。
- [ ] 过滤/排序字段有白名单。
- [ ] 有 `limit` 上限。
- [ ] 深分页有保护。
- [ ] 总数返回策略明确。
- [ ] 搜索与过滤区分。
- [ ] 导出异步化。
- [ ] 慢查询有监控。

## A.7 写操作

- [ ] 方法的安全/幂等语义正确。
- [ ] 创建/支付/退款等关键操作支持幂等键。
- [ ] 幂等键作用域、指纹、TTL、并发处理明确。
- [ ] 乐观并发使用 ETag/版本。
- [ ] 冲突返回 409/412 并说明。
- [ ] 跨服务一致性策略明确。
- [ ] 部分成功语义明确。
- [ ] 失败补偿与对账存在。
- [ ] 不依赖“恰好一次”投递。

## A.8 异步与实时

- [ ] 长任务使用 202 + 操作资源。
- [ ] 操作状态机清晰。
- [ ] 轮询有退避/`Retry-After`。
- [ ] Webhook 有签名、重试、去重、死信、重放。
- [ ] 实时连接有认证、心跳、重连、恢复、背压。
- [ ] 事件有 ID、类型、版本、时间、顺序。
- [ ] 消费者幂等。
- [ ] 断线恢复与全量对账策略明确。

## A.9 认证与授权

- [ ] 认证机制与调用方类型匹配。
- [ ] 令牌短期、可轮换、可吊销。
- [ ] 校验签名、`iss`、`aud`、`exp`、算法。
- [ ] 公共客户端使用 PKCE。
- [ ] 对象级授权逐资源检查。
- [ ] 字段级授权/输出过滤。
- [ ] 租户 ID 来自可信令牌。
- [ ] 管理面与数据面分离。
- [ ] 高风险操作二次确认。
- [ ] 授权审计完整。

## A.10 安全

- [ ] 输入白名单与类型/长度/范围校验。
- [ ] 防 mass assignment。
- [ ] 防注入（SQL/NoSQL/命令/模板）。
- [ ] 防 SSRF（URL 白名单、私网限制、重定向）。
- [ ] 防路径穿越。
- [ ] 请求体/响应体大小限制。
- [ ] 限流/配额/并发限制。
- [ ] 密钥管理、轮换、泄露响应。
- [ ] 依赖扫描/SBOM/签名。
- [ ] 错误信息不泄露敏感信息。
- [ ] 安全头/CORS/TLS 配置正确。
- [ ] 威胁模型已做。

## A.11 缓存

- [ ] 可缓存资源有 `Cache-Control`。
- [ ] 私有数据不进入共享缓存。
- [ ] 使用 ETag/Last-Modified 与条件请求。
- [ ] `Vary` 正确。
- [ ] 缓存键包含租户/用户维度。
- [ ] 失效策略明确。
- [ ] 穿透/击穿/雪崩有防护。
- [ ] 缓存故障有回源/降级预案。

## A.12 限流与配额

- [ ] 限流维度覆盖 IP/Key/用户/租户/端点/成本。
- [ ] 阈值可配置。
- [ ] 429 带 `Retry-After` 和标准错误。
- [ ] 配额与账单一致。
- [ ] 失败/重试的计量规则明确。
- [ ] 过载时有分级降级。
- [ ] 限流存储故障有预案。
- [ ] 监控限流命中与误伤。

## A.13 性能与可靠性

- [ ] 有 P50/P95/P99 目标。
- [ ] 有吞吐/容量目标。
- [ ] 有超时预算。
- [ ] 重试有限制、退避、抖动、幂等前提。
- [ ] 有熔断/舱壁/背压。
- [ ] 有降级策略。
- [ ] 有负载测试。
- [ ] 有故障注入/混沌演练。
- [ ] 有 RPO/RTO 与灾备演练。
- [ ] 有过载保护。

## A.14 可观测性

- [ ] 结构化日志。
- [ ] 请求 ID / Trace ID 贯穿。
- [ ] 指标覆盖 RED/USE。
- [ ] 延迟使用直方图/分位数。
- [ ] 有 SLO/SLI/错误预算。
- [ ] 告警可操作、有 runbook。
- [ ] 敏感数据脱敏。
- [ ] 有 API 使用分析（端点/版本/租户/客户端）。
- [ ] 有租户维度视图。

## A.15 文档与 DX

- [ ] 快速开始可在 10 分钟内完成首次调用。
- [ ] 参考文档覆盖所有端点/错误。
- [ ] 有教程、指南、概念文档。
- [ ] 示例可运行、与 SDK 版本匹配。
- [ ] 沙箱可用、可重置。
- [ ] 有变更日志。
- [ ] 有状态页/支持入口。
- [ ] 错误信息链接到文档。
- [ ] 文档可搜索、可深链。
- [ ] 多语言/无障碍按需。

## A.16 版本与生命周期

- [ ] 版本策略明确。
- [ ] 破坏性变更定义明确。
- [ ] 扩展—收缩流程可用。
- [ ] 弃用提前通知。
- [ ] 运行时弃用信号（头/文档/SDK）。
- [ ] 旧版本使用量可观测。
- [ ] 迁移工具/指南存在。
- [ ] 最终下线/清理计划。
- [ ] 回滚计划。

## A.17 治理

- [ ] API 在目录中登记。
- [ ] 所有权/on-call 明确。
- [ ] 通过设计评审。
- [ ] 通过安全评审。
- [ ] 契约 lint 通过。
- [ ] 契约测试通过。
- [ ] 文档完整。
- [ ] SLO 已定义。
- [ ] 成本已估算。
- [ ] 例外有记录。

## A.18 商业

- [ ] 目标客户/细分明确。
- [ ] 价值主张可量化。
- [ ] 定价/计量单位合理。
- [ ] 免费层有成本控制。
- [ ] 单位经济为正或路径清晰。
- [ ] 账单可预测。
- [ ] 竞争壁垒清晰。
- [ ] 合规/合同风险已评估。
- [ ] 生态/伙伴策略清晰。

## A.19 AI / Agent

- [ ] 能力描述机器可读（名称、用途、何时不用）。
- [ ] 工具参数 schema 严格，禁止额外字段。
- [ ] 错误可恢复，包含下一步。
- [ ] 高风险操作要求确认。
- [ ] 工具权限最小化。
- [ ] 幂等键与查询工具可用。
- [ ] 结果大小受限，支持分页/摘要。
- [ ] 防提示注入、混淆代理、工具投毒。
- [ ] 模型版本可追踪。
- [ ] 轨迹可审计、可回放。
- [ ] 有评估集与人工兜底。
- [ ] 成本/预算可见。

## A.20 移动端与离线

- [ ] 是否需要离线优先已评估。
- [ ] 本地数据库 schema 有版本。
- [ ] 客户端 ID 生成与冲突处理明确。
- [ ] 变更队列幂等。
- [ ] 同步游标不透明、可过期。
- [ ] 删除有墓碑。
- [ ] 冲突解决策略明确。
- [ ] 全量快照与重置可用。
- [ ] 后台同步可中断/恢复。
- [ ] 推送只做通知，不传大量数据。
- [ ] 本地数据加密，退出清理。
- [ ] 离线场景有测试。

## A.21 合同与采购

- [ ] SLA 的 SLI 可测量。
- [ ] 赔偿有上限与流程。
- [ ] DPA 数据流可实现。
- [ ] 数据驻留可落地。
- [ ] 子处理者变更通知。
- [ ] 安全控制有证据。
- [ ] 支持等级与值班匹配。
- [ ] 导出/删除接口存在。
- [ ] 终止与迁移条款可操作。
- [ ] 计费可对账。

## A.22 国际化与可访问性

- [ ] 语言标签使用 BCP 47，并有明确回退链。
- [ ] 错误码稳定，`title`/`detail` 可本地化，调用方不解析文本。
- [ ] 时间以 RFC 3339 UTC 传输，另带时区/本地日期语义。
- [ ] 金额用最小单位整数 + ISO 4217 币种（如 `{"amount":12900,"currency":"CNY"}`），不使用浮点数或金额字符串。
- [ ] 字符串长度按 grapheme 还是字节有明确约定。
- [ ] 排序规则按 locale 配置，不假设 Unicode 码点顺序。
- [ ] 复数、性别、语序使用 ICU MessageFormat，不拼接翻译片段。
- [ ] `Vary: Accept-Language` 或 locale 入 URL，缓存不串语言。
- [ ] 搜索分词、同义词、拼写容错按语言配置。
- [ ] 文档与错误页满足 WCAG 2.2 AA。
- [ ] 媒体 API 暴露字幕、音轨、alt text 等可访问性字段。
- [ ] 有伪本地化、RTL、长文本、CJK、emoji 测试。

## A.23 批量、导入与迁移

- [ ] 批量语义明确：全有或全无，还是逐条结果。
- [ ] 每条结果有稳定索引、状态、资源 ID 或错误对象。
- [ ] 有单批条数、字节、并发与超时限制。
- [ ] 幂等键覆盖批次与条目。
- [ ] 大批量走异步任务，有状态、进度与取消。
- [ ] 导入支持试运行、逐行错误、断点续传与 schema 版本。
- [ ] 导出有一致性快照、稳定排序、正确转义与签名 URL。
- [ ] 迁移有双写/回填/对账/灰度/回滚。
- [ ] 计费单位、重试计费与失败计费写进契约。
- [ ] 更完整的模式见[附录 S](s-bulk-import-export.md)。

## A.24 实现与合规

- [ ] 契约元素都有实现位置与测试。
- [ ] 请求管线顺序固定，请求体、超时、查询成本有上限。
- [ ] 对象级授权在副作用前完成。
- [ ] 幂等记录与业务写入在同一原子边界。
- [ ] API 模型与 ORM 实体分离。
- [ ] 优雅关闭、发布策略与数据库迁移经过演练。
- [ ] 监管义务已映射到 API 能力、负责人、证据与复核日期。
- [ ] DSAR、删除、同意、审计、驻留能力可验证。
- [ ] 事件响应有分级、时限、模板与演练。
- [ ] 实现架构见[附录 R](r-implementation-architecture.md)，合规映射见[附录 T](t-compliance-engineering.md)。

## A.25 Agent 商务与监管

- [ ] Agent 支付有预算、商户白名单、金额上限与过期时间。
- [ ] 支付证明一次性、可验证、可审计。
- [ ] 高风险操作有人类确认与撤销路径。
- [ ] 退款、争议、拒付责任在合同中明确。
- [ ] 监管矩阵已识别（隐私、AI、支付、行业）。
- [ ] 训练使用、数据保留、输出归属有合同条款。
- [ ] 模型变更与弃用有通知与迁移安排。
- [ ] 事故通知、审计协助与证据提供可执行。

## A.26 计量、计费与收入

- [ ] 每个计量项有稳定名称、单位与客户可见的计费语义。
- [ ] 成功/失败、重试、取消、缓存、沙箱是否计费写进契约。
- [ ] 计量事件有唯一 ID、幂等键、租户、环境、事件时间。
- [ ] 原始事件不可变，更正事件可追溯。
- [ ] 去重键带租户，去重窗口覆盖最大补录周期。
- [ ] 价格表有版本与生效区间；阶梯是分段累进还是整量统一明确。
- [ ] 套餐包含量、超额、承诺消费、true-up、proration 规则明确。
- [ ] 折扣、credits、币种、汇率、舍入、税可配置且可重放。
- [ ] 发票终态不可变；更正走贷项通知单或补充发票。
- [ ] 用量、发票、预算、credits、争议 API 完整，租户隔离强制。
- [ ] 对账链能从原始事件走到总账，差异有负责人与证据。
- [ ] 更完整的设计见[附录 V](v-metering-billing.md)。

## A.27 产品管理与增长

- [ ] 目标客户与任务用 JTBD 写清楚，覆盖开发者、技术决策者、经济决策者。
- [ ] MVP 能端到端完成一个真实任务，而不是只提供一个端点。
- [ ] 路线图同时包含新能力、采用体验、基础债务。
- [ ] Beta/GA 有进入/退出标准与迁移承诺。
- [ ] 团队亲自走通一次新客户接入，记录摩擦日志。
- [ ] TTFC 与 TTFV 有定义、度量与负责人。
- [ ] 快速开始 10 分钟内可完成，首错有修复建议。
- [ ] 沙箱覆盖成功、失败、限流、异步，且不产生真实费用。
- [ ] DevRel 覆盖内容、社区、反馈、生态四类工作。
- [ ] 指标有定义、口径、数据源、负责人；实验有护栏。
- [ ] 更完整的方法见[附录 W](w-api-product-management.md)。

## A.28 遗留现代化与迁移

- [ ] 端点、消费者、用量、关键性、数据、依赖已盘点。
- [ ] 消费者有负责人、联系人与迁移风险。
- [ ] 实体、标识、状态、金额、时间、错误、分页、空值、枚举、权限有映射。
- [ ] 防腐层隔离旧模型，旧字段不直接透传新契约。
- [ ] 门面/适配器/Strangler 方案已选择，避免大爆炸重写。
- [ ] 数据所有权与写入权威明确，双写/CDC/回填有对账。
- [ ] 灰度切流按租户/端点/比例推进，回滚演练完成。
- [ ] 数量、金额、关系、状态、抽样对账通过。
- [ ] 旧系统冻结新功能，退役清单完成。
- [ ] 更完整的实战方法见[附录 X](x-legacy-modernization.md)。

## A.29 成本工程与 FinOps

- [ ] 成本分为基础设施、第三方、运营与失败成本。
- [ ] 固定、可变、阶梯与共享成本分别建模。
- [ ] 单位成本按请求/token/GB/租户/端点可计算。
- [ ] 共享成本有公开、可复现、可申诉的分摊规则。
- [ ] 成本标签低基数、无敏感数据，能归因到租户/团队/端点。
- [ ] 财务账单与工程用量能对账。
- [ ] 租户/团队/端点能看到成本与趋势。
- [ ] 预算有告警、软/硬上限与提额流程。
- [ ] 有月度预测、异常检测与复盘。
- [ ] 免费层、重试、日志、孤儿资源有专门成本监控。
- [ ] 优化项有 owner、影响、验证与回滚，且不牺牲可靠性/合规。
- [ ] 碳成本有口径（范围、区域、PUE、碳强度），并与成本一起优化。
- [ ] 更完整的方法见[附录 Y](y-cost-engineering-finops.md)。

## A.30 分布式一致性与多区域

- [ ] 一致性承诺写清了范围、操作、时间上界与例外。
- [ ] 区分单对象一致性、跨对象一致性与会话保证（读己之写、单调读、单调写、写跟随读）。
- [ ] 写操作有幂等键，故障转移期间重试不会重复副作用。
- [ ] 每个关键键有唯一写权威，冲突在业务层裁决而不是静默 LWW。
- [ ] 全局 ID 不依赖自增，不暴露写入位置。
- [ ] 跨区事件用 Outbox，消费者幂等，顺序按聚合键。
- [ ] 读路径给出陈旧度上界，并有复制延迟/陈旧读的测量。
- [ ] 故障转移有租约/fencing token，能阻止旧主继续写。
- [ ] 切换期间返回明确的 503/降级语义，不返回伪 200。
- [ ] RPO/RTO 与复制方式、成本、合同一致。
- [ ] 数据驻留与故障转移区域已评审，不违规跨区。
- [ ] 有一致性测试、故障演练与对账。
- [ ] 更完整的设计见[附录 Z](z-distributed-consistency-multi-region.md)。

## A.31 形式化与模型检验

- [ ] 每个核心资源有状态机表，包含守卫、副作用与终态。
- [ ] 每个写操作有前置/后置条件与错误码映射。
- [ ] 关键不变量写成可判定命题，并在测试中断言。
- [ ] 并发路径有原子性保证（条件更新/锁/唯一约束）。
- [ ] 金额、库存、权限、幂等有性质测试。
- [ ] 有状态测试覆盖操作序列，而不只是单请求。
- [ ] 分布式锁/计数器/账本考虑线性一致性检查。
- [ ] 新协议在实现前有 TLA+/Alloy 或其他模型，并记录假设。
- [ ] 形式化规格与代码同仓库、有评审、有失效日期。
- [ ] 明确“验证了什么、没验证什么”，不把模型检验当证明。
- [ ] 更完整的工具箱见[附录 AA](aa-formal-contracts-model-checking.md)。

## A.32 数据契约与指标语义

- [ ] 每个数据集有 schema、语义、owner、新鲜度、质量规则与生命周期。
- [ ] 契约机器可读，存放在生产者仓库并发布到目录。
- [ ] 字段有单位、精度、时区、枚举与空值语义。
- [ ] Schema 演进遵循 full 兼容，破坏性变更走 v2 + 回填 + 对账。
- [ ] 指标有唯一定义、版本、口径 owner 与 data-through。
- [ ] BI 与 API 从同一语义层取数，并有数字对拍。
- [ ] 特征有 point-in-time 正确性、在线/离线一致性与版本。
- [ ] 数据产品可发现、可寻址、可信、可互操作。
- [ ] 导出有一致性快照、权限过滤、校验和与审计。
- [ ] CDC 有墓碑、顺序、幂等与 schema 兼容。
- [ ] 数据质量覆盖新鲜度、完整性、准确性、一致性与唯一性。
- [ ] 数据事故有影响评估、回填、通知与更正流程。
- [ ] 更完整的设计见[附录 AB](ab-data-contracts-metrics.md)。

## A.33 Serverless、边缘与 WASM

- [ ] 同步接口的最坏执行时间小于平台超时，并留缓冲。
- [ ] 请求/响应体上限与平台限制匹配，大对象走对象存储。
- [ ] 异步接口有任务 ID、状态查询、幂等、DLQ 与重放。
- [ ] 冷启动计入 SLO，并分别监控冷启动比例与初始化耗时。
- [ ] 不在进程内保存正确性依赖的状态。
- [ ] 数据库连接有代理/上限，避免连接爆炸。
- [ ] 定时任务明确时区、重叠、补跑与幂等。
- [ ] 边缘缓存键包含租户/权限/语言，回源失败有降级。
- [ ] 边缘不承担强一致写与全局精确计数。
- [ ] WASM 插件有版本化 ABI、能力授权、资源限制与签名。
- [ ] 多租户有并发/队列隔离，监控噪声邻居。
- [ ] 可观测性覆盖冷启动、限流、队列年龄、DLQ 与单次成本。
- [ ] 评估供应商锁定与迁移成本，关键路径有可移植回退。
- [ ] 更完整的设计见[附录 AC](ac-serverless-edge-wasm.md)。

## A.34 密码学与后量子

- [ ] 只启用 TLS 1.2+，优先 TLS 1.3；弱套件已禁用，证书自动轮换。
- [ ] 网关到源站仍然加密；内部信任头不可被外部伪造。
- [ ] 需要端到端完整性的场景使用消息签名，且签方法、目标 URI、关键头部、body digest 与时间戳。
- [ ] 签名基于原始字节或标准规范化结果，并验证 `keyid`、算法允许列表、时间窗与重放。
- [ ] Webhook 使用 Standard Webhooks/RFC 9421 或等价标准，支持多密钥轮换。
- [ ] JWT 校验覆盖 `alg`、`kid`、`iss`、`aud`、`exp`、`nbf`、`typ`；拒绝 `none` 与外部 JWKS。
- [ ] 高价值 API 使用 DPoP/mTLS 绑定，而不是纯 Bearer；令牌短生命周期、可吊销。
- [ ] 有密钥清单：用途、算法、位置、owner、轮换周期、紧急泄露 runbook。
- [ ] 有 CBOM/算法盘点，覆盖 TLS、证书、JWT、Webhook、代码签名与 SDK。
- [ ] 后量子迁移按数据寿命与合规要求排序，至少试点混合密钥交换。
- [ ] 契约支持算法协商、密钥 ID、双签名窗口与可操作的“不支持算法”错误。
- [ ] 更完整的工程细节见[附录 AD](ad-cryptography-pqc.md)。

## A.35 序列化与 Schema 演进

- [ ] 每个字段有类型、单位、精度、时区与空值语义；金额用字符串十进制或最小货币单位 + 币种。
- [ ] 大整数用字符串，避免 IEEE 754 精度丢失；时间用 RFC 3339，日期与时刻分开。
- [ ] 缺失、`null`、默认值三态在契约中写清。
- [ ] 有 schema 与版本，存放在仓库或 Registry；CI 做兼容性 diff。
- [ ] Protobuf 字段编号不复用，删除字段 `reserved`；Avro 新字段有默认值，重命名用 `aliases`。
- [ ] 事件/数据管道使用 full/transitive 兼容；破坏性变更走新版本 + 迁移。
- [ ] 签名与幂等指纹使用原始字节或标准规范化（JCS/确定性 CBOR），不依赖 Protobuf 序列化字节。
- [ ] 压缩考虑 BREACH、压缩炸弹、已压缩内容与 `Vary`。
- [ ] 流式响应有帧边界、错误表达、背压与取消。
- [ ] 大对象走预签名 URL/Range/分片，不塞进 JSON。
- [ ] 有真实基准测试，不靠直觉选格式。
- [ ] 更完整的取舍见[附录 AE](ae-serialization-schema-evolution.md)。

## A.36 数据库即 API / BaaS / 自动生成接口

- [ ] 明确公开表面是表、视图还是函数，并写入文档。
- [ ] 公开字段有稳定命名、类型、空值语义；内部字段不因 `select=*` 泄露。
- [ ] 默认拒绝；匿名角色无法读取任何未授权数据。
- [ ] RLS/Security Rules 覆盖所有暴露的表/集合，并有跨租户越权测试。
- [ ] 视图使用 `security_invoker`（或等价机制），不绕过底层 RLS。
- [ ] `SECURITY DEFINER` 函数设置安全 `search_path`，并限制执行权限。
- [ ] service_role/admin key 只在服务端，有 secret 管理、轮换与泄露响应。
- [ ] 实时订阅按租户/资源授权，权限变更可撤销。
- [ ] 文件桶与下载 URL 有访问控制、类型校验与过期。
- [ ] 列表接口有索引与游标分页，避免深 offset 与精确计数拖垮。
- [ ] 有语句超时、最大行数、关联深度与响应体上限。
- [ ] schema 迁移按 Expand–Contract 管理，有 CI 破坏性变更检测。
- [ ] 有从自动生成迁移到稳定契约层/服务化的路线图。
- [ ] 更完整的设计见[附录 AF](af-database-as-api-baas.md)。

## A.37 隐私增强技术（PET）

- [ ] 有威胁模型：数据主体、敏感属性、攻击者能力与可接受泄露上界。
- [ ] 隐私预算像配额一样按数据集/租户/时间窗记账，耗尽有明确错误。
- [ ] 差分隐私的相邻数据集、敏感度、噪声机制与组合有文档与测试。
- [ ] 聚合接口有最小群体阈值、补抑制，`min`/`max`/零值不泄露个体。
- [ ] 查询审计能识别差分/相减攻击，缓存命中不绕过预算。
- [ ] 导出、批量、BI 与在线查询使用同一套隐私策略。
- [ ] MPC/HE/TEE/FL 的威胁模型、信任边界、性能与精度经过实测。
- [ ] TEE 有远程认证、measurement 校验、nonce 防重放与策略版本。
- [ ] 联邦学习有安全聚合、DP、客户端采样与投毒防护。
- [ ] 合成数据经过成员推断、最近邻与下游效用评估。
- [ ] 洁净室有查询审批、输出审查、最小群体与 DP 预算。
- [ ] 隐私错误码可区分、可操作；日志/trace 不含原始敏感值。
- [ ] 更完整的工程细节见[附录 AG](ag-privacy-enhancing-tech.md)。

## A.38 基础语义：时间、金钱、数量、标识与语言

- [ ] 每个时间字段明确是时刻、本地日期时间、日期、当日时间、时长还是区间。
- [ ] 时刻使用 RFC 3339 且带偏移或 `Z`；日期使用 `YYYY-MM-DD`，不用午夜时刻冒充。
- [ ] 时区使用 IANA 名称；DST 缺口/重叠有解析策略与错误码。
- [ ] 业务日、节假日日历、截止时间、账期锚点、按比例计算规则写清。
- [ ] 时间精度、截断/舍入、闰秒策略、时钟偏差与事件排序键写清。
- [ ] 金额由数值 + ISO 4217 币种组成，不使用浮点数。
- [ ] 最小货币单位按币种 exponent，不硬编码两位小数。
- [ ] 舍入模式、舍入步骤、分摊规则与“明细之和 = 总额”不变式写清。
- [ ] 多币种、汇率来源/时间、换汇手续费、结算币种、税与历史复现写清。
- [ ] 数量字段带单位；单位代码使用 SI/UCUM 或明确的自定义体系。
- [ ] 百分比、百分点、基点不混用；坐标声明 CRS 与轴顺序。
- [ ] ID 不透明、稳定、不可枚举、不复用、URL 安全；外部 ID 与合并/拆分有映射。
- [ ] 语言标签使用 BCP 47，回退链明确；语言、地区、时区、币种分开。
- [ ] Unicode 归一化、字符串长度口径、排序规则、搜索分词写清。
- [ ] 基础语义错误有稳定错误码、字段路径与可操作提示。
- [ ] 性质测试覆盖时间、金额、单位、标识与文本的不变量。
- [ ] 更完整的规则与示例见[附录 AH](ah-primitive-semantics.md)。

## A.39 行业垂直与受监管 API

- [ ] 明确行业标准、版本、认证要求与监管义务，并映射到 API 能力与证据。
- [ ] 标准契约与内部领域模型之间有防腐层，不让标准 quirks 渗透全系统。
- [ ] 身份、同意/授权、审计、保留、删除、驻留、导出证据可验证。
- [ ] 长流程有状态机、异步任务、查询、回调、补偿与对账。
- [ ] 多版本共存、迁移、弃用与合作伙伴通知有计划。
- [ ] 沙箱、模拟器、一致性测试、认证路径与测试数据就绪。
- [ ] 医疗：FHIR 资源/搜索/事务/Profile/术语/SMART/同意/批量导出。
- [ ] 开放银行：同意资源、SCA、FAPI、支付状态机、幂等、回调、对账、错误码。
- [ ] 电信：产品-服务-资源三层、TMF Open API、订单编排、fallout、计费对账。
- [ ] 工业/汽车：设备身份、状态/命令分离、离线、命令确认、OTA、功能安全。
- [ ] 网络/设备 API 的隐私、反欺诈、限速、审计与安全联锁完整。
- [ ] 更完整的行业设计见[附录 AI](ai-vertical-apis.md)。

## A.40 沙箱、Mock 与测试数据

- [ ] 沙箱与生产同源，或明确标注模拟保真度等级。
- [ ] 测试密钥有前缀、独立作用域、环境绑定、轮换与吊销。
- [ ] 测试密钥无法调用生产，生产密钥无法调用沙箱。
- [ ] 每个测试运行有独立租户/命名空间，跨租户读取返回 404。
- [ ] 数据可播种、可重置、可自动过期，清理覆盖数据库/缓存/对象存储/搜索/队列/Webhook。
- [ ] Mock 响应通过 schema 校验，并与沙箱用同一组契约测试对拍。
- [ ] 可稳定注入校验失败、权限不足、限流、超时、部分成功与异步延迟。
- [ ] 测试时钟可控制，覆盖时区、DST、月末与过期场景。
- [ ] Webhook 可注册、验签、重放、注入失败、查看投递日志。
- [ ] 测试数据使用合成数据，工厂确定、隔离、可清理。
- [ ] 沙箱出站流量有 SSRF 防护，Webhook 重放有验签与去重。
- [ ] 沙箱有配额、滥用检测、独立 SLO 与漂移检测。
- [ ] 更完整的方法见[附录 AJ](aj-sandbox-mock-test-data.md)。

## A.41 特性开关、实验与渐进发布

- [ ] 区分部署、发布、实验与弃用，不用一次全量部署完成所有事。
- [ ] 每个开关有类型、负责人、创建原因与目标清理日期。
- [ ] Release/experiment flag 默认关闭；kill switch 默认保持可用。
- [ ] 分桶稳定、可解释，记录盐值与分桶单元。
- [ ] 开关影响响应时，缓存键包含变体，不跨租户泄露。
- [ ] Kill switch 有独立通道，生效时间可测量并定期演练。
- [ ] 渐进发布有 SLI、观察窗口、自动/手动回滚条件；金丝雀包含真实租户。
- [ ] 实验预先注册主要指标、护栏指标与分析方法，曝光日志记录首次曝光。
- [ ] 涉及计费/定价的实验经过财务、法务评审。
- [ ] 开关变更进入审计日志，高风险操作双人审批。
- [ ] 两条分支都有测试，包括默认值与配置服务故障。
- [ ] 过期开关有扫描与自动清理；清理旧路径前完成调用方盘点与弃用。
- [ ] 更完整的方法见[附录 AK](ak-feature-flags-experiments-progressive-delivery.md)。

## A.42 基础设施即 API / 控制平面

- [ ] 声明式资源有稳定身份、spec、status、生命周期与所有权。
- [ ] Terraform：Read 反映远端，创建/更新后 plan 为空，支持导入与 state 升级。
- [ ] Terraform：可变/不可变字段区分正确，默认值与服务端一致，密钥不落明文 state。
- [ ] CRD：schema/CEL/准入三层校验分工合理，默认值在 CRD schema 中。
- [ ] CRD：多版本有 conversion，round-trip 测试通过，只有一个 storage version。
- [ ] CRD：status 有 observedGeneration 与稳定 conditions；finalizer 幂等、有超时。
- [ ] 控制器水平触发、幂等、有界重试、可观测，RBAC 最小权限。
- [ ] GitOps：Git 是期望状态唯一来源，密钥加密，镜像用 digest。
- [ ] 漂移有检测、告警与“报告/自动修复/人工批准”策略。
- [ ] 字段所有权明确，避免 GitOps/Terraform/手动/控制器互相覆盖。
- [ ] 删除保护、孤儿资源对账与供应链校验完整。
