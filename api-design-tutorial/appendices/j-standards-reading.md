## J.11 如何持续学习

1. 读规范原文，而不是只读二手总结。
2. 读优秀 API 的文档：Stripe、GitHub、Twilio、Google。
3. 读事故复盘，理解失败模式。
4. 参与开源/标准社区。
5. 在自己的 API 上做小实验。
6. 建立设计决策记录。
7. 定期做对抗性评审。
8. 关注成本与商业结果，而不只是技术。

## J.13 计量、产品与现代化的工具与阅读

以下按类别列出，不构成厂商推荐；选型时仍需核对许可证、部署方式、数据驻留与退出成本。

### 计量与计费

- **OpenMeter**：开源用量计量与计费事件模型，适合理解 meter/feature/entitlement 的抽象。
- **Lago**：开源计费与发票引擎，可参考价格表、账单与 credits 的数据模型。
- **Metronome / m3ter / Stripe Billing**：商业计费平台，适合对照 usage-based billing、commitment、proration 的产品化能力。
- **Apache Kafka / ClickHouse / dbt**：常见的计量事件采集、聚合与分析组合。
- **ASC 606 / IFRS 15**：收入确认的原则性文本；工程沟通时至少理解履约义务、交易价格分摊与可变对价。

### API 产品与 DevRel

- **OpenAPI / AsyncAPI**：契约与文档的单一真相。
- **Redocly / Speakeasy / ReadMe / Postman**：文档、SDK 生成、门户与 API 测试的不同环节；不要指望一个工具覆盖全部。
- **Orbit / Common Room**：开发者关系与社区信号分析（品类参考，非必选）。
- **GitHub / Discord / Discourse**：社区与反馈渠道的常见组合。

### 遗留现代化

- **Martin Fowler, Strangler Fig Application**：逐步替换遗留系统的经典模式。
- **Eric Evans, Domain-Driven Design**：防腐层、上下文映射与领域模型。
- **Apache Camel / Debezium / Kong / Envoy**：协议适配、CDC、网关与流量治理的常见工具。
- **Pact**：消费者驱动契约测试；迁移期可用于确认新旧契约一致。
- **Michael Nygard, Release It!**：熔断、舱壁、超时与发布风险。

### 成本与 FinOps

- **FinOps Foundation**：云成本归因、showback/chargeback 与单位成本的实践框架。
- **OpenCost / Kubecost**：Kubernetes 成本可见性工具（品类参考）。

## J.14 一致性、形式化、数据契约与边缘运行时

### 一致性与形式化

- **Leslie Lamport, Specifying Systems**：TLA+ 的经典教材；重点读状态机、时序性质与精化。
- **TLA+ / TLC / Apalache**：规格、显式模型检验与符号化检查；适合协议与并发状态机。
- **Alloy / Alloy Analyzer**：关系建模与有限范围反例搜索；适合权限、租户隔离、引用完整性。
- **Jepsen / Knossos / Porcupine / Elle**：并发历史与隔离级别检查；适合锁、计数器、账本、数据库选型。
- **Hypothesis / QuickCheck / fast-check**：性质测试与有状态测试；适合金额、库存、分页、序列化。
- **Martin Kleppmann, Designing Data-Intensive Applications**：一致性、复制、分区与分布式系统权衡的通用背景。

### 数据契约与指标

- **Bitol Data Contract Spec / Open Data Contract Standard（ODCS）**：数据契约的 YAML 描述尝试；字段名不同，核心要素一致。
- **dbt contracts / dbt Semantic Layer**：分析工程侧的模型契约与指标语义层。
- **Avro / Protobuf / JSON Schema / Schema Registry**：schema 描述与兼容性管理。
- **OpenLineage / OpenMetadata / DataHub**：血缘、目录与数据产品元数据。
- **Apache Iceberg / Delta Lake / Hudi**：数据湖表格式；关注快照、时间旅行与 schema 演进。
- **Feast / Tecton（品类参考）**：特征存储与在线/离线一致性；重点理解 point-in-time join。
- **Cube / AtScale / MetricFlow（品类参考）**：语义层与指标 API 的不同实现路径。
- **OpenTelemetry**：数据质量与管道可观测性可复用其指标/Trace 模型。

### Serverless、边缘与 WASM

- **AWS Lambda / Cloudflare Workers / Deno Deploy / Fastly Compute**：不同运行时约束的代表；读文档时重点看超时、内存、请求体、并发与流式能力。
- **Knative / OpenFaaS / Fission**：Kubernetes 上的 FaaS 形态，适合对照冷启动与扩缩容。
- **WASI / WebAssembly Component Model**：WASM 的系统接口与组件化方向。
- **Proxy-Wasm / Extism / Wasmtime**：网关插件、插件框架与运行时；重点看 ABI 版本、能力授权与资源限制。
- **Serverless Framework / SST / AWS SAM**：部署与本地模拟工具；注意模拟环境与生产运行的差异。

## J.15 密码学、序列化与后量子

### 消息签名与规范化

- **RFC 9421, HTTP Message Signatures**：对 HTTP 方法、目标 URI、头部与 body digest 签名的标准框架；重点读组件选择、`created`/`expires`、`keyid` 与验证顺序。
- **RFC 9530, Digest Fields**：`Content-Digest` 等字段，替代旧的 `Digest` 头；与消息签名配合绑定 body。
- **Standard Webhooks**：Webhook 签名与投递头的公共约定；适合大多数 SaaS 回调。
- **RFC 8785, JSON Canonicalization Scheme（JCS）**：JSON 签名/哈希的规范化规则。
- **RFC 8949, CBOR** 与 **RFC 8610, CDDL**：二进制数据格式与 schema 描述；确定性编码适合签名。
- **RFC 9449, DPoP**：把令牌绑定到客户端密钥的发送方约束机制。
- **RFC 8705, mTLS 绑定令牌**：证书绑定的访问令牌。

### 后量子

- **FIPS 203（ML-KEM）**：基于格的密钥封装。
- **FIPS 204（ML-DSA）**：基于格的数字签名。
- **FIPS 205（SLH-DSA）**：基于哈希的数字签名。
- **NIST IR 8547**：向 PQC 迁移的规划草案（弃用/禁止传统公钥算法的时间表）。
- **NSA CNSA 2.0**：国家安全系统的 PQC 套件与时间线。
- **UK NCSC PQC 迁移指南**：规划、优先迁移与完成时间线的参考。
- **CycloneDX CBOM**：密码学物料清单的开放格式。

### 序列化与 Schema

- **RFC 8259, JSON**；**JSON Schema 2020-12**。
- **Protocol Buffers Language Guide / Editions**：字段编号、存在性、未知字段与演进规则。
- **Apache Avro Specification**：schema resolution、aliases、默认值与兼容性。
- **Apache Arrow / Parquet**：列式内存与存储格式；适合分析，不适合在线点查。
- **RFC 8878（zstd）/ RFC 7932（Brotli）/ RFC 1952（gzip）**：压缩格式与取舍。
- **NDJSON / RFC 7464（JSON Text Sequences）**：流式 JSON 的两种帧格式。

### 工具

- **oasdiff / openapi-diff**：破坏性变更检测。
- **Schemathesis / Hypothesis / fast-check**：性质测试与基于 schema 的测试。
- **Pact / Spring Cloud Contract**：消费者驱动契约测试。
- **Prism / Mockoon / WireMock**：mock 与沙箱。
- **k6 / wrk / Vegeta**：负载测试。

## J.17 隐私增强技术

### 差分隐私

- **Dwork & Roth, The Algorithmic Foundations of Differential Privacy**：定义、机制、组合与误差界。
- **NIST SP 800-226, Guidelines for Evaluating Differential Privacy Guarantees**：评估隐私保证的实践参考（发布状态以 NIST 官方为准）。
- **Abadi et al., Deep Learning with Differential Privacy（DP-SGD）**：裁剪、加噪与隐私会计。
- **OpenDP / Google differential-privacy / Diffprivlib / TensorFlow Privacy**：工程库与预算工具。
- **Rényi DP / zCDP**：更紧的组合分析。

### 匿名化与聚合

- **Sweeney, k-anonymity**；**Machanavajjhala et al., l-diversity**；**Li et al., t-closeness**：经典模型与局限。
- **小格抑制、补抑制、查询审计**：统计披露控制的传统方法。
- **差分隐私**：可组合、可量化的替代或补充。

### 密码学与可信执行

- **MPC**：秘密分享、混淆电路、OT、PSI；工程库如 MP-SPDZ。
- **同态加密**：Paillier、BFV/BGV、CKKS、TFHE；库如 Microsoft SEAL、OpenFHE、TFHE-rs、HElib。
- **TEE**：Intel SGX/TDX、AMD SEV-SNP、ARM CCA、AWS Nitro Enclaves；远程认证与机密容器。
- **联邦学习与安全聚合**：FedAvg、Bonawitz et al. 的安全聚合、DP-FL、鲁棒聚合；框架如 Flower、TensorFlow Federated、OpenFL。

### 元数据与匿名凭证

- **RFC 9458, Oblivious HTTP**：中继 + 网关的两层隐私转发。
- **RFC 9180, HPKE**：OHTTP 的加密构件。
- **Privacy Pass**：架构、签发与 HTTP 认证方案（RFC 9576/9577/9578）。
- **RFC 9474, RSA Blind Signatures**；BBS 匿名凭证：不可关联的授权与选择性披露。
- **UK ICO / ENISA / OECD 的 PET 指南**：治理、评估与部署经验。

### 数据共享

- **Delta Sharing**：开放共享协议、recipient、短期凭证与撤销。
- **云数据洁净室**：AWS Clean Rooms、Snowflake、Google Ads Data Hub 等；重点看输出控制与审计。
- **DP 合成数据**：生成模型 + DP-SGD；评估成员推断、最近邻与下游效用。

## J.19 基础语义标准

### 时间与日历

- **RFC 3339, Date and Time on the Internet: Timestamps**：API 时刻字段的互联网 profile。
- **ISO 8601-1:2019 / ISO 8601-2:2019**：日期、时间、时长、区间与扩展表示。
- **IANA Time Zone Database**：全球时区、历史偏移与 DST 规则；关注版本与更新流程。
- **RFC 5545, iCalendar**：RRULE、EXDATE、RDATE 与日历语义。
- **Unicode CLDR**：locale 的日期、数字、货币、排序与复数规则。
- **RFC 9110, HTTP Semantics**：`Date`、`Last-Modified`、`If-Modified-Since`、`Retry-After`、`Expires` 等日期语义。
- **RFC 8594, Sunset HTTP Header**：资源下线时间。

### 金钱、数量与单位

- **ISO 4217**：货币代码与小数位（exponent）。
- **ISO 80000 / SI Brochure**：国际单位制与量纲。
- **UCUM（Unified Code for Units of Measure）**：机器可读单位代码，医疗与实验室强烈建议使用。
- **ISO 8601 durations**：`P1M`、`PT30M` 等日历/精确时长表示。
- **EPSG Geodetic Parameter Dataset**：坐标参考系统，如 EPSG:4326、EPSG:3857。
- **RFC 7946, GeoJSON**：地理要素的 JSON 表示与坐标顺序。

### 标识、文本与规范化

- **RFC 9562, UUIDs（含 UUIDv7）**：时间有序 UUID。
- **ULID Specification**：Crockford Base32、时间有序的标识。
- **Snowflake / KSUID**：分布式有序 ID 的常见方案；关注时钟回拨与时间泄漏。
- **BCP 47（RFC 5646）/ RFC 4647**：语言标签与语言匹配。
- **Unicode UAX #15（Normalization）**：NFC/NFD/NFKC/NFKD。
- **Unicode UAX #29（Text Segmentation）**：字形簇、词、句边界。
- **Unicode UAX #9（Bidirectional Algorithm）**：RTL 与双向文本。
- **UTS #10（Collation）/ UTS #35（LDML）**：排序与 locale 数据。
- **RFC 8785, JCS**：JSON 规范化，用于签名与指纹。
- **ISO 13616（IBAN）、Luhn、GS1 GTIN**：行业标识与校验位。

## J.20 行业垂直标准

### 医疗健康

- **HL7 FHIR R4（4.0.1）/ R5（5.0.0）**：资源、搜索、Bundle、Profile、术语、订阅、批量导出。
- **SMART App Launch / SMART on FHIR**：医疗应用的 OAuth 2.0 授权与启动上下文。
- **HL7 v2 / CDA**：遗留消息与文档标准；迁移期需要映射。
- **DICOM**：医学影像与通信。
- **LOINC / SNOMED CT / ICD-10/11 / RxNorm / UCUM**：术语与单位系统；注意版本、许可与地区差异。
- **FHIR Bulk Data Access（$export）**：NDJSON 批量导出。
- **FHIR Validator / Inferno / Touchstone**：一致性测试与认证工具（品类参考）。

### 开放银行与金融

- **OBIE Read/Write API（英国）**：账户信息、支付发起、同意、错误模型。
- **Berlin Group NextGenPSD2（欧盟）**：同意、支付、账户信息、状态与错误码。
- **FDX（美国）**：金融数据共享 API 与安全要求。
- **Consumer Data Right（澳大利亚）/ Open Finance Brasil / Account Aggregator（印度）**：区域开放金融体系。
- **FAPI 2.0（OpenID Foundation）**：PAR、JARM、mTLS/DPoP、请求签名与金融级安全配置。
- **PSD2 / PSD3 / PSR**：欧盟支付服务与开放银行监管；以 EUR-Lex 官方文本为准。
- **ISO 20022**：金融报文与端到端标识。
- **PCI DSS 4.0.1**：支付卡数据安全。

### 电信与网络

- **TM Forum SID（Information Framework）**：产品、服务、资源、客户、用量、账单信息模型。
- **TM Forum Open API**：TMF620/622/637/640/641/639/635/678/629/666/681/688/696/720 等。
- **CAMARA**：Quality on Demand、Device Location、Number Verification、SIM Swap、Carrier Billing、Edge Cloud 等网络 API。
- **GSMA Open Gateway**：CAMARA 的商业与运营商协作框架。
- **3GPP**：5G 核心网、计费、网络暴露与策略标准。
- **ETSI / ITU-T**：电信规范与编号体系。

### 工业、汽车与设备

- **OPC UA（IEC 62541）**：信息模型、服务、会话、安全、PubSub、报警与历史访问。
- **MQTT 5.0 / MQTT Sparkplug B**：工业发布/订阅、出生/死亡、序列号、别名与状态。
- **COVESA VSS（Vehicle Signal Specification）**：车辆信号树、类型与单位。
- **SOME/IP / AUTOSAR**：汽车面向服务通信与服务发现。
- **UDS（ISO 14229）**：汽车诊断服务。
- **ISO 26262 / IEC 61508**：功能安全。
- **ISO/SAE 21434 / IEC 62443**：汽车与工业网络安全。
- **UNECE R155 / R156**：车辆网络安全与软件更新法规。
- **OpenSCD / OPC UA Compliance Test Tool**：一致性与认证工具（品类参考）。

## J.21 沙箱、Mock 与测试数据工具

### 契约 Mock 与服务虚拟化

- **Prism（Stoplight）**：从 OpenAPI 生成静态 Mock，校验请求，支持 `Prefer: example` 与错误响应。
- **Mockoon**：桌面/CLI Mock 服务，适合前端并行开发与本地联调。
- **WireMock**：状态化 Mock、请求匹配、故障注入与录制回放；适合集成测试。
- **Microcks**：面向 OpenAPI/AsyncAPI/gRPC 的契约 Mock 与测试；支持事件与回调。
- **Hoverfly**：服务虚拟化与流量捕获/回放。
- **MSW（Mock Service Worker）**：在浏览器/Node 中拦截请求，适合前端与 SDK 测试。
- **GraphQL Tools `addMocksToSchema`**：按 schema 生成类型正确的 Mock。

### 测试数据与时间

- **Faker 类库**：合成姓名、地址、电话等；必须固定随机种子，避免真实 PII。
- **Hypothesis / fast-check / jqwik**：性质测试与数据生成。
- **Testcontainers**：用容器提供真实数据库、消息队列与依赖。
- **Stripe Test Clocks / 测试卡**：订阅、试用、账期与支付失败的参考实现。
- **时间冻结库**：如 Freezegun、Sinon fake timers、ClockMock；注意数据库与第三方是否走同一时钟。

### 沙箱与测试环境

- **Kubernetes Namespace/Ephemeral Environments**：按测试运行创建临时环境。
- **OpenAPI/AsyncAPI 校验器**：确保 Mock 与夹具符合契约。
- **出站代理/SSRF 防护**：Webhook 沙箱的必备控制。
- **合成数据与脱敏工具**：保留格式的合成器、差分隐私合成数据。
