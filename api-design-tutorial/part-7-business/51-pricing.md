# 第 51 章 API 定价与包装

## 51.1 定价不是算术，是产品设计

API 定价决定：

- 谁会用；
- 怎么用；
- 用多少；
- 何时升级；
- 是否留存；
- 是否盈利。

一个糟糕的定价会让：

- 小客户不敢试；
- 大客户账单不可预测；
- 销售被迫打折；
- 工程团队被计量逻辑拖累；
- 毛利被隐藏成本吃掉。

### 定价的三个目标

1. **捕获价值**：价格与客户获得的价值相关；
2. **覆盖成本**：毛利可持续；
3. **驱动行为**：鼓励采用、扩展、留存。

三者经常冲突。定价是权衡，不是公式。

## 51.2 定价的基本模型

### 1. 成本加成

```text
价格 = 单位成本 × (1 + 加成率)
```

优点：简单、保底。缺点：忽略客户价值、容易被替代、无法反映稀缺性。

适合：基础设施、商品化能力。

### 2. 价值定价

```text
价格 = 客户获得价值的一部分
```

例如：支付按交易额比例、风控按避免的损失、推荐按增量收入。

优点：与客户价值对齐。缺点：价值难量化、销售复杂。

### 3. 用量定价

```text
价格 = 单价 × 用量
```

优点：低门槛、随增长。缺点：收入不可预测、账单惊讶。

### 4. 订阅/套餐

```text
月费 = 固定额度 + 功能
```

优点：可预测、易销售。缺点：额度设计难、可能低估或高估。

### 5. 分层用量

```text
0 - 10万       $0.01/次
10万 - 100万   $0.008/次
100万以上      $0.005/次
```

“分层”必须先说清楚是哪一种：

**分段累进（graduated）**：每一段按该段单价计费。用量 150 万：

```text
10 万 × $0.01      = $1,000
90 万 × $0.008     = $7,200
50 万 × $0.005     = $2,500
合计                = $10,700
```

**整量统一（volume）**：全部用量按最高档单价计费。用量 150 万：

```text
150 万 × $0.005 = $7,500
```

两者相差 43%，客户会非常敏感。价格页、合同、账单明细、用量 API 必须使用同一种口径，并展示计算过程。

优点：鼓励增长、规模折扣。缺点：边界复杂、收入优化难。

### 6. 平台费 + 分成

```text
固定平台费 + 交易额百分比
```

适合市场/平台。

### 7. credits

```text
购买 credits → 不同操作消耗不同 credits
```

适合多能力、多成本的产品。缺点：换算复杂、透明度低。

### 8. 企业合同

- 年费；
- 承诺用量；
- 超额单价；
- SLA；
- 专属支持；
- 合规。

### 模型对比

| 模型 | 可预测 | 与价值对齐 | 低门槛 | 复杂度 |
|---|---|---|---|---|
| 成本加成 | 高 | 低 | 中 | 低 |
| 价值定价 | 中 | 高 | 中 | 高 |
| 用量 | 低 | 中 | 高 | 中 |
| 订阅 | 高 | 中 | 中 | 中 |
| 分层 | 中 | 中 | 高 | 中 |
| 平台费 | 高 | 高 | 低 | 中 |
| credits | 中 | 中 | 高 | 高 |
| 企业合同 | 高 | 高 | 低 | 高 |

## 51.3 计量单位

选择计量单位要考虑：

- 与客户价值相关；
- 可解释；
- 可预测；
- 可防作弊；
- 与成本相关；
- 易于技术实现。

常见单位：

- 请求数；
- API 调用；
- 活跃用户；
- 数据量；
- 存储；
- 计算时长；
- token；
- 交易额；
- 成功订单；
- 设备数；
- 查询数；
- 导出流量。

### 好单位的特征

- 客户能理解；
- 客户能控制；
- 与价值相关；
- 不易被滥用；
- 不会因重试重复计费；
- 不会惩罚正常使用；
- 与成本相关。

### 坏单位

- 内部实现指标（CPU 秒、数据库行数）；
- 客户无法控制；
- 与价值无关；
- 容易被刷；
- 计量不稳定；
- 重试重复计费。

### 计量单位的选择

| 产品 | 好单位 | 坏单位 |
|---|---|---|
| 短信 | 成功发送条数 | API 请求数 |
| 支付 | 交易额/成功交易 | 接口调用数 |
| 地图 | 地图加载/路径规划 | CPU 时间 |
| LLM | 输入/输出 token | 请求数 |
| 存储 | GB/月 | 文件数 |
| 搜索 | 查询数/结果数 | 索引大小 |
| 身份验证 | 成功验证数 | 尝试数 |

## 51.4 免费层

免费层的作用：

- 降低尝试门槛；
- 获取开发者；
- 形成习惯；
- 转化为付费；
- 生态传播。

风险：

- 被滥用；
- 成本；
- 免费用户支持负担；
- 转化率低；
- 与付费层冲突。

设计：

- 限制额度；
- 限制功能；
- 限制并发；
- 加水印/品牌；
- 要求信用卡（谨慎）；
- 明确升级路径；
- 防滥用；
- 监控成本。

### 免费层的经济学

```text
免费层成本 = 免费用户数 × 平均用量 × 单位成本
```

如果免费用户转化率低，免费层可能成为纯成本。

需要监控：

- 免费到付费转化；
- 免费用户成本；
- 滥用率；
- 支持工单。

## 51.5 包装

包装是把能力组合成可购买的产品：

```text
Starter: 基础 API + 社区支持
Pro: 更高额度 + SLA + 团队
Enterprise: SSO + 审计 + 专属支持 + 合规
```

包装维度：

- 用量；
- 功能；
- 支持；
- SLA；
- 安全/合规；
- 用户数；
- 环境；
- 区域；
- 优先级；
- 速率限制。

### 包装的原则

- 每个层级有明确目标客户；
- 升级路径清晰；
- 差异可感知；
- 不惩罚增长；
- 不制造伪差异；
- 企业功能可单独购买。

## 51.6 定价心理学

- 锚定；
- 免费层；
- 递减单价；
- 年度折扣；
- 承诺用量折扣；
- 避免账单惊讶；
- 透明；
- 可预测；
- 社会证明；
- 损失厌恶。

### 锚定

价格页上的高价套餐会让中档看起来合理。但：

- 锚定不能替代价值；
- 过度锚定会损害信任；
- 企业价格可以“联系我们”。

### 递减单价

用量越大，单价越低：

- 鼓励增长；
- 反映规模经济；
- 但可能被大客户压价。

## 51.7 账单惊讶

原因：

- 用量突增；
- 重试重复计费；
- 失败请求计费；
- 隐藏的出口流量；
- 分层边界；
- 币种/税；
- 促销结束；
- 自动扩容；
- 模型 token 不可控。

解决：

- 实时用量；
- 预算告警；
- 用量上限；
- 预测；
- 明细账单；
- 重试不计费；
- 明确计费规则；
- 账单解释；
- 退款政策。

### 账单惊讶的代价

- 客户流失；
- 支持成本；
- 信任受损；
- 负面口碑；
- 退款/纠纷。

## 51.8 AI 定价

LLM 成本与 token 相关：

```text
输入 token 单价
输出 token 单价
缓存命中折扣
批量折扣
模型分层
```

定价策略：

- 按 token；
- 按请求；
- 按结果；
- 按席位；
- credits；
- 混合。

挑战：

- 成本波动；
- 输出长度不可控；
- 模型升级改变成本；
- 缓存；
- 推理/思考 token；
- 失败/拒绝是否计费；
- 流式取消；
- 多模态输入。

### AI 定价的设计

- 输入/输出分开；
- 缓存折扣；
- 最大输出限制；
- 预算；
- 预估成本；
- 失败不计费；
- 模型分层；
- 批处理折扣。

## 51.9 定价与 API 设计

定价会影响 API：

- 计量点；
- 限流维度；
- 配额；
- 错误码；
- 账单 API；
- 用量 API；
- 升级流程；
- 试用；
- 成本预估。

如果 API 设计不支持计量，定价就无法落地。

### 计量点设计

- 何时计量（请求开始/完成）；
- 计量什么（成功/失败/重试）；
- 如何去重；
- 如何聚合；
- 如何对账；
- 如何退款。

### 账单 API

```text
GET /v1/billing/usage?from=...&to=...
GET /v1/billing/invoices
GET /v1/billing/invoices/{invoiceId}
GET /v1/billing/estimates?...
```

## 51.10 定价实验

- A/B 测试；
- 客户访谈；
- 赢单/输单分析；
- 价格敏感度；
- 竞品；
- 用量分布；
- 毛利；
- 流失；
- 联合分析（conjoint）。

不要只靠直觉。

### 定价实验的注意事项

- 不要对不同客户不公平；
- 不要违反合同；
- 不要伤害信任；
- 样本量足够；
- 长期影响；
- 法律/合规。

## 51.11 反模式

- 所有客户同一价格；
- 计量单位与价值无关；
- 免费层无限；
- 账单不可预测；
- 隐藏费用；
- 重试重复计费；
- 价格页复杂；
- 销售折扣失控；
- 成本上涨不调价；
- 定价与 API 能力脱节；
- 只按请求数计价，忽略成本差异；
- 免费层被滥用。

## 51.12 本章小结

- 定价是产品设计，不是算术。
- 成本加成、价值定价、用量、订阅、分层、平台费、credits、企业合同各有适用。
- 计量单位要可理解、可控、与价值相关。
- 免费层与包装影响转化与扩展。
- 账单惊讶是留存杀手。
- AI 定价要处理 token 成本与不确定性。
- 定价必须与 API 计量能力匹配。
- 价格表、计价、发票与收入确认的工程实现，见[附录 V](../appendices/v-metering-billing.md)。
