# 第 52 章 单位经济与财务模型

## 52.1 为什么技术团队要懂单位经济

API 的每一个技术决策都会变成成本：

- 多一次数据库查询；
- 多一个区域；
- 多一份日志；
- 多一次模型调用；
- 多一个支持工单；
- 多一个合规审计。

如果不知道单位经济，团队会：

- 用昂贵的方式解决便宜的问题；
- 为低价值客户提供高成本服务；
- 在价格上亏损；
- 无法判断优化优先级。

### 技术决策的成本视角

| 技术决策 | 成本影响 |
|---|---|
| 缓存 | 内存/复杂度 vs 数据库/延迟 |
| 多区域 | 复制/运维 vs 可用性 |
| 日志全量 | 存储/查询 vs 可观测性 |
| 同步调用 | 延迟/耦合 vs 简单 |
| 异步队列 | 基础设施/复杂度 vs 削峰 |
| 模型升级 | 单价 vs 质量 |

## 52.2 核心公式

### 收入

```text
MRR = 月度经常性收入
ARR = MRR × 12
ARPU = 收入 / 用户数
```

### 毛利

```text
Gross Margin = (Revenue - COGS) / Revenue
```

COGS（收入成本）包括：

- 基础设施；
- 第三方 API；
- 支付渠道费；
- 支持；
- 合规；
- 实施；
- 客户成功（视模式）。

不包括：

- 研发；
- 销售；
- 市场；
- 管理。

### 获客成本

```text
CAC = 销售与市场支出 / 新客户数
```

### 客户终身价值

```text
LTV = ARPU × Gross Margin / Churn Rate
```

或按毛利：

```text
LTV = ARPU × Gross Margin × 平均生命周期
```

### 回本周期

```text
Payback = CAC / (ARPU × Gross Margin)
```

### 净收入留存

```text
NRR = (期初收入 + 扩展 - 降级 - 流失) / 期初收入
```

NRR > 100% 表示老客户收入在增长。

### 公式的边界

这些公式是简化模型：

- 假设流失率稳定；
- 假设 ARPU 不变；
- 忽略扩展；
- 忽略折扣；
- 忽略时间价值。

真实模型需要 cohort 和现金流。

## 52.3 一个示例

假设一个 API 套餐：

```text
月费：$99
包含：100 万次调用
COGS：
  计算        $8
  存储        $2
  网络/出口   $3
  第三方      $2
  支持        $5
  合计        $20
毛利：$79（79.8%）
```

获客：

```text
CAC = $600
月流失率 = 2%
```

计算：

```text
LTV = 99 × 0.798 / 0.02 = $3,950
LTV / CAC = 6.6
Payback = 600 / (99 × 0.798) = 7.6 个月
```

这些数字说明：

- 毛利健康；
- 回本约 8 个月；
- LTV/CAC 较高；
- 但如果流失率升到 5%，LTV 降到 $1,580，模型变紧。

### 每调用成本

```text
每调用成本 = COGS / 调用量
           = 20 / 1,000,000
           = $0.00002
```

如果单价是 $0.0001/次，毛利空间很大；如果单价是 $0.00003/次，几乎没有空间。

### 大客户与小客户

先明确每个分层的完整 COGS，而不是只减支持成本。下面是一个示例假设：

| 项目 | 小客户 | 大客户 |
|---|---:|---:|
| 月收入 | $99 | $10,000 |
| 计算 | $8 | $1,200 |
| 存储 | $2 | $200 |
| 网络/出口 | $3 | $300 |
| 第三方 | $2 | $500 |
| 支持 | $20 | $500 |
| **COGS 合计** | **$35** | **$2,700** |
| **毛利** | **$64** | **$7,300** |
| **毛利率** | **64.6%** | **73.0%** |

这组数字说明：

- 小客户的支持成本占比高，毛利率更低；
- 大客户的基础设施成本更高，但规模摊薄后毛利率可能更好；
- 如果小客户的支持成本升到 $40，COGS 变成 $55，毛利率降到 44.4%；
- 平均毛利率会掩盖分层差异，必须按客户分层看。

实际模型中，计算、存储、网络、第三方与支持都要有可追溯的成本分摊规则，而不是拍一个“支持成本”。

## 52.4 敏感性分析

| 变量 | 基准 | 变化 | LTV | LTV/CAC |
|---|---|---|---|---|
| 月流失率 | 2% | 5% | $1,580 | 2.6 |
| 毛利 | 80% | 60% | $2,970 | 5.0 |
| CAC | $600 | $1,200 | $3,950 | 3.3 |
| ARPU | $99 | $49 | $1,955 | 3.3 |

敏感性分析帮助你判断：

- 哪个变量最致命；
- 优化优先级；
- 定价空间；
- 是否值得做某个客户。

### 最敏感的变量

通常：

- 流失率；
- 毛利；
- CAC；
- ARPU。

流失率的微小变化会显著影响 LTV，因为它是分母。

## 52.5 API 特有指标

- 调用量；
- 活跃 API Key；
- 每客户调用量；
- 每千次调用成本；
- 每租户基础设施成本；
- 错误率；
- 支持工单/千次调用；
- 激活时间；
- 首次成功调用；
- 用量集中度；
- 免费转付费；
- 扩展收入；
- 流失原因；
- 每租户存储/流量；
- 每模型 token 成本。

### 每千次调用成本

```text
Cost per 1K calls = 总 COGS / 总调用量 × 1000
```

按端点、租户、区域拆分，才能发现异常。

## 52.6 成本驱动

### 计算

- 请求处理；
- 序列化；
- 加密；
- 模型推理；
- 背景任务。

### 存储

- 数据库；
- 对象存储；
- 日志；
- 备份；
- 向量索引。

### 网络

- 出口流量；
- CDN；
- 跨区域；
- 第三方调用。

### 支持

- 工单；
- 文档；
- 客户成功；
- 实施。

### 合规

- 审计；
- 认证；
- 法律；
- 数据驻留。

### 获客

- 内容；
- 广告；
- 销售；
- 社区；
- 合作伙伴。

### 成本结构示例

```text
基础设施   40%
第三方     20%
支持       15%
合规       10%
获客       15%
```

不同业务差异很大。

## 52.7 cohort 分析

按注册月份分组，观察：

- 留存；
- 用量；
- 收入；
- 扩展；
- 毛利；
- 支持成本。

```text
Cohort 2026-01（小客户自助层，首月流失 15%，之后留存改善）：
  M0: 100 客户
  M1: 85
  M3: 70
  M6: 60
  M12: 50
```

这组数字不等于 52.3 的 2% 基准流失率：首月流失 15%，随后月流失逐步降到约 5%～10%。cohort 要按客户分层看：小客户自助层可能首月流失 10%～15%，企业客户可能低于 1%。把不同分层的 cohort 混在一起，会得到没有意义的平均值。

cohort 能揭示：

- 产品市场匹配；
- 流失模式；
- 扩展；
- 获客质量；
- 定价变化影响。

### cohort 的维度

- 注册月份；
- 渠道；
- 套餐；
- 地区；
- 行业；
- 初始用量。

## 52.8 毛利结构

API 业务的毛利可能被以下因素侵蚀：

- 免费层滥用；
- 大客户定制；
- 出口流量；
- 支持成本；
- 第三方费用；
- 合规；
- 多区域复制；
- 低效查询；
- 日志/追踪存储；
- 重试。

优化：

- 缓存；
- 批处理；
- 模型路由；
- 存储分层；
- 限流；
- 自助；
- 文档；
- 自动化；
- 压缩；
- 生命周期。

### 毛利的陷阱

- 用平均毛利掩盖亏损客户；
- 忽略支持成本；
- 忽略获客成本；
- 忽略基础设施的固定成本；
- 把一次性收入当经常性收入。

## 52.9 定价与单位经济

- 价格低于成本 → 越卖越亏；
- 价格高于价值 → 流失；
- 分层不当 → 大客户补贴小客户；
- 免费层无限制 → 成本失控；
- 超额定价过高 → 客户不敢用；
- 折扣 → 毛利下降。

### 定价下限

```text
最低价格 ≥ 单位成本 / (1 - 目标毛利率)
```

例如单位成本 $0.00002，目标毛利 70%：

```text
最低价格 = 0.00002 / 0.3 = $0.000067
```

## 52.10 财务模型

一个简化的年度模型：

```text
新客户数 × ARPU × 12
+ 老客户扩展
- 流失
= 收入

收入 - COGS = 毛利
毛利 - S&M - R&D - G&A = 营业利润
```

需要假设：

- 获客速度；
- 转化率；
- 流失率；
- 扩展率；
- 单价；
- 成本；
- 招聘；
- 融资。

### 模型的结构

```text
客户获取 → 激活 → 留存 → 扩展 → 收入
成本：基础设施、支持、合规、获客、研发
```

### 从财务模型到估值

估值不是“收入 × 一个倍数”这么简单。对 API 业务，至少要同时看五组变量：

| 变量 | 为什么重要 | 常见信号 |
|---|---|---|
| 增长 | 决定倍数上限 | 同比增速、净新增 ARR |
| 毛利 | 决定收入质量 | 基础设施/第三方成本占比 |
| 留存与扩展 | 决定复利 | NRR、logo churn、用量留存 |
| 客户集中度 | 决定风险折价 | 前 5 大客户收入占比 |
| 获客效率 | 决定增长可持续 | CAC payback、LTV/CAC |

常见估值方法：

- **可比公司倍数**：ARR/收入倍数、EV/ARR、EV/EBITDA；倍数随增长、毛利、留存、市场情绪变化，不能把某一年的倍数当常数。
- **DCF**：适合现金流可预测、合同期限长的业务；对 API 用量型收入，要分别建模留存、扩展与价格下行。
- **战略价值**：客户、数据、开发者生态、牌照、地域覆盖；收购方可能愿意支付溢价，也可能因为整合风险折价。
- **资产法**：通常不适用于持续经营的 API 业务，但对专利、牌照、数据资产有参考价值。

API 资产的技术尽调通常包括：

- 契约稳定性与版本策略；
- 客户集中在哪些端点/租户；
- 毛利对第三方模型、支付通道、云厂商的敏感度；
- 数据处理协议、跨境传输、子处理者清单；
- SLA 历史、事故记录、赔偿条款；
- 开源许可证与供应链依赖；
- 收购后 API 合同是否自动继承、是否需要客户同意；
- 迁移到收购方平台的成本与客户流失风险。

并购后的常见失败：

- 强行合并 API、破坏兼容性，导致客户流失；
- 统一提价，忽略用量型客户的成本结构；
- 停掉“非核心”端点，却不知道谁在依赖；
- 数据驻留/合规承诺无法继承；
- 开发者关系团队被裁，生态冷却。

估值是收入质量、增长、毛利、留存与风险的函数。技术团队能提供的最有价值证据，不是“架构多先进”，而是“契约有多稳、成本有多可预测、客户有多难离开”。

## 52.11 反模式

- 只看收入，不看毛利；
- 用平均成本掩盖大客户亏损；
- 免费层无成本模型；
- 忽略支持成本；
- 忽略出口流量；
- 定价拍脑袋；
- 不做 cohort；
- 不做敏感性；
- 把一次收入当经常性收入；
- 忽略重试成本；
- 忽略日志/追踪成本。

## 52.12 本章小结

- 单位经济连接技术与商业。
- 核心公式：毛利、CAC、LTV、回本、NRR。
- API 特有指标包括调用量、每千次成本、支持工单、激活。
- 成本驱动包括计算、存储、网络、支持、合规、获客。
- cohort 与敏感性分析帮助判断可持续性。
- 估值是收入质量、增长、毛利、留存与风险的函数；技术尽调看契约稳定性、客户集中度与迁移成本。
- 定价必须覆盖成本并反映价值。
- 从计量、计价到发票、收入确认与对账的链路，见[附录 V](../appendices/v-metering-billing.md)；成本归因与 FinOps 运营见[附录 Y](../appendices/y-cost-engineering-finops.md)。

## 设计练习

为一个“短信通知 API”建立单位经济模型：

- 每条短信成本；
- 月套餐；
- 免费层；
- CAC；
- 流失；
- 支持成本；
- 毛利；
- LTV/CAC。

做一张敏感性分析表，找出最敏感的变量。然后回答：

1. 免费层每月成本多少？
2. 哪个客户分层亏损？
3. 如果渠道费上涨 20%，毛利如何变化？
4. 最低可持续价格是多少？
