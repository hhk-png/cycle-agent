# 第 54 章 运营指标与增长

## 54.1 API 产品的增长漏斗

```text
访问 → 注册 → 获取密钥 → 首次调用 → 首次成功集成
→ 持续使用 → 扩展 → 付费 → 留存 → 推荐
```

每一步都有转化率。API 产品最关键的早期指标是：

- **Time to First Call（TTFC）**；
- **Time to First Successful Integration**；
- **激活率**；
- **周/月活跃 API Key**；
- **用量增长**；
- **留存**。

### 漏斗的诊断

| 阶段 | 问题 | 指标 |
|---|---|---|
| 访问 | 找到我们了吗？ | 流量、搜索排名 |
| 注册 | 愿意试吗？ | 注册转化 |
| 密钥 | 能开始吗？ | 密钥创建率 |
| 首次调用 | 能跑通吗？ | TTFC、首次成功率 |
| 集成 | 能上线吗？ | 集成完成率 |
| 持续 | 还在用吗？ | 活跃 Key、用量 |
| 扩展 | 用得更多吗？ | NRR、用量增长 |
| 付费 | 愿意付吗？ | 免费转付费 |
| 留存 | 会留下吗？ | 流失率 |
| 推荐 | 会推荐吗？ | NPS、推荐 |

### 漏斗计算示例

```text
访问        10,000
注册         1,200   (12%)
获取密钥       800   (67%)
首次调用       500   (63%)
首次成功集成   250   (50%)
持续使用       180   (72%)
付费            40   (22%)
```

从访问到付费的整体转化率：

```text
40 / 10,000 = 0.4%
```

瓶颈通常在：

- 注册到密钥；
- 密钥到首次调用；
- 首次调用到集成。

每一步都可用产品手段改善：

- 注册流程；
- 引导；
- 示例；
- 沙箱；
- 错误信息；
- 文档。

## 54.2 北极星指标

北极星指标应与客户价值一致：

- 成功调用数；
- 活跃集成数；
- 每月处理的消息/订单/文档数；
- 客户节省的时间/成本；
- 开发者活跃度。

不要选：

- 注册数；
- 页面浏览量；
- API 总数；
- 收入（短期）。

### 北极星指标的标准

- 反映客户价值；
- 可增长；
- 可影响；
- 可理解；
- 不被短期操纵。

## 54.3 激活

激活的定义因产品而异：

```text
注册后 7 天内完成 10 次成功调用
或
完成一次真实业务集成
```

关键：

- 首次调用时间；
- 首次成功调用；
- 首个生产密钥；
- 首个 Webhook 成功；
- 首个付费；
- 首个真实数据。

### 激活的分解

```text
激活 = 注册 → 密钥 → 首次调用 → 首次成功 → 首次生产使用
```

每一步都可以优化。

## 54.4 留存

- 日/周/月活跃；
- 调用留存；
- 收入留存（NRR）；
- 租户留存；
- 功能留存；
- cohort。

API 留存的特点：

- 集成后切换成本高；
- 但可能长期低用量；
- 需要区分“活跃”和“沉睡”；
- 大客户集中度高。

### 留存的度量

```text
Logo retention = 留存客户数 / 期初客户数
Revenue retention = 留存收入 / 期初收入
Usage retention = 留存调用量 / 期初调用量
```

三者可能不同：

- 客户留存但用量下降；
- 用量增长但客户流失；
- 收入留存高于客户留存（扩展）。

## 54.5 扩展

- 用量增长；
- 套餐升级；
- 新功能采用；
- 新部门/地区；
- 合作伙伴；
- 席位。

NRR 公式见第 52 章。

### 扩展的信号

- 用量接近配额；
- 限流命中增加；
- 新 API Key；
- 新环境；
- 新地区；
- 新团队。

## 54.6 可靠性指标

- 可用性；
- 错误率；
- P50/P95/P99 延迟；
- 限流命中；
- 超时；
- 重试；
- 依赖故障；
- 事件响应时间；
- MTTR；
- SLO 达标率。

这些指标要能按：

- 端点；
- 租户；
- 区域；
- 版本；
- 客户端；
- 模型；

拆分。

### 可靠性指标的业务影响

- 错误率上升 → 客户流失；
- 延迟上升 → 用量下降；
- 限流误伤 → 支持工单；
- 事故 → 信任受损。

## 54.7 支持指标

- 工单量；
- 首次响应时间；
- 解决时间；
- 自助解决率；
- 文档命中率；
- 重复问题；
- 客户满意度（CSAT）；
- 升级率。

支持工单是产品改进的金矿。

### 工单分析

- 按主题；
- 按端点；
- 按错误码；
- 按客户；
- 按版本；
- 按地区。

重复工单往往意味着：

- 文档缺失；
- 错误信息不清；
- 产品缺陷；
- 限制不合理。

## 54.8 文档与 DX 指标

- 无结果率；

- 示例复制；
- 沙箱使用；
- SDK 下载；
- 首次调用错误率；
- 文档反馈；
- TTFC。

## 54.9 收入与商业指标

- MRR/ARR；
- ARPU；
- 毛利率；
- CAC；
- LTV；
- 回本周期；
- NRR；
- 流失率；
- 扩张收入；
- 客户集中度；
- 免费转付费；
- 承诺用量完成率。

### 客户集中度

```text
Top 10 客户收入占比
```

过高意味着：

- 议价能力弱；
- 流失风险大；
- 定制压力大。

### Agent 产品的运营指标

当 API 的主要消费者变成 Agent，传统“调用次数/月活”不足以描述价值。需要补充：

| 指标 | 定义 | 用途 |
|---|---|---|
| 任务成功率 | 端到端完成的任务 / 发起的任务 | 衡量 Agent 是否真的解决问题 |
| 工具选择正确率 | 选对工具的次数 / 工具调用次数 | 发现描述与 schema 问题 |
| 参数正确率 | 首次参数合法 / 调用次数 | 衡量契约是否清晰 |
| 人工介入率 | 需要人确认或接管的任务比例 | 自动化程度的真实成本 |
| 平均工具调用数 | 每任务工具调用次数 | 发现绕路、重复与低效 |
| 每任务成本 | 模型 + 工具 + 基础设施 | 定价与毛利 |
| 恢复率 | 失败后可自愈的比例 | 错误设计质量 |
| 未授权拦截率 | 因未授权/策略被拒绝的请求 / 总请求 | 安全策略是否在生效 |
| 过阻率（false positive） | 人工复核判定本应允许、却被拦截的请求 / 被拦截请求 | 策略是否误伤正常调用 |
| 漏放率（false negative） | 事后判定应拦截、却放行的请求 / 应拦截请求 | 策略是否有缺口 |

这些指标要能按租户、模型版本、工具版本、任务类型切片。否则你只能看到“成功率下降了”，却不知道是模型升级、工具变更还是某个下游 API 变慢。

## 54.10 实验

API 产品可以做：

- 定价实验；
- 文档布局；
- 快速开始流程；
- SDK 默认值；
- 错误信息；
- 沙箱；
- 限流策略；
- 新功能灰度。

实验要：

- 有假设；
- 有指标；
- 有样本量；
- 有伦理/合规；
- 不伤害生产；
- 有停止条件。

## 54.12 仪表盘

分层：

### 高管

- ARR；
- NRR；
- 毛利；
- 客户数；
- 流失。

### 产品

- 激活；
- 留存；
- 功能采用；
- 用量；
- 支持。

### 工程

- SLO；
- 错误率；
- 延迟；
- 容量；
- 成本。

### 客户成功

- 健康度；
- 用量；
- 工单；
- 续费风险。

### 仪表盘的原则

- 每个指标有定义；
- 每个指标有负责人；
- 每个指标有行动；
- 不要堆砌；
- 定期清理。

### 仪表盘布局示例

```text
┌──────────────────────────────────────────────┐
│ 北极星：成功调用数       趋势  目标  预测      │
├────────────────────┬─────────────────────────┤
│ 激活漏斗            │ 留存 cohort             │
├────────────────────┼─────────────────────────┤
│ SLO / 错误预算      │ 延迟分位数              │
├────────────────────┼─────────────────────────┤
│ 每租户用量 Top 10   │ 支持工单 / 错误码       │
└────────────────────┴─────────────────────────┘
```

每个图表应能下钻到：

- 端点；
- 租户；
- 版本；
- 客户端；
- 区域。

## 54.13 事故沟通

- 状态页；
- 事件等级；
- 影响范围；
- 更新时间；
- 根因；
- 修复；
- 复盘；
- 客户通知。

透明度建立信任。

### 事故沟通模板

```text
[P1] 订单 API 错误率上升

影响：华东区域部分订单创建失败
开始时间：2026-11-26 10:05 UTC
当前状态：已定位，正在回滚
影响范围：约 3% 的创建请求
下一步：10:40 更新
```

要求：

- 说影响，不说猜测；
- 给时间点；
- 给下次更新时间；
- 不推卸责任；
- 复盘公开。

### 事故等级

```text
P0：全站不可用
P1：核心功能不可用
P2：部分用户/功能受影响
P3：需要关注
```

## 54.14 反模式

- 只看注册数；
- 不看激活；
- 不看留存；
- 不看毛利；
- 指标不可拆分；
- 仪表盘太多；
- 告警疲劳；
- 支持与产品脱节；
- 实验无统计；
- 事故不透明；
- 北极星指标可被操纵；
- 只看增长不看质量。

## 54.15 本章小结

- API 增长看漏斗：访问、注册、首次调用、集成、留存、扩展、付费。
- 北极星指标要与客户价值一致。
- 激活、留存、扩展是核心。
- 可靠性、支持、文档、收入指标要一起看。
- Agent 产品要看任务成功率、工具正确率、人工介入率与每任务成本。
- 实验与客户成功驱动增长。
- 仪表盘按受众分层。
- 事故沟通建立信任。
