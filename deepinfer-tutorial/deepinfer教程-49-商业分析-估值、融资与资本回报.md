# 第 49 章 商业分析：估值、融资与资本回报

本章导读：第 47 章算的是一个项目或一个客户的现金流，本章把这些现金流放回资本市场：一笔 GPU 投资值多少钱，一家推理公司用什么方法估值，融资会稀释多少，什么时候该买卡、租卡或回购，以及并购和退出时买家真正看什么。读完本章，你应该能区分“项目 NPV”和“公司估值”，能用 DCF 和倍数法交叉验证一个数字，并知道哪些假设会让估值从合理变成故事。

## 49.1 推理业务的资本特征

推理业务和典型 SaaS 的财务结构不同，估值方法也不能直接套。

第一，**资本开支重**。GPU、服务器、网络、存储要先投入，收入在后面逐步爬坡。一个 8 卡 pod 的 3 年 TCO 可能是 80 万美元，而第一年的收入可能只有几十万美元。现金流在前期为负，回本周期以年计。估值时必须把 capex、折旧和营运资金算进去，不能只看毛利率。

第二，**边际成本不低**。SaaS 多服务一个客户的边际成本接近零；推理多服务一个客户要消耗 GPU、电力和 KV 存储。毛利会随利用率、上下文长度、缓存命中率和价格变化。一个 80% 毛利的模型，可能在长上下文或价格战下变成 40%。

第三，**利用率是隐藏杠杆**。同样的 GPU，利用率 70% 和 40% 的有效成本差近一倍。估值模型如果假设 80% 利用率，但实际只能做到 50%，现金流会差很多。利用率不是“运营细节”，它是估值假设。

第四，**收入质量差异大**。按量计费的 API 收入是经常性的，但客户可以随时流失；承诺合同收入可预测，但折扣和容量预留会压低毛利；私有化实施费是一次性的，不能按订阅倍数估值。估值时要拆分收入类型，分别给倍数或现金流。

第五，**技术迭代快**。GPU 一代代更新，模型结构也在变；今天买的卡可能三年后残值很低，今天的推理优化可能被下一代硬件或模型结构重写。折旧年限、残值和技术路线风险要显式建模，不能假设“设备一直有用”。

这五点决定了：推理公司的估值不能只看收入增长，还要看毛利、capex、利用率和收入质量。一个增长 100% 但毛利 20%、capex 吃掉全部现金流的公司，估值可能低于一个增长 30%、毛利 60%、现金流稳定的公司。

## 49.2 估值的三把尺子

估值有三种基本方法，它们回答的问题不同，应该交叉使用。

**DCF（现金流折现）**：预测未来自由现金流，按资本成本折现，得到企业价值。它最接近“这个业务值多少钱”，但依赖长期假设，终值往往占总价值的 70% 以上。`finance.dcf_value` 实现了显式现金流加 Gordon 终值的版本。

**可比公司倍数**：用同行业上市公司的 EV/Revenue、EV/EBITDA、P/E 等倍数，乘到目标公司的对应指标上。它反映“市场现在愿意为类似的增长和毛利付多少”，但可比公司难找，市场情绪也会让倍数大幅波动。

**可比交易倍数**：用并购交易的 EV/Revenue 或 EV/EBITDA，乘到目标公司上。它反映“战略买家愿意付多少”，通常包含控制权溢价和协同价值。交易样本少，时点差异大。

三种方法的结果应该在一个区间内互相解释。如果 DCF 算出 5 亿美元、可比公司算出 20 亿美元，不要取平均；要问“为什么差 4 倍”：是增长假设不同、毛利不同，还是可比公司选错了层（基础设施、API、应用）？估值不是求一个精确数，而是理解“市场和你对未来的假设差在哪里”。

对推理业务，还要按价值链分层选倍数。芯片/互联是重资产、高壁垒，适合 EV/EBITDA 或 EV/产能；推理引擎/平台是软件，适合 EV/Revenue；API/云服务是基础设施，适合 EV/Revenue 加毛利调整；应用/工作流最接近客户，适合 SaaS 倍数。把一家 API 公司和一家应用公司放在同一组可比里，会得出荒谬的结论。

## 49.3 DCF：把 capex 和终值算清楚

DCF 的骨架是：

```text
FCF_t = EBITDA_t - capex_t - ΔNWC_t - tax_t
EV = Σ FCF_t / (1 + WACC)^t + TV / (1 + WACC)^N
TV = FCF_N × (1 + g) / (WACC - g)
```

`WACC` 是加权平均资本成本，反映股东和债权人的机会成本；`g` 是永续增长率，通常不超过长期 GDP 增速；`ΔNWC` 是营运资金变化，企业客户回款慢时会吃掉现金；`tax` 是现金税，不是会计上的递延税。

用第 47 章的 8 卡 pod 例子：`cashflows = [-460000, 140000, 240000, 300000]`（capex 46 万，三年净经营现金流 14/24/30 万），折现率 10%，终值增长率 2%。`dcf_value` 的输出是显式现金流现值约 9.1 万美元，终值现值约 287.4 万美元，企业价值约 296.5 万美元。终值占了约 97%，这是“三年显式期太短、终值假设主导”的典型结果，也是一个警告：三年后就报废的 GPU pod 不配永续增长。任何对 `g` 或 `WACC` 的小改动都会大幅改变估值：`g=1%` 时终值约 252.9 万美元，`g=3%` 时约 331.7 万美元，差约 31%。

这个例子说明三件事。第一，**终值假设比显式期更重要**。如果业务只有三年寿命，就不应该用永续终值；如果业务会持续，就要解释为什么三年后的增长和毛利可持续。一个更保守的交叉检查是用退出倍数：按第 3 年收入 42 万美元的 4 倍算，退出价值只有约 168 万美元，远低于永续终值的 287 万美元；两个数字的差距就是“终值假设”的价格。第二，**capex 和折旧要一致**。DCF 里的 capex 是现金支出，折旧只影响税；如果 capex 已经算在 t=0，后续又按折旧扣一次，会重复计算。第三，**营运资金不能忘**。企业客户 60 到 120 天回款，收入确认和现金到账之间有缺口；快速增长时，应收账款可能先于亏损出现。

还要补一项很多 DCF 会漏掉的成本：**替换 capex**。GPU 的寿命只有 3 到 5 年，三年后的 300 万美元终值假设业务继续产生现金流，却没有为下一代 GPU 再付一次钱。更稳妥的做法是把显式期延长到资产寿命、在每年扣掉维持性 capex，或者用“退出时的残值/倍数”代替永续增长。永续模型不是不能用，但它要求你能解释“为什么三年后不需要再买卡”。

对推理业务，DCF 还要单独建模三类 capex：GPU/服务器、网络/存储、机房改造。GPU 的折旧年限通常 3 到 5 年，残值取决于下一代产品；网络和存储的寿命更长；机房改造是长期资产。把三类资产混成一个折旧率，会高估或低估前几年的成本。第 32 章的 TCO 模型可以作为 DCF 的成本输入，但要把“3 年 TCO”拆成“每年 capex + opex”，而不是把总额一次性放在 t=0。

## 49.4 倍数法：收入倍数不是常数

收入倍数（EV/Revenue）是最常用的快速估值工具，但它不是一个固定数字。它由四个变量决定：增长、毛利、留存、资本强度。

```text
EV/Revenue ≈ f(growth, gross_margin, retention, capex_intensity)
```

增长越快、毛利越高、留存越好、capex 越轻，倍数越高。一个增长 80%、毛利 70%、净收入留存 120% 的 SaaS，可能拿到 10 到 15 倍收入；一个增长 30%、毛利 40%、capex 占收入 50% 的推理基础设施公司，可能只有 2 到 4 倍。把 SaaS 倍数套到推理 API 上，会高估几倍。

`revenue_multiple_value(revenue, multiple)` 和 `implied_revenue_multiple(ev, revenue)` 是一对互逆的函数。前者用倍数算价值，后者从交易价格反推倍数。反推的用途是校准：如果你看到一笔并购是 3 亿美元买 5,000 万美元收入，隐含 6 倍；再看它的毛利、增长和 capex，判断这个倍数是否合理，而不是直接套到自己的公司上。

推理公司还要区分收入类型。按量 API 收入是经常性的，但客户流失率高，倍数应该低于订阅；承诺合同收入可预测，但折扣和容量预留会压低毛利，倍数要按贡献毛利调整；私有化实施费是一次性的，不能按收入倍数估值，应该按项目现金流或服务毛利估值。一个公司如果 50% 收入来自一次性实施，用 8 倍收入估值会严重高估。

EV/EBITDA 适合重资产、折旧大的业务，但推理公司的 EBITDA 可能被 capex 和折旧扭曲：折旧年限短，EBITDA 看起来高，但现金流出大。用 EV/EBITDA 时，要同时看 capex/EBITDA 和自由现金流转换率。一个 EBITDA 很高但 capex 吃掉 80% 的公司，估值不应该按 EBITDA 倍数给。

## 49.5 融资路径与稀释

推理业务的融资路径通常分阶段，每一阶段对应不同的风险。

**种子/天使**：验证产品和早期客户，金额几十万到几百万美元。投资人看团队、场景和早期留存，不太看收入倍数。

**A 轮**：验证 PMF 和单位经济，金额几百万到几千万美元。投资人看收入增长、毛利、CAC 回收期和留存。

**B/C 轮**：规模化，金额几千万到几亿美元。投资人看市场份额、销售效率、现金流和竞争壁垒。这一阶段可能需要债务或设备融资来买 GPU。

**成长/Pre-IPO**：优化资本结构，准备上市或被并购。投资人看收入质量、利润率、治理和合规。

**债务/项目融资**：用 GPU 或合同现金流做抵押，利率低于股权，但要求稳定的现金流和担保。适合已有承诺合同、利用率可预测的业务。

**战略投资**：云厂商、GPU 厂商、模型厂商投资，可能带渠道、算力或模型合作，也可能带排他条款。接受前要看清战略条款对客户和估值的影响。

稀释可以用一个简单模型算。假设公司投前估值 2,000 万美元，融资 500 万美元，投后估值 2,500 万美元，投资人占 20%。下一轮投前 1 亿美元，融资 2,000 万美元，投后 1.2 亿美元，新一轮占 16.7%，创始人从 80% 稀释到 66.7%。如果中间还有期权池、可转债、桥轮，稀释会更多。融资不是“钱越多越好”，每轮都要问：这笔钱能换来什么里程碑，里程碑能否让下一轮估值覆盖稀释？

融资时机也很重要。最好的时机不是“没钱了”，而是“单位经济刚被验证、增长可以复制”的时候。此时估值高、谈判筹码多；等到现金流紧张再融资，投资人会压价、加条款，创始人和老股东损失更大。反过来，如果单位经济没验证就大额融资，钱会烧在获客和算力上，增长越快亏得越多。

## 49.6 资本配置：买卡、租卡、回购

融资和经营产生现金后，资本配置决定长期回报。推理业务最常见的三个选择是买卡、租卡、回购/分红。

**买卡**适合利用率高、需求稳定、技术迭代可控的场景。这里有两个容易混用的临界利用率。第一个是第 47.6 节的“覆盖固定成本”：`u* = 年固定成本 / (GPU 数 × 8760 × 每 GPU 小时贡献)`，它回答“自建能不能养活自己”。第二个是第 32.3 节的“自建 vs 云”：`u* = (自建 3 年 TCO / 3) / (GPU 数 × 8760 × 云上每 GPU 小时价格)`，它回答“自建和租卡哪个便宜”。两个公式的分母不同（贡献 vs 云价），不能互相替代。买卡还要考虑残值、折旧、机房电力和运维人力，不能只比单卡价格。

**租卡**适合需求波动大、技术迭代快、不想承担 capex 的场景。云厂商的预留实例、savings plan、竞价实例各有取舍：预留便宜但锁定，竞价更便宜但可能被中断，按量最灵活但最贵。推理服务要区分在线和离线：在线请求不能承受频繁中断，离线批处理可以用竞价实例。第 40 章的离线调度和第 46 章的容量缓冲可以配合使用。

买卡和租卡不能只比名义总价，要把时间、残值、税和利用率放进同一个现金流。一个示意的 3 年比较：8 卡买卡的 capex 是 46 万美元，年度 opex 12 万美元，3 年后残值按 capex 的 20% 算（9.2 万美元），折现率 10%。买卡的 PV 成本约 `46 + 12/1.1 + 12/1.21 + 12/1.331 - 9.2/1.331 ≈ 68.9 万美元`。同样的 8 卡按 4.5 美元/GPU 小时租，满负荷 3 年的 PV 约 `8 × 4.5 × 8760 × 2.4869 ≈ 78.4 万美元`；买卡略便宜。但如果平均利用率只有 40%，租卡的按量成本约 `78.4 × 0.4 ≈ 31.4 万美元`，反而更便宜；盈亏平衡利用率约 `68.9 / 78.4 ≈ 88%`。这就是“利用率低时租、利用率高时买”的算术来源。真实决策还要加税盾、维保、残值不确定性、迁移成本和合同锁定；这里只示范口径，不构成采购建议。

**回购/分红**适合现金流稳定、增长机会有限、资本成本高的业务。如果公司无法把现金投入到高于资本回报的项目，回购或分红比盲目扩张更创造价值。推理业务容易陷入“增长陷阱”：为了增长买更多卡，利用率下降，单位成本上升，现金流恶化。回购的前提是现金流真实、负债可控、未来 capex 可预测。

资本配置还要看“边际回报”。同样 100 万美元，投在 GPU 上可能带来 20% 的增量回报，投在销售上可能带来 30%，投在研发上可能带来 50% 但周期更长。用第 47 章的 NPV 和本章的 DCF 比较不同用途的边际回报，而不是按“哪个部门声音大”分配。

## 49.7 情景估值与敏感性

估值不是单点，是区间。至少要做三情景：基准、乐观、悲观。`scenario_table` 把收入乘 0.8、成本乘 1.2（收入降 20%、成本涨 20%），给出 worst/base/best 的 NPV、IRR 和回收期。对估值，还要额外做三个敏感性：终值增长率 `g`、折现率 `WACC`、利用率。

用 8 卡 pod 的例子：基准企业价值约 405 万美元；`g` 从 2% 降到 1%，终值降到约 354 万美元；`WACC` 从 10% 升到 12%，企业价值会再降约 25%（终值折现和显式现金流同时变小）；利用率从 70% 降到 50%，现金流下降，估值可能腰斩。三个变量的影响不是相加，而是相乘；悲观情景下，估值可能只有基准的三分之一。

敏感性分析要用 tornado 图排序，找出“最值得验证的假设”。如果 `g` 最敏感，就去验证长期增长和留存；如果利用率最敏感，就去压测真实流量；如果单价最敏感，就去做定价实验。不要平均用力，也不要用“保守一点”代替具体假设。

情景估值还要有“触发条件”。不是“如果增长慢一点”，而是“如果第 12 个月付费客户少于 30 个、月流失率高于 3%、GPU 利用率低于 40%，就触发降级方案”。触发条件让估值从“拍数字”变成“可管理的计划”：达到什么指标继续投，达不到什么指标收缩或转型。第 50 章会把这种触发条件扩展到技术路线和商业模式。

## 49.8 并购、退出与收入质量

并购买家分两类。**战略买家**看协同：客户、渠道、技术、算力、合规资质。他们愿意为协同付溢价，但会严格要求收入质量和团队留任。**财务买家**看现金流和退出倍数，通常用杠杆收购，要求稳定的经常性收入和可预测的 capex。

买家最关心的五个问题。第一，收入中有多少是经常性的、多少是一次性的？第二，客户集中度多高，前五大客户占多少收入？第三，毛利是否扣除了 GPU、电力、带宽、存储和支持？第四，capex 和折旧是否真实，未来两年要不要大额买卡？第五，技术和团队是否可替代，核心 kernel/调度/客户关系是否集中在少数人身上？

收入质量比收入规模更重要。一个 1,000 万美元收入、80% 经常性、前五大客户占 20%、毛利 60% 的公司，可能比一个 3,000 万美元收入、50% 一次性实施、前五大客户占 60%、毛利 30% 的公司更值钱。并购尽调会重新计算“调整后 EBITDA”，把一次性的研发、营销、法律费用加回，也会把“应该花但没花”的 capex 和运维扣掉。卖方常用的“EBITDA 倍数”在尽调后往往会下降。

退出路径不只有并购和 IPO。二级市场老股转让、员工期权回购、战略合资、资产出售都是选项。选择取决于流动性需求、估值、控制权和税务。一个常见的错误是“等到必须卖的时候才找买家”，此时谈判筹码最少；提前建立关系、准备数据、规范财务和合规，能在退出时显著提高估值。

## 49.9 治理与风险

估值的前提是治理可信。投资人会看：财务是否规范、关联交易是否披露、数据是否合规、模型和权重许可是否清晰、关键人依赖是否可控、董事会是否有独立声音。治理缺陷会直接折价，甚至让交易无法完成。

推理业务的特有风险有五个。第一，**价格战**：模型能力接近时，单价会快速下降，毛利被压缩。第二，**技术路线**：线性注意力、新记忆结构、端侧芯片可能改变成本结构，今天的 GPU 投资可能贬值。第三，**供应链**：GPU、HBM、网络设备、电力都可能短缺或涨价。第四，**监管**：数据驻留、内容审核、模型备案、出口管制会增加成本和进入门槛。第五，**客户集中**：大客户自建或换供应商，会让收入断崖。

治理不是“等上市前再补”。从第一天就保留合同、发票、数据流、模型版本、安全审计和董事会纪要，融资和并购时能省几个月。合规也不是成本中心：在金融、医疗、政务市场，合规资质本身就是护城河，能支撑更高的单价和更低的客户流失。

## 49.10 用 finance.py 和 market.py 复算

`mini_deepinfer/finance.py` 提供 `dcf_value`、`terminal_value`、`revenue_multiple_value`、`implied_revenue_multiple`、`venture_return`，以及第 47 章的 NPV、IRR、LTV/CAC、合同和情景分析。`mini_deepinfer/market.py` 提供 TAM/SAM/SOM、采用曲线、漏斗、magic number 和销售产能。运行：

```bash
python examples/finance.py
python -m pytest tests/test_finance.py tests/test_market.py -q
```

一次运行的输出包括：8 卡 pod 的 DCF 显式现值约 9.1 万美元、终值现值约 287.4 万美元、企业价值约 296.5 万美元；4 倍收入乘 1,000 万美元收入得到 4,000 万美元；5,000 万美元退出对 1,000 万美元投资是 5 倍 MOIC；TAM/SAM/SOM 是 1.12 亿/3,360 万/336 万美元；10 万访客的漏斗最终 1,500 个付费客户；magic number 1.33。这些数字是确定性的，用来对照公式，不代表真实市场或真实公司的估值。

这些模型能回答“假设变了，结果怎么变”，不能回答“这个假设会不会成立”。真实估值还要看团队、竞争、技术、合规和市场情绪；模型的作用是让你在谈判时知道自己在为什么付费，而不是被一个倍数牵着走。

## 49.11 常见陷阱

**把项目 NPV 当公司估值。** 一个 pod 的 NPV 是项目层面的现金流，公司估值还包括团队、客户关系、技术资产、增长期权和负债。直接把所有 pod 的 NPV 相加，会忽略总部成本、销售费用和资本结构。

**用收入倍数代替现金流。** 收入倍数在低利率、高增长时期很高，在利率上升或增长放缓时会快速压缩。估值时要用 DCF 做底，用倍数做交叉验证，而不是反过来。

**忽略 capex 和营运资金。** 推理公司的现金流被 GPU 采购和应收账款占用；只看 EBITDA 或毛利，会高估自由现金流。

**终值假设过于乐观。** 永续增长率高于长期 GDP、毛利率假设高于行业稳态、利用率假设接近 100%，都会让终值虚高。终值占估值比例越高，越要保守。

**融资只看估值不看条款。** 清算优先权、反稀释、董事会席位、否决权、对赌条款，都会改变真实回报。高估值但苛刻条款，可能比低估值但干净条款更差。

**把一次性收入当经常性收入。** 私有化实施、硬件转售、一次性调优不能按订阅倍数估值；收入质量和可持续性比总额更重要。

**忽略稀释和退出税。** 多轮融资后创始人可能只剩小股份；并购和 IPO 的税、费用、员工期权也会影响净回报。算 MOIC 时要用税后、费后的净额。

## 小结

估值把技术、市场和现金流翻译成资本语言。DCF 看长期自由现金流，倍数法看市场愿意付多少，可比交易看战略买家的协同；三者要交叉验证，不能单独使用。推理业务的资本特征是高 capex、边际成本不低、利用率敏感、收入质量差异大，估值时必须把 capex、折旧、营运资金和利用率算进去。融资要看时机、稀释和条款，资本配置要看边际回报和盈亏平衡利用率，并购要看收入质量、客户集中度和技术可替代性。`finance.py` 和 `market.py` 把这些关系写成可复算的函数，但真实决策还要靠对团队、竞争和风险的判断。
