# 第 0 章 前言：如何读这本书

本章导读：说明这本书要解决的问题、读者路径、代码约定、验证口径和章节之间的关系。读完之后，你应该知道哪些章节必须按顺序读，哪些可以按需跳读，以及“mini-deepinfer 能跑”到底证明了什么、没有证明什么。

## 0.1 这本书想解决什么问题

一个大模型推理框架看起来在做很多事：调度请求、管理显存、切分专家、压缩 KV、编译文法、抓取性能 trace。把这些事拆开，背后其实只有三个问题。

第一，**怎样把一次自回归生成变成一条稳定的流水线**。模型只负责“给定前缀，输出下一个 token 的概率”。真正对外提供服务时，请求会并发到达、长度不同、随时取消，GPU 还要同时做 prefill 和 decode。框架要把这些不确定性收拢成可预测的 step。

第二，**怎样让每个 token 的成本足够低**。成本由计算、显存带宽、通信和存储共同决定。prefill 通常更像矩阵乘法，decode 通常更像“把整个模型的权重读一遍”，MoE 又把计算变成稀疏路由，KV cache 则把“重复读前缀”变成“读缓存”。优化必须落在具体的硬件和负载上，不能只停留在口号。

第三，**怎样在成本之外保证正确性和可运维性**。低精度不能改变语义，批处理不能改变输出，结构化输出不能靠事后修补，KV 缓存命中不能悄悄改变结果，故障切换不能把用户请求丢掉。一个推理框架的“快”只有建立在“可复现、可观测、可恢复”之上才有商业意义。

这本书围绕这三个问题展开。第一部分建立性能与系统直觉；第二部分拆开 DeepSeek-V4.1-Flash 与 DeepInfer 的关键算法；第三部分进入引擎内部；第四部分把这些机制压缩成一个可以在这台机器上运行的实现；第五部分讨论安全与评测；第六部分讨论钱、竞争和部署；第七部分讨论工程化、模型接入、云原生、产品化和合规；第八部分处理多模态、长思维链、离线批处理、多模型/适配器、检索推理和图编译这些专项负载与平台能力；第九部分把镜头转向 RL rollout、端侧异构和流量工程；第十部分讨论现金流、市场测算、估值融资，并回到未来与结语。每一章都尽量回答“为什么这样设计、代码在哪里、数字怎么算、边界在哪里”四个问题。

## 0.2 先排除一个同名项目

公开资料中有两个 DeepInfer。

一个是 2017 年 MICCAI/SPIE 论文中的医学影像工具包，它把训练好的模型打包成 Docker 镜像，通过 3D Slicer 插件做推理，核心是模型仓库、容器和影像交互。另一个是 DeepSeek 在 2026 年 10 月开源的 LLM 推理框架 `deepseek-ai/DeepInfer`，它服务 DeepSeek-V4.1-Flash，核心是 kernel、调度、KV cache、专家并行和推测解码。

本书只讨论后者。两者没有代码或架构上的继承关系。你在搜索资料时如果看到 3D Slicer、Docker model store、prostate segmentation，那不是本书的对象。

## 0.3 六条阅读路径

**路径 A：从零建立系统直觉。** 依次读第 1、2、3、4 章，然后读第 12、13、14、15、16 章，最后进入第四部分。这条路径不要求你读过 DeepInfer 源码，但要求你会基本的 Transformer 前向传播。读第四部分时，每写一个模块就回到对应机制章节对照一次，效果比一口气读完更好。

**路径 B：带着源码问题来。** 先读第 2、3 章建立地图，再按兴趣跳读第 5 到 11 章，之后读第 12 到 19 章。每章末尾会指出对应的源码目录和关键类。读到调度器时，建议同时打开 `csrc/engine/scheduler.hpp`；读到模型时，打开 `deepinfer/model_executor/models/v4_modules/`；读到 kernel 时，对照第 18 章的融合与对齐讨论。

**路径 C：只关心部署、成本与选型。** 读第 2、4、19、28、29、30、31、32 章，再读第 33 到 37 章的工程化、模型接入、云原生、产品化和合规，然后读第 47、48、49 章的现金流、市场测算和估值，遇到术语查附录 A。第 32 章的 TCO 模型可以直接改成你所在团队的表格。第 29 章的评测方法可以帮助你判断“供应商 benchmark 到底能不能信”。第 36 章会把技术指标翻译成价格、毛利和商业模式；第 48 章回答“市场有多大、先打谁”，第 49 章回答“这笔生意值多少钱”。

**路径 D：第一次接触 Transformer。** 先读附录 F，建立 token、attention、KV、采样的最小直觉；再读第 1、4 章；然后按路径 A 继续。不要一开始就啃第 5 章的 CED/CSA2/Engram，那些结构是建立在基础 Transformer 之上的优化。

**路径 E：平台与多模型。** 先读第 2、3、12、13、14 章建立引擎与 KV 的直觉，再读第 30 到 32 章的成本与部署，然后读第 33 到 35 章的工程化与云原生，最后读第 41 到 43 章的多模型/适配器、检索推理和编译优化。这条路径适合正在把单模型引擎扩展成平台的团队。

**路径 F：训练侧、端侧与商业决策。** 先读第 4、8、10、11 章建立性能和采样的坐标系，再读第 44 章的 rollout、第 45 章的端侧、第 46 章的流量工程和第 47 章的财务模型，最后读第 48 章的市场测算和第 49 章的估值融资。这条路径适合做后训练基础设施、端侧产品、平台容量规划、创业或投资决策的读者。读第 44 章前最好知道 logprob 和 KV 的基本概念；读第 47 章前最好先看第 30 章的单位成本；读第 49 章前最好先读第 48 章的 TAM/SAM/SOM。

初学者不必一开始就理解 CSA2、EPLB、DSpark 的所有细节。先抓住“prefill 算什么、decode 卡在哪、KV 为什么贵、批处理为什么能摊薄成本”这四件事，后面的机制都是在这四件事上做文章。

## 0.4 代码约定

书中的代码片段默认使用 Python 3.10+，只依赖标准库和 NumPy。所有命令都在 `deepinfer-tutorial/` 根目录执行。

mini-deepinfer 的模块命名刻意贴近 DeepInfer：`EngineConfig` 对应 `EngineArgs`，`Scheduler` 对应 C++ 调度器，`PagedKVCache` 对应 `CacheEngine`，`SamplingParams` 对应同名类。这样你在两边切换时不需要重新建立心理映射。

书中的“真实实现”指 DeepSeek 开源的 DeepInfer 代码；“迷你实现”指本仓库的 `mini_deepinfer/`。两者不是同一份代码，也不共享权重、kernel 或分布式运行时。书中每次说“实现”时会尽量写清楚是哪一边。

需要特别注意路径：`deepinfer/`、`csrc/`、`vendor/`、`deep_cluster/` 指外部 DeepInfer 仓库里的目录，必须先 clone 官方仓库才能打开；本教程仓库只包含 `mini_deepinfer/`、`examples/`、`tests/` 和文档。读到“打开 `csrc/engine/scheduler.hpp`”时，请确认你在 DeepInfer 仓库，而不是在 `deepinfer-tutorial/` 里找这个文件。

为了让代码可以逐段阅读，mini 的实现遵循四条约定：模块顶部写清楚它对应生产系统的哪一部分；性能敏感的循环优先保证正确性和可观察性；错误使用明确异常，不静默降级；任何简化都在 docstring 或本章正文里标出，不把“不支持”伪装成“支持”。

## 0.5 mini-deepinfer 的边界

mini-deepinfer 的目标不是“在小机器上复现 DeepSeek 的服务”。它做不到，也不应该假装做到。它的目标是把 DeepInfer 中**可以在 CPU 上验证的机制**做成真实代码：

- 分页 KV cache、前缀哈希、copy-on-write、LRU 淘汰；
- 连续批处理、chunked prefill、LCFS、抢占与重算；
- 推测解码的提议、验证、接受/拒绝和变长验证；
- 正则、JSON Schema、EBNF 到 NFA 的编译与 token mask；
- 冗余专家、EPLB 放置、EP 全对全的逻辑模拟；
- CP 的 K/V all-gather、PD 的 KV 交接、KV block store 的 TTL/LRU；
- 异步调度的成本模型、形状特化缓存、HTTP/SSE 服务；
- roofline 计算、KV 字节估算、推测加速比和单位成本模型；
- 模型 manifest、网关配额与路由、请求 tracing、TCO 与容量规划模型；
- RL rollout 的组规划、GRPO 优势、权重版本和部分 rollout 状态；
- 端侧内存/roofline/能耗/热模型与云边路由；
- 排队、准入、路由、重试预算、熔断、容量缓冲和多区域故障转移；
- NPV、IRR、LTV/CAC、承诺合同、情景分析、DCF、倍数估值，以及 TAM/SAM/SOM、漏斗和销售产能。

它**没有**实现：FlashMLA/DeepGEMM/TileLang 等真实 kernel，SM100/Ascend 上的算子，真正的多进程 NCCL/HCCL 通信，CUDA Graph 捕获，1M 上下文，552B backbone（含 Engram 约 748B，不同口径含 DSpark/ViT 会更高）模型，3FS，生产级容错。第 20 章会用一张“保真度矩阵”逐项说明差距。读到“DeepInfer 能做到”时，不要把主语换成 mini-deepinfer。

## 0.6 验证口径

这本书里的数字分两类。

第一类是**确定性数字**：测试数量、示例数量、章节数量、配置上限、缓存块数、token 数、KV 字节数。这些必须和代码或脚本一致，`check_docs.py` 会检查其中一部分。第二类是**时间数字**：吞吐、TTFT、TPOT、加速比。它们依赖 CPU 型号、当前负载、Python 版本和 NumPy 的 BLAS 实现。书里给出的值只用于说明量级和趋势，不是 benchmark 承诺。真正的性能结论要在目标硬件上用固定负载重测。

验证命令只有三条：

```bash
python -m pytest -q
python examples/offline_inference.py
python check_docs.py
```

第一条验证机制正确性，第二条验证端到端可运行，第三条验证文档没有指错文件、没有过期计数、没有空壳章节。当前版本对应 268 个测试、28 个示例、52 章正文和 10 个附录。三条都通过，只能说明这个教学仓库内部一致；它不能证明生产 DeepInfer 在你机器上的性能。

如果你想更严格地验证，可以再加两条：把 28 个示例全部跑一遍并检查退出码；把 `python examples/roofline.py` 的输出与你手算的结果对一遍。前者验证端到端路径，后者验证你对公式的理解。

## 0.7 本书不做什么

本书不会教你训练一个 552B 模型，也不会逐行解释 TileLang kernel 的汇编级优化。它不会给出“某框架一定比某框架快”的结论，因为推理性能高度依赖模型、硬件、batch 分布和 SLO。它也不会把商业分析写成市场宣传：第 30 到 37 章会给出可代入的公式、敏感性分析和合规清单，而不是一个拍脑袋的市场规模。

本书对公开规格保持谨慎。V4.1-Flash 的部分参数来自技术报告、模型页和社区解读，不同来源可能有差异；凡是涉及这些数字，正文会写“公开资料显示”。涉及 DeepInfer 代码行为时，以仓库代码为准。两者不要混为一谈。

## 0.8 章节之间怎么连

第一部分（第 0 到 4 章）建立坐标系：prefill/decode、roofline、KV、批处理和指标。第二部分（第 5 到 11 章）把坐标系放回 V4.1 的结构：CED、CSA2、SWA、Engram、MoE、DSpark、结构化输出、低精度和采样。第三部分（第 12 到 19 章）进入引擎：分层、调度、KV 系统、并行、长上下文与 Agent 负载、异步执行、GPU kernel 和可靠性。第四部分（第 20 到 27 章）把这些机制实现成一个可运行的 mini 引擎。第五部分（第 28 到 29 章）讨论安全与评测。第六部分（第 30 到 32 章）讨论经济性、竞争和 TCO，第七部分（第 33 到 37 章）讨论工程化、模型接入、云原生部署、产品化和合规治理。第八部分（第 38 到 43 章）先处理三类专项负载：多模态、长思维链和离线批处理，再讨论多模型/多适配器、检索推理和推理编译器这三项平台能力。第九部分（第 44 到 46 章）把镜头转向训练侧推理、端侧与异构设备、流量工程和多区域运营。第十部分（第 47 到 51 章）先补上现金流、定价和投资回报，再讨论市场测算、进入策略、估值、融资和资本回报；第 50 章讨论未来，第 51 章收束全书。附录 F 为初学者补上 Transformer 推理的基础；附录 G 用一条可运行的 request trace 把 tokenizer、调度、分页 KV、采样和状态回收串成一条基准线，读任何机制时都可以回到它，问“这个机制会改变 trace 里的哪个字段”。

第 4 章和第 18 章是两条“回到物理”的路线：前者用手算公式判断瓶颈，后者用 GPU 执行模型解释 kernel 为什么这样写。第 13、14、22 章是一条“调度与内存”的路线：先看生产策略，再看 mini 的逐行实现。第 26 章是把所有机制串起来的验证章，建议在读完第四部分后精读。第 33 到 37 章是一条“从代码到服务”的路线：先补齐工程化，再接入模型和版本，然后部署到 Kubernetes，最后讨论产品化和合规。第 34 章的 manifest、第 33 章的 tracing、第 35 章的 deploy 清单可以互相参照。第 44 到 47 章是四条“换一个约束重新推导”的路线：第 44 章把请求换成训练样本，第 45 章把数据中心换成端侧设备，第 46 章把单机换成集群和区域，第 47 章把技术指标换成现金流。它们都可以独立阅读，但最好在读完第 4、12、14、30 章之后读。

## 小结

这本书的主线是“机制 -> 代码 -> 数字 -> 商业含义”。DeepInfer 的生产实现是一个复杂的分布式系统；mini-deepinfer 是一个规模缩小、但机制可验证的对照实现。两者之间的差距本身就是教程的一部分：它告诉你哪些东西可以靠读代码学会，哪些必须靠硬件、集群和长期运维积累。
