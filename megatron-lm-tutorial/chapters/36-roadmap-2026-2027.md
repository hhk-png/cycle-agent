# 第 36 章 路线图 2026–2027：技术判断与采用决策

第 34 章讲“技术是什么”，本章讲“什么时候该跟、跟到什么程度、什么信号出现时
应该停”。路线图不是承诺，而是一组**可证伪的信号**。

> 时间基线：2026 年 11 月。文中“Q3/Q4”指公开 roadmap/issue 的季度标签，
> 不是发布日期承诺。看到“已合并”“已发布”“计划中”要分开对待。

## 36.1 信号分级：别把 roadmap 当 release note

| 级别 | 证据 | 可信度 | 采用建议 |
|---|---|---|---|
| L1 已发布 | release tag + 文档 + 可运行示例 | 高 | 可以进生产评估 |
| L2 已合并 | `dev`/main 有代码 + 测试 | 中高 | 可做小规模验证 |
| L3 路线图 | roadmap issue/设计文档 | 中 | 只做架构预留 |
| L4 传闻/二手解读 | 博客/推文/转述 | 低 | 不作为决策依据 |

一个常见错误是把 L3 当成 L1：在架构评审里说“下个版本就支持”，结果把关键
路径押在一个没有日期的 issue 上。正确做法是：**为 L3 留接口，不为 L3 改
主线**。

## 36.2 2026 Q4–2027 的决策表

下表把公开信号转成“如果发生，我们做什么”。日期是窗口，不是承诺；置信度是
作者判断。

| 窗口 | 信号 | 置信度 | 影响 | 现在做什么 | 放弃/回滚条件 |
|---|---|---|---|---|---|
| 2026 Q4 | HybridModel 的 EP overlap / FSDP 集成进入可用版本 | 中 | MoE+SSM 混合模型的并行调度 | 把模型层抽象成可插拔 block；预留 EP/FSDP 组 | 连续两个版本仍只在 dev、无收敛报告 |
| 2026 Q4 | Megatron FSDP v2 支持 TP/EP + PP/VPP 1F1B overlap | 中 | 小模型/中等模型可能不再需要手工 3D 并行 | 用 FSDP 跑一个 1B–7B 基线，对比吞吐/显存 | 吞吐低于现有方案 20% 且无明确路线 |
| 2026 Q4 | Blackwell 2D MXFP8 / NVFP4 训练 recipe 稳定 | 中高 | FP8/FP4 成为默认精度选项 | 在 FP8 基线上加 FP4 影子实验；记录 amax/收敛 | 500 步内 loss 偏离 FP8 基线 > 阈值 |
| 2027 H1 | 64K→1M 长上下文课程与 CP indexer 成熟 | 中 | 长上下文从 demo 到可训练 | 先做 64K/128K 数据课程；CP 压测 | 1M 下吞吐下降超过 3× 且无稀疏方案 |
| 2027 H1 | 训练/推理一体化（chunked prefill、PD 分离）进入 Core | 中高 | 训练框架直接产出可部署权重 | 统一 tokenizer/权重格式；评估 Core inference | 推理性能落后专用引擎 30%+ |
| 2027 H1 | distributed Muon 在 100B+ 有公开收敛证据 | 低中 | 优化器多元化 | 小规模 Muon/混合优化器 A/B | 只有小模型结果、无超参迁移报告 |
| 2027 H2 | 多模态统一模型（vision/video/audio）进入主流训练配方 | 中 | 数据/并行/缓存全面复杂化 | 先做 vision+text；单独 encoder 并行组 | 视觉 token 成本超过文本 10× 且无压缩方案 |

表的使用方式：

- 置信度低不等于不做，而是**只做可逆投入**（接口、影子实验、 benchmark）；
- 每一行都要有“放弃条件”，否则路线图会变成信仰；
- 窗口过后回看：信号是按时出现、延后，还是消失了？把结论写进下一版。

## 36.3 五条主线的技术判断

### 1. 并行维度融合：从“手工选”到“全局规划”

TP/PP/DP/CP/EP 的组合越来越多，手工试配置的成本上升。HybridModel/FSDP v2
的方向是让调度器同时考虑计算、通信、显存，而不是“先选 TP 再选 PP”。

判断：**方向确定，但 2027 年前仍是“半自动”**。自动规划需要准确的性能模型，
而性能模型对网络/负载/数据分布很敏感。团队应先把自己的配置搜索流程脚本化
（第 14 章），再逐步引入自动规划。

### 2. 低精度成为默认：关键不是“支持”，而是“自动选择”

FP8 在 2026 已是主流训练精度之一；FP4 在 Blackwell 上从推理走向训练。真正
的难点是：

- 哪些层/算子可以用 FP4，哪些必须保留 FP32/FP8；
- per-block/per-expert scale 如何校准；
- 低精度与 MoE 路由、长上下文、Muon 的交互；
- 出问题时如何快速回退到 FP8。

判断：**FP8 默认化可信，FP4 训练在 2027 年前仍是“选择性使用”**。不要用
厂商的 FP4 TFLOPs 直接推算训练成本；要先看收敛证据和回退路径。

### 3. 长上下文工程化：模型、数据、系统、评测四件事

1M 上下文不是“把 RoPE base 调大”。它需要：

- 稀疏/混合注意力（滑动窗口、全局 token、indexer）；
- CP/ring attention 与通信 overlap；
- 长上下文数据课程与评测（needle、长文推理、代码库）；
- 激活/KV 显存优化。

判断：**2027 年 1M 会“可用”，但不会“免费”**。大多数团队应先做 64K–128K，
把数据课程和评测做扎实，再考虑 1M。

### 4. 训练/推理一体化：框架边界在消失

chunked prefill、prefix cache、speculative decoding、PD 分离正在进入训练
框架。对平台团队的含义：

- tokenizer/权重格式/并行布局要统一；
- 训练产出的 checkpoint 要能直接被推理引擎加载；
- 评测要同时覆盖训练 loss 和在线指标（TTFT/TPOT/goodput）。

判断：**一体化是长期方向，但专用推理引擎（vLLM/TensorRT-LLM）在 2027 年前
仍有性能优势**。现实架构是“训练用 Megatron，推理用专用引擎，Bridge 做转换”。

### 5. 优化器多元化：Muon 是变量，不是答案

Muon 的 Newton–Schulz 正交化在小规模上显示了潜力，但大规模仍需回答：

- 与 MoE/MLA/长上下文的交互；
- 分布式正交化的通信成本；
- 超参（LR/momentum/NS steps）如何随规模迁移；
- 与 FP8/FP4 的数值兼容。

判断：**2027 年前 AdamW 仍是默认，Muon 是“值得做 A/B 的第二优化器”**。
不要在主线训练上一次性替换优化器；用影子实验和 checkpoint 回滚控制风险。

## 36.4 三类团队的采用路线

### 研究团队

- 跟 `dev` 分支和 roadmap issue，但只在**可复现的小规模**上验证新功能；
- 每引入一个 L2/L3 功能，写一个最小复现脚本和失败回滚方案；
- 保留配置/checkpoint/数据快照，否则新功能无法归因。

### 平台团队

- 把并行配置、checkpoint、监控、故障恢复做成平台能力；
- 为 L3 功能预留接口（模型 block、并行组、精度策略），但不在主线押注；
- 训练/推理共用 tokenizer/权重转换/评测；
- 关注供应链：CUDA/NCCL/TE/PyTorch 版本组合的兼容矩阵。

### 企业决策者

- 用 TCO 而不是 GPU 单价评估（第 44 章）；
- 区分“训练框架”和“推理服务”的采购；
- 自建/云/托管取决于团队能力、合规、弹性（第 45 章）；
- 开源不等于零成本：运维、人才、数据是长期投入。

## 36.5 需要警惕的炒作与验证方法

| 说法 | 问题 | 怎么验证 |
|---|---|---|
| “一个开关支持 1M 上下文” | 忽略数据/稀疏/系统 | 要 1M 下的吞吐、显存、评测三组数 |
| “FP4 训练全面超越 BF16” | 忽略精度/收敛/硬件 | 要 loss 曲线、回退路径、可复现 recipe |
| “MoE 一定比稠密好” | 忽略通信/负载/推理成本 | 同 FLOPs/同显存/同延迟下比较 |
| “MFU 达到 X%” | 忽略模型/序列/精度/是否含通信 | 问清 dense/稀疏、是否含 attention、端到端还是 kernel |
| “开源免费” | 忽略支持/合规/运维 | 算 3 年 TCO，含人力和故障成本 |
| “某框架将取代 Megatron” | 忽略生态/硬件/规模验证 | 看 100B+ 的真实训练报告，不看 demo |

一个实用原则：**任何路线图数字，先问口径（模型/序列/精度/并行/是否含通信/
是否端到端），再问可复现性（代码/配置/数据/checkpoint），最后才问性能。**

## 36.6 本章小结

- 路线图要分级：已发布、已合并、计划中、传闻，采用策略不同。
- 2026 Q4–2027 的主线是 HybridModel、低精度、长上下文、FSDP v2、训练推理
  一体化、优化器多元化。
- 每条主线都要有“现在做什么”和“放弃条件”，否则不是路线图。
- 并行调度会从手工选择走向半自动规划，但性能模型仍是瓶颈。
- 对厂商数字保持口径意识；对 L3 功能只做可逆投入。
